= Позиции диагностик

`diagnostic-positions-v1` — отдельный профиль приёмки, закреплённый за
Asciidoctor 2.0.23. Манифест:
link:../compatibility/acceptance/positions.json[positions.json].
26 собственных проб дают *26 PASS*, XFAIL нет. Прежний XFAIL
`position-comment-direct-peek` исправлен вместе с общим случаем
(`position-block-peek-dropped-directive`): цикл разделов Ruby перед каждым
блоком подглядывает две предобработанные строки (`is_next_line_section?`), и
строка, отброшенная между ними, сдвигает `mark` блока. Всё, что Ruby сообщает
по этой метке (незакрытый блок, повторный id блока), называет строку ниже
первой строки блока, пока обе строки не прочитаны; adoctra запоминает такие
блоки (`Reader::peeked_blocks`) и берёт для них `section_cursor`. Стили
`comment` (сырое подглядывание) и `discrete`/`float`, а также блоки пунктов
списка не сдвигаются. Прежний XFAIL
`position-title-peek-dropped-directive` исправлен: директива, отброшенная при
подглядывании двух строк заголовка раздела, сдвигает `reader.cursor` Ruby, и
все три проверки уровня (`section title out of sequence`, `level 0 sections …`,
`… do not support nested sections`) называют строку после заголовка; adoctra
берёт для них один курсор после подглядывания (проба
`position-nested-section-peek-dropped-directive` — для `[glossary]`). Это ограниченная выборка
диагностик, не весь upstream suite и не проверка ASG/TCK.

== Контракт

Оба процессора выполняют разбор и HTML-конвертацию с одинаковыми атрибутами
и safe mode; так в журнал попадают и отложенные предупреждения конвертации.
HTML в этом профиле не сравнивается. Результат — упорядоченный список
`diagnostics`, где каждое сообщение содержит:

* `severity`: warning, error, fatal или unknown; сообщения ниже WARN исключены;
* `message`: полный текст без изменения содержания;
* `location`: `{file, line}` или явный `null`, если координат нет.

Строки нумеруются с 1; строка 0 — настоящий вывод Ruby для
`reader.cursor_at_prev_line` на первой строке (предупреждения стиля `[#]`,
`[#a#b]`). Порядок и повторные сообщения значимы. Ruby launcher
`--diagnostic-positions` читает `source_location` из `MemoryLogger`.
Он не восстанавливает координаты из текста сообщения. Адаптер adoctra читает
файл/строку из stderr CLI; предупреждения backend без позиции получают `null`.
Наличие позиции у adoctra при `null` у Ruby считается отличием, даже если
это дополнительная полезная редактору информация.

Единственные преобразования имён: `-` adoctra и `<stdin>` Ruby обозначают
один stdin; абсолютный временный корень fixture заменяется на `<fixture>`,
с сохранением всего относительного пути. В сообщениях заменяется только этот
временный корень. Другой источник, выход за корень и неизвестный формат stderr
вызывают ошибку стенда. Переименование файла, сдвиг строки, исчезновение позиции,
смена текста/уровня или порядка сообщений приводят к FAIL.

Ruby не предоставляет в этих logger cursors колонок и byte spans. Они
не выдумываются и не включаются в сравнительный профиль. Вторичный
`include_location`, стек включений и составной provenance также вне схемы;
`source_location` остаётся первичной позицией, даже когда Ruby указывает на
директиву include, а физический span adoctra — на сам ресурс.

== Выборка и исправления

Четыре пробы добавлены 2026-11-03 после того, как upstream-аудит стал
сравнивать курсоры (см. link:upstream-tests.adoc[]):
`position-converter-unlocated` (исключённые `abstract` и `partintro`, неверная
ссылка на сноску и устаревший `footnoteref` — Ruby пишет их без курсора, а
исключённые блоки — только при конвертации), `position-invalid-part-cursor`
(часть без раздела — `reader.cursor` после чтения части: строка заголовка
закрывающей части после её метаданных и комментариев или конец ввода),
`position-style-attribute-previous-line` (`cursor_at_prev_line`, в том числе
строка 0) и `position-invalid-substitutions` (`resolve_subs` без курсора).
Все четыре на прежнем CLI давали FAIL.

PASS проверяют пропуск уровня раздела, повторный id, неполную строку таблицы,
отсутствие диагностик у корректного документа, Unicode/CRLF, порядок нескольких
предупреждений, вложенный include, выбор непоследовательных строк, выбор тега
и вложенный тег с CRLF и снятием отступа. Исходники имеют SHA-256 и происхождение;
семь прежних проб переиспользуются без изменений. Все примеры написаны в adoctra,
а не перенесены из upstream-тестов.

Все восемь прежних расхождений устранены в стандартном выводе CLI;
эталоны Ruby не изменялись, XFAIL-baseline удалены:

* Пропущенный атрибут выводится без cursor, как в Ruby.
* Незакрытый listing выводится как warning с текстом `unterminated listing block`.
* Неразрешённая xref и незакрытое условие остаются редакторскими диагностиками
  в модели, но не появляются в стандартном журнале конвертации.
* Проверка заголовка учитывает lookahead Ruby через EOF include и восстановление
  cursor ближайшего родительского файла, включая возврат в основной документ.
* После отбора строк/тегов cursor начинается с первой выбранной строки и
  далее считает выбранные строки подряд, как Ruby. `leveloffset` компенсирует
  две добавленные служебные строки.
* Незакрытый тег выводится с позицией директивы include и полным текстом,
  содержащим строку тега и путь ресурса.
* Непарный endif использует текст Ruby с исходной директивой.
* Ошибки уровня 0 и вложенности специальных разделов используют курсор после
  подглядывания заголовка, как предупреждение о порядке уровней
  (`position-title-peek-dropped-directive`).
* Метка блока после подглядывания цикла разделов учитывает отброшенные строки
  (`position-comment-direct-peek`, `position-block-peek-dropped-directive`).

`Diagnostic.span`, `severity` и `message` сохраняют физическую редакторскую
диагностику. Новое поле `report: DiagnosticReport` задаёт представление для
конвертации: явное отсутствие позиции, cursor, переопределение текста/уровня
или отсутствие сообщения в обычном журнале. Это метаданные от места обнаружения
ошибки; CLI не распознаёт тип ошибки по английскому тексту сообщения.

CLI по умолчанию использует `--diagnostics compat`: `файл:строка: уровень: текст`
или `уровень: текст` без вымышленных колонок. `--diagnostics editor` возвращает
физические `файл:строка:колонка`, byte spans и дополнительные редакторские
сообщения. WASM продолжает сериализовать исходную редакторскую диагностику.
Сравнительный стенд запускает обычный CLI без специального режима для fixtures
и не фильтрует отдельные типы warning/error.

Отдельные native-тесты `diagnostic_positions_*` в
link:../crates/adoctra-core/tests/includes.rs[includes.rs] проверяют физические
source_id/имена, начало и конец byte spans, исходный срез и колонку в Unicode
scalar values после вложенного include, отбора строк/тегов и удаления отступов.
В них есть CRLF, кириллица и emoji. Заголовок на EOF отдельно сохраняет
физический вложенный источник. Эти проверки — контракт adoctra, не сравнение
колонок с Ruby.

== Запуск

[source,sh]
----
cargo build -p adoctra-cli
python3 scripts/acceptance.py --manifest compatibility/acceptance/positions.json
python3 scripts/acceptance.py --manifest compatibility/acceptance/positions.json --verify-reference
python3 scripts/acceptance.py --manifest compatibility/acceptance/positions.json --json-report target/positions-report.json
python3 -m unittest discover -s scripts -p 'test_*.py'
ruby scripts/test_asciidoctor_positions.rb
----

Offline-режим использует сохранённые JSON-эталоны без Ruby и сети.
`--verify-reference` требует установленного закреплённого gem и отвергает дрейф.
Для осознанного обновления доступны `--case ID --update-reference` и отдельный
`--case ID --record-known-differences`; ожидания автоматически не меняются.
Оба режима, Python-проверки стенда и шесть независимых проверок Ruby launcher
включены в CI. Прежний HTML/диагностический профиль сохраняет собственные
эталоны и теперь даёт 28 PASS, без XFAIL.
