= Позиции диагностик

`diagnostic-positions-v1` — отдельный профиль приёмки, закреплённый за
Asciidoctor 2.0.23. Манифест:
link:../compatibility/acceptance/positions.json[positions.json].
18 собственных проб дают *10 PASS / 8 XFAIL*. Это ограниченная выборка
диагностик, не весь upstream suite и не проверка ASG/TCK.

== Контракт

Оба процессора выполняют разбор и HTML-конвертацию с одинаковыми атрибутами
и safe mode; так в журнал попадают и отложенные предупреждения конвертации.
HTML в этом профиле не сравнивается. Результат — упорядоченный список
`diagnostics`, где каждое сообщение содержит:

* `severity`: warning, error, fatal или unknown; сообщения ниже WARN исключены;
* `message`: полный текст без изменения содержания;
* `location`: `{file, line}` или явный `null`, если координат нет.

Строки нумеруются с 1. Порядок и повторные сообщения значимы. Ruby launcher
`--diagnostic-positions` читает `source_location` из `MemoryLogger`.
Он не восстанавливает координаты из текста сообщения. Адаптер adoctra читает
файл/строку из stderr CLI; предупреждения backend без позиции получают `null`.
Наличие позиции у adoctra при `null` у Ruby считается отличием, даже если
это дополнительная полезная редактору информация.

Единственные преобразования имён: `-` adoctra и `<stdin>` Ruby обозначают
один stdin; абсолютный временный корень fixture заменяется на `<fixture>`,
с сохранением всего относительного пути. В сообщениях заменяется только этот
временный корень. Другой источник, выход за корень и неизвестный формат stderr
вызывают ошибку стенда. Переименование файла, сдвиг строки, исчезновение позиции,
смена текста/уровня или порядка сообщений приводят к FAIL.

Ruby не предоставляет в этих logger cursors колонок и byte spans. Они
не выдумываются и не включаются в сравнительный профиль. Вторичный
`include_location`, стек включений и составной provenance также вне схемы;
`source_location` остаётся первичной позицией, даже когда Ruby указывает на
директиву include, а adoctra — на сам ресурс.

== Выборка и отличия

PASS проверяют пропуск уровня раздела, повторный id, неполную строку таблицы,
отсутствие диагностик у корректного документа, Unicode/CRLF, порядок нескольких
предупреждений, вложенный include, выбор непоследовательных строк, выбор тега
и вложенный тег с CRLF и снятием отступа. Исходники имеют SHA-256 и происхождение;
семь прежних проб переиспользуются без изменений. Все примеры написаны в adoctra,
а не перенесены из upstream-тестов.

Восемь XFAIL закрепляют весь результат этого профиля:

* Пропущенный атрибут: Ruby не передаёт cursor, adoctra указывает на ссылку.
* Незакрытый listing: различаются уровень и текст диагностики.
* Неразрешённая xref и незакрытое условие: adoctra выдаёт редакторские сообщения,
  отсутствующие у Ruby на обычном уровне журнала.
* Заголовок в конце вложенного include: Ruby уже вернулся к cursor основного
  файла; adoctra сохраняет физический вложенный источник.
* Диагностика после разрыва выбранных строк include: Ruby считает только
  выбранные строки (строка 5), adoctra сохраняет физическую строку 7.
* Незакрытый тег: Ruby указывает директиву include и включает путь/строку тега
  в текст; adoctra указывает открывающий тег и выдаёт более короткий текст.
* Непарный endif: строка совпадает, текст adoctra короче.

Эти XFAIL не являются свидетельством совместимости. Baseline хранит полный
список сообщений и координат; его дрейф и XPASS завершают проверку с ошибкой.
Ошибка процесса, таймаут, повреждённая схема или неизвестный stderr не могут
стать XFAIL. Изменения parser/CLI ради имитации менее точного cursor Ruby
не потребовались.

Отдельные native-тесты `diagnostic_positions_*` в
link:../crates/adoctra-core/tests/includes.rs[includes.rs] проверяют физические
source_id/имена, начало и конец byte spans, исходный срез и колонку в Unicode
scalar values после вложенного include, отбора строк/тегов и удаления отступов.
В них есть CRLF, кириллица и emoji. Заголовок на EOF отдельно сохраняет
физический вложенный источник. Эти проверки — контракт adoctra, не сравнение
колонок с Ruby.

== Запуск

[source,sh]
----
cargo build -p adoctra-cli
python3 scripts/acceptance.py --manifest compatibility/acceptance/positions.json
python3 scripts/acceptance.py --manifest compatibility/acceptance/positions.json --verify-reference
python3 scripts/acceptance.py --manifest compatibility/acceptance/positions.json --json-report target/positions-report.json
python3 -m unittest discover -s scripts -p 'test_*.py'
ruby scripts/test_asciidoctor_positions.rb
----

Offline-режим использует сохранённые JSON-эталоны без Ruby и сети.
`--verify-reference` требует установленного закреплённого gem и отвергает дрейф.
Для осознанного обновления доступны `--case ID --update-reference` и отдельный
`--case ID --record-known-differences`; ожидания автоматически не меняются.
Оба режима, Python-проверки стенда и шесть независимых проверок Ruby launcher
включены в CI. Прежний HTML/диагностический профиль сохраняет собственные
эталоны и результаты 25 PASS / 3 XFAIL.
