= Фаззинг `fuzz-v1`

Стенд `scripts/fuzz.py` ищет ошибочный ввод, на котором adoctra падает,
нарушает инварианты редактора или расходится с закреплённым
Asciidoctor 2.0.23. Входы детерминированы seed-ом. Находки стенд только
сообщает и не замораживает: каждая подтверждённая находка становится
регрессионным тестом ядра и случаем обычного корпуса (PASS после
исправления или XFAIL с причиной и полным фактическим результатом).

== Входы

* *Мутации.* Источники — минимальные случаи `compatibility/cases.json` и все
  golden-фикстуры. К каждому применяется от одной до пяти операций: удаление,
  повтор и перестановка строк, вставка строки-конструкции (разделители,
  маркеры списков, атрибуты, директивы препроцессора, заголовки, макросы),
  вставка inline-маркера внутрь строки, вклейка строк другого источника,
  отступ, пустая строка, обрезка документа по символу.
* *Глубокая вложенность.* Семейства `example`, `sidebar`, `quote`, `list`,
  `olist`, `dlist`, `table`, `inline`, `section`, `open-in-list`,
  `include-cond` с заданными глубинами (`--depths`).

== Этапы

`robust`:: Пример `adoctra-wasm` `fuzz` выполняет путь редактора
(`parse_json`, `tokens_json`) для всех входов в одном процессе. Каждый вход
идёт в рабочем потоке со стеком 1 МиБ (порядка стека wasm32), поэтому
переполнение стека видно так же, как в редакторе. Находки: паника (с местом),
аварийное завершение процесса (переполнение стека; виноватый вход
определяется по недостающему ответу), превышение времени, медленный вход
(дольше 0.5 с и 1 мс на байт) и нарушение инвариантов span: span главного
источника (блоки, inline, заголовок, сноски, диагностики, токены,
комментарии) выходит за источник или не лежит на границе символа.
`diff`:: CLI (secure, embedded, `showtitle`) сравнивается с постоянным
процессом Ruby `scripts/asciidoctor-batch.rb` по DOM-профилю тела и
диагностикам приёмочного профиля. Статусы: `PASS`, `DIFF`, `RUBY_ERROR`
(исключение Ruby или невалидный HTML Ruby, который проекция не принимает),
`ADOCTRA_ERROR` (паника CLI, код завершения, невалидный HTML).
С `--minimize` расхождение уменьшается удалением строк, затем символов,
пока сохраняется тот же статус; одинаковые минимальные входы
сворачиваются.

Обе стороны читают вывод процессов байтами: text-режим Python превращал
одиночный `\r` в перевод строки (это исправлено и в `compatibility.py`
и `acceptance.py`).

[source,sh]
----
python3 scripts/fuzz.py --stage robust --seed 1 --count 4000 --depths 8,16
python3 scripts/fuzz.py --stage diff --seed 2 --count 3000 --diff-count 1500 --minimize
python3 -m unittest discover -s scripts -p test_fuzz.py
----

CI выполняет этап `robust` с seed 1–3 (по 1500 мутаций, глубины 8, 64, 128 и 2048);
любая находка останавливает проверку. Этап `diff` требует Ruby и запускается
вручную.

== Результаты (2026-10-31)

`robust`, seed 1–10 по 4000 мутаций: найдены две паники ядра, исправлены:

* срез по байтовому индексу внутри символа в `lists::delimiter` (строка вида
  ``` ``о} ```, четыре символа сравнивались по трём байтам);
* `consume_block_metadata` за концом ввода (`:doctype: manpage` без тела).

После исправлений 40 000 входов проходят без находок.

Глубокая вложенность: рекурсивный разбор переполнял стек 1 МиБ примерно на
96–128 уровнях вложенных блоков или списков в release (debug — на 32); со
стеком 8 МиБ (CLI) — около 1024. Ruby выдерживает 1024 уровня и падает
(`SystemStackError`) около 4096; 4096 вложенных пунктов списка Ruby не
обрабатывает за 120 с. По решению пользователя от 2026-10-31 рекурсия
убирается (явный стек), без ограничения глубины.

Рекурсия по глубине документа убрана по слоям:

* чтение блоков идёт по стеку в куче (`read_blocks`): контейнеры, пункты всех
  списков и Markdown-цитаты стали кадрами этого стека, продолжения после
  вложенного чтения — замыкания с `'static`-состоянием;
* общий обход `visit` — явный стек владеющих кадров: группы вложенных блоков
  (пункт списка, описание, ячейка, тело контейнера) временно вынимаются из
  блока и возвращаются после обхода, порядок прежний; хуки `enter_block` и
  `leave_block` заменили `visit_block`. На нём работают подстановки
  (`body_subs`), проверка `abstract`/`partintro`, регистрация ссылок, сноски,
  токены и отображение span;
* документ разбирает дерево при освобождении итеративно (`Drop` для
  `Document`);
* бэкенды HTML, JSON и WASM пишут вложенные блоки через
  `adoctra_core::segments`: рендерер помечает вложенный блок, а `expand`
  разворачивает метки по явному стеку, поэтому код рендереров почти не
  изменился.

`unsafe` не используется (запрещён в workspace). Со стеком 1 МиБ разбор,
токены, освобождение и сериализация WASM проходят 32 768 уровней вложенных
блоков; тесты ядра и каждого бэкенда разбирают, выводят и освобождают 3000
уровней в потоке со стеком 1 МиБ. Ограничены синтаксисом и остаются
рекурсивными только вложенные документы ячеек AsciiDoc (каждому уровню нужен
свой разделитель) и вложенность inline-разметки (число видов форматирования,
как у проходов подстановок Ruby). Глубокие списки читаются за время, растущее
быстрее квадрата глубины (каждый уровень заново копирует строки вложенных
пунктов, как и у Ruby): это вопрос производительности, отложенной по
приоритетам, поэтому семейства `list`/`olist` фаззинга ограничены 128
уровнями. CI проверяет глубины 8, 64, 128 и 2048.

`diff`, seed 1 (600 входов) и seed 2 (1500 входов). Исправлены:

* заголовки и якоря блоков с отступом распознавались (у Ruby это literal-абзац;
  `AtxSectionTitleRx` и `BlockAnchorRx` привязаны к началу строки);
* пробелы Unicode: Rust `trim` убирал U+00A0, U+3000 и т. п., а Ruby
  `strip`/`rstrip` — только ASCII-пробелы и NUL (строка из неразрывных пробелов
  — абзац, роль сохраняет внутренний U+00A0). Вызовы ядра переведены на
  `ruby_strip`;
* имя контекста в `unterminated … block` после маскировки стилем (`pass`,
  `stem`, `admonition`, `listing` для `[source]` над `--` и т. д.);
* исключённые `[partintro]`/`[abstract]` не конвертируются, поэтому их сноски не
  регистрируются;
* ошибки уровня раздела выдаются при чтении заголовка, а `invalid part` — при
  закрытии части (порядок диагностик);
* неизвестный стиль над строкой с отступом сбрасывается, как в Ruby (literal);
* CRLF в абзацах со стилями `[literal]`/`[source]`/`[listing]` и в `[verse]`:
  текст сохранял `\r` (было скрыто text-режимом стенда);
* порядок диагностик между проходами: ошибки препроцессора, предупреждения
  выбора include, конвертация заголовков разделов при чтении (в том числе в
  ячейках AsciiDoc) и повторные id теперь идут одним потоком по ходу чтения,
  как у Ruby; незакрытый контейнер предупреждает в конце упреждающего чтения
  (см. `**Diagnostic order**` в implementation-notes).

Повторный прогон `diff` seed 1–4 (по 700 входов): расхождений порядка
диагностик между проходами нет. Семь расхождений тела из seed 3 и 4 (были и
раньше) минимизированы и исправлены (случаи `fuzz-*` в основном корпусе):

* строки метаданных блока (`[e]`, `[.r]`, `[[id]]`) между текстом пункта списка
  и сливаемым абзацем: в режиме `text_only` Ruby читает их как метаданные, а
  `fold_first` соединяет текст и абзац через LF — adoctra брала весь диапазон
  как текст (`mut-3-75`, `mut-3-206`, `mut-3-207`). id слитого абзаца Ruby
  регистрирует (ссылка разрешается с его reftext), теперь и adoctra;
* строка ревизии: ` *` в `RevisionInfoLineRx` отдаёт пробелы при откате, так что
  ` :` — строка ревизии с пустой `revremark` (`mut-4-552`); разбор переписан как
  эмуляция регулярного выражения с порядком перебора Ruby;
* сгенерированная подпись `[refid]` создаётся на стадии макросов до
  восстановления passthrough: Ruby восстанавливает их и в ней, adoctra
  оставляла индекс заполнителя (`mut-4-358`);
* ссылка на документ внутри его заголовка: Ruby запоминает заголовок только
  после внешней конвертации, поэтому подпись конвертирует заголовок ещё раз
  (`mut-4-174`);
* ячейка AsciiDoc: Ruby соединяет блоки вложенного документа через LF без
  завершающего LF, текст passthrough заканчивается у `</div>` (`mut-4-521`).

Попутно стал PASS прежний XFAIL `fuzz-dlist-folded-attribute-entry`.
Повторный прогон после исправлений (входы сместились вместе с корпусом) нашёл
ещё три давних расхождения, тоже исправленные:

* заголовок раздела с явным id и ссылкой на атрибут Ruby конвертирует при
  чтении до регистрации id, поэтому ссылка на сам раздел даёт `[sec]`;
* неизвестный стиль над отступным абзацем: Ruby не раскрывает табуляцию
  (`adjust_indentation!` без размера), `tabsize` действует только с `[literal]`;
* `include dropped …`: журнал Ruby называет всю директиву
  (`include::{r}[…]`), редакторское сообщение остаётся коротким.

Закрыты прежние XFAIL:

* строка ` +` в пункте списка: при свёртке абзаца общий отступ снимается и с
  его первой строки (`adjust_indentation!`), так что `+` без пробела — не
  жёсткий перенос;
* разметка в подписи `[refid]` неразрешённой ссылки: подпись строится из
  лексического написания refid (теги, сгенерированные подстановками, остаются
  разметкой; поле `Xref::spelling` для подписей, строящихся позже);
* «многократное вычисление `{counter}` в названии документа» на деле было
  подстановкой строки автора: Ruby применяет header subs к каждому значению
  `process_authors` (`firstname`, `author`, `authors`, копии `_1`, ревизия) по
  очереди; adoctra не подставляла их вовсе. Заодно заголовок, который вывод не
  показывает (embedded с `notitle`), конвертируется лениво — при первой ссылке;
* записи атрибутов над абзацем, слитым в описание, не воспроизводятся при
  конвертации.

Широкий прогон `diff` seed 5–20 (по 700 сравнений; около 30 уникальных
минимизированных находок, все были и раньше) и исправления:

* ячейка таблицы подставляет текст целиком и делит результат по `\n{2,}`
  (`Cell#content`): замены и passthrough через пустую строку, счётчики и
  порядок предупреждений совпадают; сворачивание строк в абзаце сохраняет
  серии переводов строк для этого деления;
* неизвестный стиль абзаца сбрасывается до чтения строк, поэтому абзац
  пункта списка после строки метаданных прерывается на маркере списка;
* под стилем `comment` следующая строка подглядывается без загрузки
  (`Reader::peek_raw`), и список читает её с препроцессором;
* verse со стандартными подстановками отбрасывает пустые крайние строки
  после подстановок (в том числе созданные `{empty}`);
* `mailto` кодирует subject/body из лексического написания (замены как
  `&#8217;`);
* ссылка на начало документа в заголовке раздела, конвертируемом при чтении:
  `[^top]`, пока нет заголовка документа и завершённого раздела верхнего
  уровня, иначе заголовок этого раздела; без `sectids` повторная конвертация
  заголовка изнутри него;
* `#` внутри ссылки на символ (`&#8217;`) в лексическом refid не делит
  путь и фрагмент;
* `pass:m` в записи атрибута тела разрешает ссылку с текущим
  `outfilesuffix`;
* заголовки, конвертируемые при чтении, используют режим compat заголовка
  документа (`Evaluation::with_quote_mode`), как `doc.compat_mode` Ruby;
* раздел NAME manpage из заголовка нумеруется без номера;
* `illegal block content outside of partintro` выдаётся при чтении блока;
* значение в одинарных кавычках, начинающееся с `\'`, не подставляется
  повторно;
* проекция стенда: заголовок `div.hdlist` Ruby и перенос строки перед
  блочным комментарием в пункте списка.

Широкий прогон `diff` seed 21–28 (по 700 сравнений; 5533 PASS, 89
RUBY_ERROR — переполнение стека Ruby на глубине 2048 и невалидный HTML Ruby
для перекрытой inline-разметки, 10 DIFF) и исправления:

* кавычка в атрибутах: `class`/`id` блоков и inline-ролей, поля `link:`
  и xref в значениях, `lang`/`data-lang`, `src`, `title`, `width`/`height`,
  `href` и классы inline-изображения и font-значка экранируются (раньше
  ряд путей использовал текстовое экранирование без `"`, и XFAIL
  `fuzz-unescaped-quote-in-role` замораживал сломанный вывод adoctra);
* спецификация ячейки после ячейки без ведущего разделителя (`e` и строка
  `3*|`): очередь спецификаций Ruby отдаёт `3*` этой ячейке, и span ячейки
  теперь начинается с её текста, поэтому копии сохраняют отложенные поля;
* неудачная форма `[attrs]` у inline-форматирования откатывается, как
  регулярка Ruby: `[#]#` даёт `[<mark>]</mark>`;
* `kbd:[`/`btn:[` внутри метки `kbd`/`btn` не считается вложенным макросом
  (один проход регулярки Ruby), метка закрывается первой `]`;
* проверка partintro/abstract охватывает пункты colist, описания и ячейки
  AsciiDoc (вложенный документ: partintro — ошибка, abstract — нет);
* ведущий якорь ячейки с пустым после подстановки reftext даёт ссылке
  пустую подпись (`Inline#xreftext`), якорь абзаца по-прежнему не
  регистрируется;
* стиль чек-листа остаётся классом после `checklist`;
* цель директивы `ifdef`/`include` отделяется только ASCII-пробелами
  (`\s` Ruby): NBSP — часть цели.

Оставшиеся три DIFF — уже учтённые намеренные отличия (кавычка в `href`
и `class`, роль `&mp;` — именованная сущность HTML5).

Широкий прогон `diff` seed 29–36 (по 700 сравнений; 5500 PASS, 86
RUBY_ERROR — те же границы сравнения, 15 DIFF, 11 уникальных минимальных
входов) и исправления:

* метка `NOTE: ` в начале абзаца действует, только если абзац остаётся
  абзацем (без стиля, `normal` или неизвестный стиль): под `[sidebar]`,
  `[TIP]`, `[literal]` и т.п. это текст;
* стиль admonition над `____` (и `****`) не действует: блок остаётся
  цитатой, как в `DELIMITED_BLOCKS` Ruby;
* строка ` // x` с отступом в пункте списка — текст: Ruby пропускает
  комментарии до снятия отступа;
* тело, первый блок которого отброшен (`[comment]`-абзац, блочный макрос
  с `drop-line`), не начинается с раздела: уровень следующего заголовка
  проверяется (`is_next_line_section?` Ruby);
* при блочном заголовке над заголовком документа атрибут `doctitle` не
  становится заголовком документа;
* строка после ATX-заголовка раздела предобрабатывается до проверки уровня
  (Ruby подглядывает две строки): ошибка директивы идёт раньше;
* заголовок вложенного документа (ячейка `a|`) и скрытый заголовок
  документа (`notitle`) не регистрируют сноски, счётчики и диагностики:
  Ruby их не конвертирует.

Оставшиеся DIFF — учтённые намеренные отличия (кавычка в атрибутах
`href`/`title`, id раздела из HTML заголовка со ссылкой с разметкой). Новая
проба позиций `position-title-peek-dropped-directive` (после отброшенной при
подглядывании директивы Ruby называет строку после заголовка) была XFAIL и
затем исправлена: проверки уровня берут курсор после подглядывания. Повторный прогон seed 30, 31, 33–36 после исправлений: 7 DIFF,
все — те же намеренные отличия.

Широкий прогон `diff` seed 37–44 (по 700 сравнений; 5517 PASS, 74
RUBY_ERROR — переполнение стека Ruby на глубине 2048 и невалидный HTML Ruby
для перекрытой inline-разметки, 9 DIFF, 7 уникальных минимальных входов).
Новых дефектов нет: все DIFF — намеренные отличия (кавычка в `class`, `id`
и `href`, сущность в значении атрибута, id раздела из HTML заголовка со
ссылкой). Сущность в языке листинга (```` ```&mp; ````: Ruby пишет
`class="language-&mp;"` и `data-lang` без экранирования) — новый вариант
отличия роли со ссылкой на сущность, заморожен как XFAIL
`fuzz-language-entity-reference`. Тот же прогон шёл после исправления меток
блоков (`Reader::peeked_blocks`, см. diagnostic-positions.adoc).

Известные расхождения (XFAIL с причинами в корпусах):

* намеренные: роль и язык листинга со ссылкой на сущность, кавычка в `href`/`class`, id
  раздела из HTML заголовка со ссылкой с разметкой (см. compatibility.adoc);
* id из отброшенной ячейки AsciiDoc регистрируются
  (`fuzz-table-dropped-cell-anchor`, исправлено). Порядок диагностик таблицы
  (`fuzz-table-separator-order`, `fuzz-table-dropped-cell-content`) исправлен:
  ячейка AsciiDoc разбирается в момент создания, в том числе отброшенная.
  Заголовок документа под `[comment]` (`fuzz-comment-style-setext-title`)
  исправлен: Ruby исключает для него только `discrete`/`float`. Исправлены
  также id раздела со ссылкой на документ при заголовке документа
  (`fuzz-top-reference-header-title-id`) и значение `mailto` в одинарных
  кавычках с типографской заменой (`fuzz-mailto-single-quoted-replacement`).

`RUBY_ERROR` (Ruby выдаёт невалидный HTML для перекрытой inline-разметки) —
граница сравнения, а не совпадение.
