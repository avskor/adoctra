= Контекст разбора и исходные файлы

`parse(&str)` и `tokens(&str)` остаются доступными и используют источник с id 0.
`parse_with_options` и `tokens_with_options` принимают `ParseOptions` с идентификатором
источника и внешними значениями атрибутов. Все эти функции доступны через `adoctra-core`
и umbrella crate `adoctra`.

== Единый результат для редактора

`ParseResult.tokens: Vec<Token>` содержит подсветку из того же разбора, что
`document` и `diagnostics`. Отдельный вызов `tokens` не нужен, если приложение
уже получило `ParseResult`. Совместимые функции `tokens` / `tokens_with_options`
/ `tokens_resource` возвращают это поле результата своего разбора.
Литералы структуры `ParseResult` должны задавать новое поле `tokens`.

Parser записывает структурные токены при чтении header, метаданных, макросов,
списков, таблиц и verbatim-блоков. Inline-токены собираются при преобразовании
целого поля (абзаца, пункта списка, ячейки, verse), до потери исходного синтаксиса.
Для выбранных `subs` исходный синтаксис поля сканируется без повторения эффектов,
с фильтрацией по включённым стадиям. Повторного структурного разбора, построчной
inline-грамматики и воспроизведения атрибутов в tokenizer нет.
Многострочное форматирование сохраняет диапазоны AST; границы абзацев и ячеек
не склеиваются. Строки literal/source в абзацной форме получают `literal-text` /
`listing-text`, как тела ограждённых блоков.

Токены отображаются из координат reader в исходные файлы один раз; токен через
include разбивается на физические фрагменты без `provenance`. Unicode, CRLF,
выбор строк и изменение отступов используют общую карту источников.
Инкрементальный разбор и pull/event API пока не реализованы.

WASM `parse_json` / `parse_json_with_source` и `ResourceWorkspace.parse_json`
добавляют массив `tokens` рядом с `document` и `diagnostics`. Формат элементов
совпадает с прежним `tokens_json`; старые функции остаются доступными.

== Источники и позиции

`SourceMap` принадлежит вызывающему приложению. Он хранит имена и исходный текст;
регистрация ничего не читает с диска. Идентификаторы устойчивы внутри одной карты.
При разборе зарегистрированного текста приложение передаёт соответствующий id:

[source,rust]
----
use adoctra::{parse_with_options, ParseOptions, SourceMap};

let mut sources = SourceMap::new();
let id = sources.add("chapter.adoc", "See <<missing>>.");
let options = ParseOptions { source_id: id, ..Default::default() };
let result = parse_with_options(sources.get(id).unwrap().text(), &options);
let diagnostic = &result.diagnostics[0];
assert_eq!(sources.slice(diagnostic.span), Some("<<missing>>"));
----

`Span` содержит `source_id`, `start`, `end` и `provenance: Option<usize>`. Границы по-прежнему измеряются
в байтах UTF-8 и образуют полуоткрытый интервал. `Span::new` создаёт диапазон
источника 0; `Span::in_source` задаёт источник явно. При использовании литералов
структуры Rust необходимо задать `provenance: None` для простого диапазона.

`SourceMap::slice` возвращает `None` для неизвестного id, обратного диапазона,
выхода за границы или границы внутри UTF-8-символа. `SourceFile::position` переводит
байтовую позицию в строку и колонку с нумерацией от 1; колонка считается в Unicode
scalar values. Для редакторов с UTF-16-координатами требуется отдельное преобразование.
CLI с `--diagnostics editor` использует карту для сообщений `файл:строка:колонка`.
По умолчанию `--diagnostics compat` выводит файл/строку из `Diagnostic.report`
без вымышленных колонок, в соответствии с logger cursor Ruby.

`Diagnostic` сохраняет физический `span`, редакторские `severity` и `message`.
Поле `report: DiagnosticReport` содержит необязательные переопределения текста
и уровня, признак `suppressed` для сообщений вне обычного журнала конвертации
и `location: DiagnosticLocation`: `Source`, `Unlocated` или `Cursor`.
`DiagnosticCursor` содержит `source_id` и строку с нумерацией от 1. Cursor может
отличаться от физического span после отбора строк include или lookahead через EOF.
В литералах `Diagnostic` без специальных правил нужно задать
`report: Default::default()`. WASM экспортирует прежнюю редакторскую диагностику;
представление конвертации не изменяет подсветку и исходные диапазоны.

Ресурсный разбор читает несколько файлов в одном потоке. Диапазон внутри одного
вхождения файла сохраняет его исходные координаты. Для диапазона через границы
вхождений (даже одного файла, включённого повторно) `provenance` указывает на
`ParseResult.provenance[index]: Vec<Span>`: исходные фрагменты в порядке чтения.
Основные `source_id/start/end` относятся к первому фрагменту и всегда пригодны
для `SourceMap::slice`. Фрагменты сами не имеют provenance; каждый охватывает
исходный промежуток своего вхождения, включая удалённые строки внутри него.
Индекс действует только вместе с результатом, из которого взят узел. Сохраняйте
`ParseResult`, если нужны составные позиции, а не только `Document`.

Карта комментариев и условий композиционно возвращает диапазоны inline-узлов
в эти координаты. Части атрибуции quote/verse начинаются в диапазоне своего поля
списка атрибутов.

== Списки атрибутов блоков

Строка метаданных распознаётся как в закреплённом Ruby: `[` в первой колонке,
затем пустое содержимое или символ Word/`.#%{,"'` и `]` в конце строки. `[]`
поглощается как метаданные, строка с `[[` бывает только якорем, а строка
с начальным пробелом остаётся текстом. Подсветка использует тот же распознаватель.

Поля разбирает общий лексер AttributeList (также для параметров include
и подписей ссылок). Позиционные значения хранятся по индексу поля Ruby:
именованные поля и пропущенное `name=None` тоже занимают индекс. Следующая строка
заменяет значения с теми же индексами; пустое поле без кавычек — явный nil,
а `""` — пустая строка. `Block.attrs.positional` содержит значения после стиля
(и после языка `source`) по этим индексам, с пустыми строками на месте пропусков.
Второе и третье позиционные значения становятся автором и citetitle атрибуции;
`[source, язык]` переопределяет и именованный `language`.

Shorthand `style#id.role%option` разбирается из объединённого первого позиционного
значения после именованных полей строки и отключается пробелом. Id и роли не
проверяются по символам. Пустое имя и повторный id дают Warning с диапазоном
строки. Именованный `role=` заменяет прежние роли, shorthand-роли добавляются.
`options`/`opts` со списком через запятую удаляют пробелы, одиночное значение
сохраняет их.

Подстановки выполняются при чтении, как в Ruby `sub_input`/`sub_result`.
Сначала вся строка проходит a-стадию с set/counter/counter2 и политиками
attribute-missing (drop-line удаляет весь список, строка остаётся метаданными).
Поля ищутся уже в раскрытом тексте, поэтому значение с запятой разделяет поля.
Значения в одинарных кавычках (кроме именованных title/reftext/options) затем
получают normal-подстановки; предупреждение о пропущенном атрибуте может
повториться на этой стадии. Эффекты действуют на дальнейшее чтение и не
воспроизводятся как декларации; начальные метаданные до header входят в его снимок.

Атрибуция без кавычек или в двойных кавычках — это `Inline::Raw` исходного текста
и `Inline::AttributeRef` раскрытых ссылок (ссылка, чьё значение попало в два поля,
есть в обоих). HTML выводит Raw без экранирования, как Asciidoctor; JSON сохраняет
проекцию разрешённого текста, WASM — узлы и диапазоны. Поле в одинарных кавычках,
не изменённое ранней стадией, сохраняет точные позиции; иначе узлы и диагностики
получают диапазон поля. Подсветка берёт ссылки строки из reader и не исполняет
выражения повторно. Остальные поля в одинарных кавычках сохраняют видимый текст
результата, а не HTML, как Ruby.

Именованные `title=` и `reftext=` используют те же ключи, что строка `.Title`
и reftext блочного якоря: побеждает последнее значение. Они не получают
`sub_result` даже в одинарных кавычках. Неизменённое название сохраняет точные
позиции; значение, изменённое ранней стадией, получает диапазон поля для узлов
и диагностик. Reftext из списка сохраняет узлы ссылок и форматируется так же,
как reftext якоря. Название перед заголовком раздела переносится на следующий
блок с содержимым (в том числе через несколько разделов), discrete/float-заголовок
его отбрасывает. `caption=` по-прежнему задаёт префикс подписи примера; метка
admonition из `caption=` ещё не поддержана.

== Ресурсы приложения и CLI

`ResourceProvider::load(ResourceRequest)` — явный интерфейс загрузки UTF-8-текста.
Запрос содержит `target` и необязательный `referrer`: каноническое имя текущего
источника, ранее возвращённое тем же provider. Результат `Resource { name, text }`
содержит каноническую идентичность и исходный текст без нормализации BOM/CRLF.
Разрешение путей и правила доступа принадлежат provider. Подстановка атрибутов,
выбор строк/тегов и рекурсивное раскрытие include выполняет reader.
Сам parser не выполняет I/O и не ищет ресурс через неявный fallback.

`ResourceProvider::prepare_include(request, encoding, line_limit)` вызывается для
include до выбора строк/тегов. Метод получает `encoding` после подстановок и
разбора параметров либо `None`, а также верхнюю границу чтения для конечного
положительного `lines`. Для тегов, открытых диапазонов и блокирующего очередь
неположительного первого номера передаётся `None`. CLI и MemoryResources
вызывают `BinaryResource::prepare_include`. Результат `IncludeInput` содержит
либо `Decoded(IncludeResource)`, либо исходные байты `Deferred` для отложенной
проверки UTF-8/BINARY. Корректные ресурсы и остальные кодировки продолжают
использовать `decode_include`. По умолчанию новый метод делегирует прежнему
`load_include`; пользовательские декодеры сохраняют поведение.

Для отложенного UTF-8/BINARY reader проверяет выбранные строки. Повреждённые
пропущенные строки не попадают в UTF-8-текст снимка и сохраняются отдельно,
без вставки пробелов, новых строк или символов замены. При выборе тегов
повреждённая UTF-8-строка с `::` и `[]` отклоняется даже вне выбранного тега:
Ruby проверяет её регулярным выражением. Маркеры BINARY сканируются побайтно
в исходных пропущенных строках; такие маркеры не становятся текстом документа.
Ошибка выбранного содержимого не регистрирует снимок.

Если весь ресурс корректен, возвращается полный снимок. Если повреждён только
хвост после последней прочитанной LF-строки, возвращается исправный префикс от
начала файла с `complete=false`. При перекодировании все байты до границы проверяются, включая
пропускаемые строки. Символы замены не вставляются, строки не перенумеровываются.
Граница учитывает кодировку LF и выравнивание UTF-16/32; это ограничение
декодирования, а не потокового I/O: provider пока загружает исходные байты целиком.

Реализация `load_include` по умолчанию делегирует
`ResourceProvider::load_with_encoding(request, encoding)` и считает результат
полным. Прежние text-only и пользовательские декодеры сохраняют поведение;
для восстановления префикса host переопределяет новый метод. Сам
`load_with_encoding` продолжает проверять полный ресурс; по умолчанию вызывает `load`: без кодировки
возвращает его результат, с кодировкой интерпретирует UTF-8-байты его текста
как входные байты. Provider, располагающий исходным файлом в другой кодировке,
должен переопределить этот метод и декодировать исходные байты, а не уже
преобразованный текст.

Встроенный декодер поддерживает UTF-8, UTF-16/32 (BE/LE и варианты с BOM),
ASCII и 53 однобайтовые кодировки из закреплённого Ruby: ISO-8859,
Windows-1250–1257, KOI8-R/U, ряд IBM/Mac, TIS-620 и Windows-874.
Также поддержаны Shift_JIS, Windows-31J, EUC-JP, eucJP-ms и CP51932;
одно-, двух- и трёхбайтовые последовательности преобразуются по таблицам Ruby.
Варианты сохраняют разные отображения: алиас `SJIS` означает Windows-31J,
а не строгий Shift_JIS. Незавершённая, недопустимая или не имеющая Unicode-
отображения последовательность возвращает `InvalidEncoding`.
Big5, Big5-HKSCS, Big5-UAO, CP950 и CP951 используют отдельные двухбайтовые
таблицы Ruby, включая private-use и символы вне BMP. `Big5-HKSCS:2008` — алиас
Big5-HKSCS; `csBig5` в Ruby неизвестен. Варианты нельзя подменять одним web-
декодером: в частности, HKSCS `8862/8864/88a3/88a5` не имеют отображения.
Как и остальные перекодирующие codecs, Big5 проверяет пропущенные байты внутри
прочитанной части и при выборе тегов; конечный `lines` может восстановить
исправный префикс до повреждённого хвоста. Позиции относятся к декодированному
UTF-8-снимку; одинаковый результат разных вариантов переиспользует source ID,
разные результаты сохраняются отдельно.
GB2312 (алиасы `EUC-CN`, `eucCN`), GB12345, GBK (алиас `CP936`) и GB18030
также используют отображения Ruby. GBK принимает одиночный байт `80` как евро,
GB18030 требует `a2e3`; GB12345 сохраняет традиционные иероглифы.
Четырёхбайтовый GB18030 проверяет грамматику и явные диапазоны отображений,
включая символы вне BMP, пробелы между диапазонами и верхнюю границу Unicode.
Ошибки, усечённые последовательности и пропущенные повреждённые байты в
прочитанной части обрабатываются как у остальных перекодирующих codecs.
EUC-KR (алиас `eucKR`) и CP949 поддержаны отдельными таблицами Ruby.
Расширенные слоги хангыль CP949, например `8141` → `갂`, отклоняются EUC-KR.
Обе кодировки сохраняют строгую проверку прочитанных байтов до выбора тегов
и при пропуске строк внутри прочитанной части.
ISO-2022-JP (алиас `ISO2022-JP`) поддерживает переключения JIS X 0208/ASCII
через `ESC $ B`/`ESC $ @` и `ESC ( B`/`ESC ( J`. Roman сохраняет `\`/`~`;
сброс перед EOF не обязателен. Неизвестные escape-последовательности, SO/SI,
повреждённые/неопределённые пары и CR/LF внутри JIS отклоняются. Конечный
`lines` может сохранить исправный префикс; source identity, позиции и spans
относятся к декодированному UTF-8, как у остальных codecs.
CP50220/CP50221 используют тот же автомат с vendor-таблицей CP51932.
`ESC $ @` запрещает vendor-строки `2d` и `79–7c`, сохраняя Windows-отображения
базовых символов; эти расширения доступны после `ESC $ B`.
`ESC ( I` и SO включают полуширинную катакану; SI возвращает ASCII, не
восстанавливая предыдущий режим. Вне JIS принимаются raw bytes `a1–df`.
Контрольные байты/пробел/CR/LF в режиме катаканы, SO/SI внутри JIS-пары и
неизвестные escape-последовательности вызывают `InvalidEncoding`. Оба варианта
декодируют одинаково; результат, а не external encoding, определяет source identity.
`stateless-ISO-2022-JP` декодирует отдельные тройки `90/92 a1–fe a1–fe`
через таблицу EUC-JP; ESC и SO/SI отклоняются как в файловом конвертере Ruby,
прочие ASCII-байты сохраняются без переключений. `String#encode` с его
ASCII fast path не является эталоном файлового декодирования этих контролов.
Bare EUC-пары, kana/0212 префиксы, повреждённые/неопределённые тройки
вызывают `InvalidEncoding`. Оба префикса при одинаковом результате используют
общий UTF-8-снимок; прежние снимки сохраняются после изменения ресурса.
Поддерживаются имена и алиасы Ruby без учёта регистра. Неизвестное имя
игнорируется с возвратом к UTF-8; известное, но неподдержанное многобайтовое
имя (например, ISO-2022-JP-KDDI) возвращает `Unsupported`, а не молча становится
UTF-8. Кодировки без доступного преобразователя в эталонном Ruby
(например, Windows-1258) дают ошибку чтения. Таблицы воспроизводятся командой
`ruby scripts/generate_encodings.rb > crates/adoctra-core/src/source_encoding_tables.rs`
и `cargo fmt --all`; зависимостей для декодирования нет.

`SourceMap::load_with_encoding` и `SourceMap::load_include` регистрируют
*декодированный UTF-8-снимок*.
Именно его возвращают `SourceFile::text`, `source_text` WASM и `SourceMap::slice`;
byte spans не являются смещениями в исходном UTF-16/однобайтовом файле.
BOM и CR/LF сохраняются в снимке до прежней нормализации reader.
Reader также удаляет BOM в начале первой выбранной строки после selection;
исходный снимок сохраняет его, и диапазоны указывают на текст после BOM.
Одинаковые каноническое имя, декодированный текст, признак полноты и записи
пропусков переиспользуют source ID;
разные результаты декодирования одного файла получают разные неизменяемые снимки.
`SourceFile::is_complete()` и WASM `source_is_complete(id)` позволяют отличить
исправный префикс или текст с пропусками от полного файла. Частичный снимок не заменяет полный и не
используется как кэш успешного чтения: последующая полная загрузка обращается
к provider и сообщает об ошибке повреждённого хвоста. Замена ресурса полным
файлом с тем же текстом создаёт отдельный ID, сохраняя старые диапазоны.
Неудачное декодирование не регистрирует источник. `MemoryResources.insert_binary`
и WASM `set_binary` позволяют передать исходные байты include; двоичный буфер
имеет приоритет над текстовым буфером того же имени при таком чтении.

`SourceFile::omitted_lines()` возвращает
`OmittedSourceLine { offset, line, bytes }`: место вставки в сохранённом UTF-8-
тексте, исходный номер строки (с единицы), точные байты включая окончание строки.
Последовательные пропуски могут иметь одинаковый offset. WASM предоставляет
`source_omitted_lines_json(id)`, где `bytes` — hex-строка. Непрочитанный хвост
за конечным `lines` не входит в этот список; о нём говорит `is_complete=false`.
Изменение пропущенных байтов создаёт новый source ID даже при одинаковом тексте.
Пропущенные байты учитываются в лимите include вместе с сохранённым текстом.

Диапазоны AST/tokens относятся к сохранённому UTF-8-представлению, а не к
смещениям полного исходного UTF-8-файла с пропусками. `SourceMap::slice`
возвращает только сохранённый текст; `SourceFile::position` учитывает пропуски
и возвращает исходный физический номер строки. Клиент WASM должен учитывать
метаданные пропусков при отображении координат. Такой снимок нельзя использовать
как первичный источник `parse_resource`: это даёт `InvalidEncoding`, а не
неявный разбор склеенного текста. Обычные полные снимки и префиксы не менялись.

Диагностики маркеров в пропущенных BINARY-строках содержат
`omitted_span: Option<OmittedSourceSpan>` с полями `line`, `start`, `end`.
`line` — физический номер строки из `omitted_lines`, а диапазон `[start,end)`
относится к её исходным байтам. Source ID берётся из `Diagnostic::span`;
сам `span` пустой и указывает точку вставки в сохранённый UTF-8-текст.
Для точного перехода к маркеру нужно использовать `omitted_span`, а не
`position(span.start)`, который относится к сохранённому тексту.
`SourceFile::omitted_slice` проверяет диапазон и возвращает исходные байты.
WASM экспортирует необязательное поле `omitted_span` в JSON диагностики.
CLI `--diagnostics editor` помечает эти диапазоны `at omitted bytes` и использует
побайтовую колонку. Conversion-курсор и текст сообщения остаются как в Ruby.
Невалидное UTF-8-имя в сообщении выводится как `<binary:HEX>` без потери байтов:
Ruby JSON logger в таком случае может падать; это граница сравнения.

Выбранный повреждённый UTF-8 и
ASCII-8BIT может завершать Ruby исключением вне обработки ошибок include;
аналогичная граница есть у selection с неявным UTF-16 BOM. Эти границы
совместимости остаются открытыми; adoctra сохраняет частичный результат и
диагностику вместо падения. Неподдержанные многобайтовые кодировки также остаются
в очереди совместимости.

`ResourceProvider::load_binary(ResourceRequest)` загружает байты ресурса
(`BinaryResource { name, bytes, content_type }`, тип — например, из HTTP
`Content-Type`) с тем же разрешением путей; по умолчанию возвращает
`ResourceErrorKind::Unsupported`. Его использует `data-uri`, как `image_uri`
Ruby: ниже secure mode при преобразовании `src` блочных и inline-картинок, значков
`icon:`, admonition и callouts становится `data:<тип>;base64,…`. Файл
запрашивается относительно основного документа (`base_dir` Ruby) под
`imagesdir`/`iconsdir`, тип — по расширению (`.svg` — `image/svg+xml`, без
расширения — `application/octet-stream`); нечитаемый файл даёт пустые данные и
предупреждение `image to embed not found or not readable` в месте картинки. URI
(или цель под URI-каталогом) читается только с `allow-uri-read` (тип из ответа,
при ошибке остаётся URI с предупреждением). Строковые API без provider всегда
получают пустые данные. MemoryResources хранит двоичные буферы
(`insert_binary`/`remove_binary`; текстовые буферы тоже читаются как байты), CLI
читает файлы и http/https, WASM `ResourceWorkspace.set_binary`.

`ResourceProvider::document_path(name)` необязательно возвращает абсолютный путь
с разделителями `/` в пространстве provider. Метод не загружает ресурс заново;
по умолчанию возвращает `None`, поэтому произвольные идентификаторы не считаются
путями. MemoryResources возвращает виртуальный путь, файловый adapter CLI —
канонический файловый путь (включая разрешение symlink). Путь — только метаданные:
`referrer` при загрузке включений остаётся исходным каноническим именем ресурса.

При `parse_resource` и `tokens_resource` этот путь основного снимка задаёт
`docfile`, `docdir`, `docname` и `docfilesuffix` до чтения заголовка. Имя и суффикс
следуют Helpers.basename/extname эталона, включая файлы без расширения, dotfiles,
несколько точек и завершающую точку. Атрибуты блокируются: они перекрывают значения
в ParseOptions и не изменяются объявлениями/unset в header, теле или включениях.
Вложенные include сохраняют пути основного документа; значения доступны в условиях,
целях и поддержанных параметрах include. ParseOptions вызывающего кода не меняется.

Строковый API, stdin и provider без document_path не получают неявных атрибутов
путей, cwd или окружения. Явные атрибуты ParseOptions продолжают работать.
В server/secure mode `docdir` становится пустым, а `docfile` — относительным, как
в Ruby (см. `ParseOptions.safe` ниже); сами пути provider не маскирует. Встроенных `includedir`, `infile` и `indir` в
закреплённом Ruby нет; включаемые файлы используют обычный referrer provider.

`SourceMap::load(target, relative_to, provider)` загружает и регистрирует источник.
`relative_to: Option<SourceId>` задаёт текущий исходный файл; неизвестный id даёт
ошибку до вызова provider. Одинаковые каноническое имя и текст используют прежний
id; изменённый текст получает новый id, а старые диапазоны остаются действительными.
Неудачная загрузка не меняет карту. В одной карте имена provider должны находиться
в общей области идентичности: независимые provider с разными файлами не должны
выдавать одинаковые канонические имена.

[source,rust]
----
use adoctra::{MemoryResources, SourceMap, ParseOptions, parse_with_options};

let mut resources = MemoryResources::new();
resources.insert("docs/main.adoc", "= Main\n\nBody").unwrap();
resources.insert("docs/parts/one.adoc", "See <<missing>>.").unwrap();
let mut sources = SourceMap::new();
let root = sources.load("docs/main.adoc", None, &resources).unwrap();
let part = sources.load("parts/one.adoc", Some(root), &resources).unwrap();
let options = ParseOptions { source_id: part, ..Default::default() };
let parsed = parse_with_options(sources.get(part).unwrap().text(), &options);
assert_eq!(sources.slice(parsed.diagnostics[0].span), Some("<<missing>>"));
----

`MemoryResources` хранит буферы приложения и не обращается к диску или сети.
Имена — виртуальные пути с `/` на всех платформах. Начальный `/` означает корень,
`.` и `..` нормализуются; выход выше корня запрещён. Пустые имена, имена директорий,
NUL, backslash и colon не принимаются; URL/OS-пути не интерпретируются.
`insert` заменяет буфер, `remove` удаляет его. Уже зарегистрированные снимки в
`SourceMap` не меняются при редактировании или удалении буфера.

Файловый adapter находится в CLI. Основной файл загружается через него; канонический
родитель этого явно заданного файла становится корнем ресурсов. Относительные
запросы разрешаются от текущего файла, alias через symlink получает каноническое
имя, а путь за пределами корня отклоняется (в unsafe mode корень снимается).
Основной файл загружается как UTF-8; include из файлов и http/https (`ureq`,
при `allow-uri-read`) поддерживают декодирование, описанное выше.
Восстановления пути внутри jail, как в Ruby, нет:
отказ provider даёт строку `Unresolved directive`.

`ResourceError` содержит `kind`, `target` и `message`. Виды: `NotFound`,
`AccessDenied`, `InvalidTarget`, `InvalidEncoding`, `Unsupported` и `Io`. Ошибки явной загрузки
возвращаются как `Result`; reader подавляет `NotFound` для optional includes,
а прочие ошибки включений и синтаксические ошибки возвращаются как диагностики.

WASM экспортирует `ResourceWorkspace` с методами `set`, `remove`, `load`,
`source_name`, `source_text`, `parse_json` и `tokens_json`. `load` возвращает id
снимка; повторная загрузка изменённого буфера даёт новый id. Методы разбора и
подсветки принимают id основного снимка, загружают включения и возвращают id
каждого фактически использованного источника. Неизвестный основной id и ошибки
явной загрузки передаются JS как исключения со строковым сообщением; ошибки
включений попадают в `diagnostics`. В native Rust
доступен тот же класс с типизированными ошибками и методом `source`.

[source,javascript]
----
const workspace = new ResourceWorkspace();
workspace.set('docs/main.adoc', '= Main\n\ninclude::part.adoc[]');
workspace.set('docs/part.adoc', 'Hello *world*');
const main = workspace.load('docs/main.adoc');
const part = workspace.load('part.adoc', main);
const ast = JSON.parse(workspace.parse_json(main));
const tokens = ast.tokens;
----

Основной снимок не меняется, но включения загружаются из текущих буферов host при
каждом вызове. Поэтому `parse_json` и `tokens_json` в Rust требуют `&mut self` и
могут зарегистрировать новые снимки. Для согласованной пары AST/подсветки используйте
`document` и `tokens` одного результата `parse_json`: включения читаются один раз.
Старые снимки остаются доступными по id.

== Атрибуты

Внешние `ParseOptions.attributes` используют строковые формы Ruby. Обычное
`name=value` блокирует присваивания и удаления в документе; `name@=value` и
`name=value@` задают мягкое значение, которое документ может изменить или удалить.
`name!`/`!name` блокируют атрибут удалённым; `name!@`, `!name@`, `name!=@`,
`!name=@` удаляют умолчание без блокировки последующего присваивания.
При модификаторе на имени конечный `@` в значении сохраняется буквально.
CLI принимает те же формы через `-a`; последнее указание того же имени имеет
приоритет даже при смене формы. Имена регистронезависимы. Внешние значения
задаются строками, Ruby nil/boolean не входят в API. `Attributes` остаётся
BTreeMap: при прямом использовании API передавайте одну форму каждого имени,
а не конфликтующие формы с ожиданием порядка вставки. Блокировки процессорных
атрибутов и принудительных атрибутов safe mode сохраняются.

`ParseOptions.embedded` — режим `standalone: false` Ruby: атрибут `embedded`
(заблокирован, документ его не меняет) и умолчание `notitle`, если host не задал
`showtitle` (тогда `notitle` заблокирован удалённым) или `notitle` (тогда так же
`showtitle`). Документ standalone (по умолчанию) получает `copycss`,
`iconfont-remote`, `stylesheet` и `webfonts`. Присваивание `showtitle` в
документе, как `store_attribute`, сначала записывает обратный `notitle`.

`ParseOptions.safe` (`SafeMode`, по умолчанию `Safe`; Ruby API — `Secure`)
задаёт атрибуты и ограничения safe mode Ruby: `safe-mode-*`, блокировки
server/secure, усечение значений записей до `max-attribute-value-size`, ссылки
вместо include в secure. `allow-uri-read` (только от host) разрешает передавать
provider цели include по URI; без него они становятся ссылками.
`SafeMode::of(attributes)` восстанавливает уровень по `safe-mode-level`.

`ParseOptions.dates` (`DocumentDates { local, document }` из `DateTime` с
`utc_offset` в секундах) — часы host для `fill_datetime_attributes` Ruby:
`localdate`/`localyear`/`localtime`/`localdatetime` и `docdate`/`docyear`/
`doctime`/`docdatetime` (`%F`, `%T` и `UTC` или `±hhmm`) заполняют только
незаданные ключи, поэтому внешние и header-значения имеют приоритет, а заданная
дата выводит год. Ядро не читает часы: без `dates` эти атрибуты не задаются.
CLI передаёт `SOURCE_DATE_EPOCH` (UTC, оба времени) или локальное время и время
изменения входного файла.

`Document::authors()`/`authors_line()` дают авторов шапки HTML, как
`Document#authors` Ruby. `adoctra_core::docinfo(attributes, location, suffix,
provider, referrer)` — `Document#docinfo`: файлы `docinfo`/`docinfo1`/`docinfo2`
(shared/private с квалификаторами расположения) из `docinfodir` через provider,
нормализованные и с подстановками `docinfosubs` (по умолчанию attributes).

Разбор поддерживает атрибуты перед заголовком и непосредственно после `= Title`,
присваивания на границах блоков, обе формы удаления (`:!name:` и `:name!:`), а также
подстановку ссылок на атрибуты в значениях. Строка атрибута внутри уже начавшегося
параграфа или verbatim-блока остаётся текстом. Изменения внутри parsed-контейнера
действуют и после него.

`Document.attributes` — снимок заголовка. Каждый `Block.attribute_context` хранит
неизменяемый снимок на момент завершения разбора блока. Снимки используют
`Arc<Attributes>` и разделяют данные до следующей записи. `Block.conversion_context`
(`Block::conversion_attributes()`) — атрибуты при преобразовании блока, которые
читают backends, как конвертер Ruby: снимок заголовка с воспроизведёнными
объявлениями и эффектами предыдущих преобразований, взятый при входе в блок до
его названия и содержимого, без эффектов только чтения (объявления без
следующего блока, выражения в заголовках разделов). Уже разобранные inline-
значения остаются привязаны к моменту их сканирования. Подписи примеров назначаются
при завершении блока, дочерние раньше родительского, до кэширования его названия.
Используется текущий example-caption; его удаление отключает подпись и счётчик.

Определения атрибутов выполняют `{set:name:value}`, `{set:name}`, обе формы
unset (`{set:name!}`, `{set:!name}`), `{counter:name[:seed]}` и
`{counter2:name[:seed]}`. Контекст выполнения общий для обычной a-стадии,
выбранных pass-стадий, ранних quote-метаданных и повторных параметров ссылок
внутри определения. Операторы регистрозависимы, обычные имена set нормализуются;
имена счётчиков сохраняются точно, включая регистр. `Attributes::get` остаётся
регистронезависимым API обычных ссылок; `iter` может содержать отдельный ключ
счётчика с заглавными буквами. Целые счётчики не ограничены машинным разрядом;
строковые значения используют числовой/буквенный перенос с Unicode.

Пустой результат set/counter2 удаляет только ставшие пустыми строки. Unset по
умолчанию удаляет затронутую строку целиком; attribute-undefined меняет это
поведение. Все выражения стадии выполняются до фильтрации строк. Политики missing
и undefined выбираются при первом соответствующем событии и сохраняются до конца
стадии. Locked-присваивания не вычисляют значение; locked-счётчик имеет отдельный
регистр продвижения и не меняет исходный host-атрибут.

После header сохраняется отдельное состояние воспроизведения деклараций.
Побочные изменения при вычислении body-определения влияют на дальнейшее чтение,
условия, includes и заголовки разделов. При формировании обычного inline-текста
воспроизводится только результат самого объявления, без повторения его побочных
эффектов. Например, после header `:first: {counter:n}` значение n равно 1;
body-запись `:second: {counter:n}` задаёт second=2, но обычный `{n}` продолжает
давать 1 до явной записи n. `Block.attribute_context` сохраняет состояние чтения
при завершении блока, а не отдельную таблицу воспроизведения.

Stateful passthrough выполняется при восстановлении каждого вхождения slot.
Удалённый внешней стадией slot не исполняется; два вхождения одного slot
исполняются отдельно. Предел вложенности остаётся 32, диагностика указывает на
физическое определение, включая составное происхождение. Токены определений
остаются attribute-entry, использования — attribute-ref; новых вариантов узлов
и схем сериализации нет. `parse`/`tokens` создают изолированные состояния.

Обычный текст параграфов, пунктов списков и verse выполняет stateful-выражения
в отдельном проходе после полного чтения документа, до отображения исходных
диапазонов и разрешения ссылок. Проход обходит содержимое в порядке вывода,
начиная со снимка header; перед блоками воспроизводит вычисленные результаты
явных объявлений. Даже присваивание того же значения является событием и может
сбросить счётчик, продвинутый предыдущим параграфом. Регистр locked-счётчиков
сохраняет результат всех определений, выполненных при чтении.

Body-эффекты не изменяют Document.attributes, Block.attribute_context и уже
обработанные условия, includes или заголовки разделов. Ранние q-метаданные
обычного текста, a-стадия, повторные параметры ссылок и поздние pass-стадии
используют один изменяемый контекст. Отброшенные при смене стиля исходные поля
не выполняются. AST готов к повторному преобразованию backends без новых эффектов.

Исполненные выражения представлены существующим AttributeRef с именем выражения,
resolved value и нейтральными parts; пустые результаты сохраняют адресуемый span.
WASM сохраняет этот узел, JSON — существующую проекцию resolved text/parts.
Tokens берёт выражения из готового AST, включая составное provenance; отдельный
лексический проход не выполняет их повторно. Диагностики проходят обе карты
текста: фильтрацию комментариев и преобразование reader/include.

Заголовки разделов выполняют set/counter/counter2 при чтении; ID и xref используют
уже вычисленные узлы без повторных эффектов. Изменения доступны последующим
определениям и preprocessing, но не становятся событиями воспроизведения.
Уровень самого раздела вычисляется до эффектов его названия; изменение
leveloffset влияет на последующие разделы.

Неявный doctitle выполняет раннюю a-стадию до метаданных header. Она сохраняет
неизвестные ссылки с фиксированной политикой skip даже при изменении
attribute-missing внутри выражения. Отображаемое название документа выполняет
normal-подстановки после чтения всех разделов, перед телом, начиная со снимка
header. Регистр locked-счётчиков при этом сохраняет эффекты фазы чтения.
Например, `= H {counter:n}` даёт doctitle `H 1` и отображаемый заголовок `H 2`.
Эффекты отображаемого названия переходят в вычисление тела, сохраняя исходные
Document.attributes и Block.attribute_context. Setext включает compat-mode после
раннего doctitle; защищённые backticks при выводе могут подавить второй эффект.

Переопределённый doctitle сохраняет охватывающий диапазон объявления, включая
составное происхождение через include; host-значение использует пустой span.
Подсветка сохраняет attribute-entry и не добавляет ложные inline-токены на весь
диапазон преобразованного объявления. Обычные выражения в заголовках получают
attribute-ref из готового AST. Новые публичные варианты узлов не вводятся.

Названия `.Title` сохраняют исходный текст до завершения блока. При явном ID и
наличии `{` в исходном названии normal-подстановки выполняются при чтении и
кэшируются. Эффекты видны дальнейшему чтению, но не воспроизводятся как
декларации. Остальные отображаемые названия вычисляются перед содержимым блока,
в общем изменяемом контексте преобразования. Для контейнера это происходит до
воспроизведения деклараций дочерних блоков. Повторная `.Title` заменяет прежнюю;
заменённые и оставшиеся без блока названия не исполняются и не диагностируются.

Название passthrough-блока не выводится в HTML. Если оно не кэшировалось при
чтении, AST сохраняет его как исходный Text без подстановок и предупреждений.
У кэшированного названия эффекты чтения сохраняются даже без вывода заголовка.
Физические spans заголовков, диагностики и tokens проходят общую карту reader;
исполненные выражения добавляют attribute-ref к существующему block-title.

Нумерация примеров использует общий example-number: определения и кэшированные
заголовки могут менять его при чтении. Подпись назначается до кэширования
названия и хранит полученный префикс. Сохранённое значение счётчика воспроизводится
при входе в блок, до названия и содержимого, отдельно от деклараций исходника.
Это сохраняет порядок вложенных примеров: номер внешнего назначается после
внутреннего, но воспроизводится раньше. Locked-счётчики, Unicode seed и целые
произвольной длины используют общий механизм; снимок header остаётся неизменным.
Эффекты обычного текста и поздних названий не меняют уже назначенные подписи.
Локальный `caption=` или атрибут документа `caption`, включая пустые значения,
заменяют префикс без нумерации. Caption остаётся строковым полем; структурные/raw
значения caption/example-caption и подписи остальных видов блоков ещё не перенесены.

Reftext блочного якоря `[[id,текст]]` выполняет раннюю a-стадию при чтении
метаданных, до разбора блока. Работают set/counter/counter2, host locks,
missing/undefined, обе формы экранирования и обычные ссылки на атрибуты.
Эффекты выполняются даже для впоследствии заменённых или сиротских значений;
якорь без reftext сохраняет текст предыдущего якоря в той же группе метаданных.
В теле документа эти эффекты видны дальнейшему чтению, но не входят в replay
явных деклараций. Ссылки используют сохранённый результат ранней стадии.

Начальные метаданные читаются до распознавания заголовка и снимка header,
включая определения между строками метаданных. Их эффекты входят в
`Document.attributes`. Сохранённые метаданные передаются заголовку документа
или первому блоку без повторного исполнения. Явный ID заголовка хранится на
его Heading; role и исходный вычисленный reftext — в атрибутах документа.
Атрибут reftext сохраняет raw-строку; подпись ссылки отдельно защищает её c-стадией.

`Block.reftext` — снимок, отформатированный набором c/q/r при завершении блока
или header, без исполнения выражений и без диагностик. Каждая ссылка форматирует
reftext заново (см. «Разрешение ссылок»). Второй a-проход, macros,
post-replacements и извлечение passthrough не запускаются: например, `link:p[{counter:n}]` увеличивает счётчик при чтении, но остаётся
текстом ссылки, а не вложенным HTML-якорем. Карта фрагментов сохраняет физические
spans выражений и предупреждений, в том числе через include/selection/indent.
Подсветка использует записанные reader диапазоны даже для заменённых и сиротских
значений. Пустой результат даёт название блока или раздела либо `[id]` без
предупреждения о неизвестном ID; пустые исходные AttributeRef сохраняются в AST.

Атрибуции, сами списки,
include-параметры и условия требуют отдельной интеграции. Остаются прочие
производные настройки блоков. Производные атрибуты backend/doctype описаны в
разделе совместимости «Встроенные атрибуты».

Многострочные значения поддерживают конечный ` \` и legacy ` +`. Первый
маркер определяет продолжение всей записи; другой маркер завершает значение
и остаётся его частью. Начальные ASCII-пробелы продолжений удаляются; строки
соединяются пробелом, а после ` +` внутри значения — переводом строки.
Пустая строка завершает запись и потребляется, EOF сохраняет собранное значение.
Контейнер ограничивает сбор своим закрывающим разделителем.

Условия и include раскрываются при сборе с прежним контекстом; подстановка
ссылок и запись атрибута происходят после сборки. Продолжение может начаться
в одном ресурсе и закончиться в другом. Даже locked/unset-запись потребляет
свои продолжения. Комментарии и похожие на блоки строки внутри значения
остаются текстом. Внутри обычного параграфа или verbatim запись не открывается.

Подсветка получает классификацию строк атрибутов от parser и возвращает отдельные
`attribute-entry` токены с физическими диапазонами, включая продолжения из include.
SourceMap не меняется; диапазон `AttributeRef` указывает на место использования.
Встроенный профиль backend/doctype реализован (см. совместимость); атрибуты safe
mode, даты и окружения, алиасы и настраиваемые substitutions впереди.
HTML hard break после подстановки значения и Ruby replay присваиваний из пустого
контейнера остаются явными XFAIL сравнительного корпуса.

== Заголовок документа

`Document.header: Option<DocumentHeader>` присутствует при начальном `= Title`
или двухстрочном setext-названии с эффективным уровнем 0.
Он содержит общий `span`, `title_span`, исходный текст `title`, `authors: Vec<Author>` и необязательную
`revision: Revision`. В литералах структуры `Document` следует добавить `header`
или использовать `..Default::default()`. Литералы `DocumentHeader` теперь также
требуют поле `title`.

`Author` содержит исходный диапазон, разобранное имя, firstname/middlename/lastname,
initials и email. `Revision` — диапазон, number/date/remark. Эти поля описывают
объявления строк исходника, до применения внешних переопределений и подстановок
в значениях. Для действующих значений используются `Document.attributes`
(`author`, `authors`, `authorcount`, `email`, `revnumber`, `revdate`, `revremark`
и производные поля имени). При нескольких авторах доступны также `author_1`,
`author_2` и соответствующие индексированные поля.

Название остаётся первым `BlockKind::Heading { level: 0, .. }` в `blocks`;
header ссылается на его исходный диапазон, не хранит вторую копию inline-дерева.
Общий visitor посещает диапазоны header. Standalone HTML выводит авторов и
ревизию в `.details` шапки, как `convert_document` Ruby.

Атрибуты могут находиться между названием, авторами и ревизией. Первая пустая
строка после названия завершает header: следующие строки остаются телом документа.
Явные `author`/`authors` также порождают поля имени без строки авторов; такие значения
не создают фиктивные исходные диапазоны в `header.authors`.

Индексированные `author_N` пересчитывают поля имени в конце header, если явные
`author`/`authors` не запустили собственный пересчёт. Нужен заголовок документа;
ключи просматриваются от `author_1` до первого пропуска. Сравнение выполняется
с объявлениями исходника; неизменённые имена сохраняют составные компоненты.
Пустые значения пропускаются, но полностью пустой результат не стирает строку
авторов. Производные поля объединяются с текущими атрибутами: невычисленные
lastname/middlename/email и прежние индексы сохраняются. При пересчёте header
отсутствующий email заполняется из email_1. Вычисленные поля могут заменить
host overrides, как в Ruby; блокировка последующих присваиваний остаётся.
В теле `author_N` меняет только сам атрибут, не производные поля и не header.
Документы без авторов имеют `authorcount=0`.

Setext-название распознаётся по двум соседним строкам обработанного reader:
текст не начинается с точки, содержит букву или десятичную цифру, а однородное
подчёркивание отличается по длине не более чем на один Unicode-символ. Маркеры
`=`, `-`, `~`, `^`, `+` соответствуют уровням 0–4 до leveloffset. ATX имеет
приоритет. Комментарий или пустая строка между текстом и подчёркиванием мешают
распознаванию; удалённые условия и раскрытые include могут соединять эти строки.
`title_span` и диапазон Heading охватывают обе строки, inline-диапазоны — только
текст; при нескольких источниках используется provenance. Подсветка выдаёт
отдельные `heading` для текста и подчёркивания с физическими координатами.
Setext устанавливает пустой compat-mode до последующих строк header; внешнее
locked значение сохраняется, последующий unset поддержан. Кавычки в тексте
используют действующий compat-mode блока; прочие эффекты setext-названия на
substitutions остаются отдельной работой.

Setext-разделы в теле используют ту же проверку строк, но только там, где Ruby
ищет разделы: на уровне документа (вне контейнеров и пунктов списка), а
discrete/float-заголовок — в любом контексте. ATX имеет приоритет; подчёркивание
распознаётся раньше разделителей блоков (`----`, `--`, `====`, `++++`), абзац
setext-заголовком не прерывается. Блок со стилем `comment` читает вторую строку
без препроцессора. Heading охватывает обе строки (с provenance при нескольких
источниках), inline-узлы — только текст; compat-mode не меняется. Reader
записывает строки заголовков разделов (`heading_lines`: ATX, текст и подчёркивание
setext), и подсветка выдаёт для них `heading` вместо токенов разделителей, не
повторяя классификацию. Вне контекста разделов (контейнеры, пункты списка, внутри
абзаца) строки заголовков — обычный текст, кроме discrete/float.

Разделы образуют дерево, как `next_section` Ruby. `BlockKind::Section { level,
blocks }` содержит в `blocks[0]` заголовок (`Heading` того же уровня с id, reftext,
ролями и атрибутами раздела), затем содержимое и подразделы. Диапазон раздела —
от названия до конца последнего вложенного блока (для сворачивания в редакторе),
снимок атрибутов — состояние после последнего блока. `BlockKind::Preamble { blocks }`
объединяет блоки между header и первым разделом, если у документа есть название и
хотя бы один раздел (у книги — и без разделов). Название документа и
discrete-заголовки остаются `Heading` вне дерева. Нарушение порядка уровней даёт
warning, раздел уровня 0 вне `doctype=book` — error, как в Ruby; если документ без
header начинается с раздела, уровни разделов верхнего уровня не проверяются.
`Document::flat_blocks`/`into_flat_blocks` возвращают блоки в порядке документа без
структуры разделов. JSON/WASM используют `name:"section"` (с `level`) и
`name:"preamble"` (с `title`).

Непустой `doctitle` до названия или в header заменяет действующее название.
Пустое значение и обе формы unset внутри header восстанавливают первоначальное
значение (включая override до названия). Внешний hard override сохраняется;
пустой внешний override допускает неявное название, но блокирует последующие
присваивания. Без строки названия непустой `doctitle` создаёт Heading, а
`Document.header` остаётся None: декларации названия в исходнике нет.

Неявный `doctitle` устанавливается до метаданных header и содержит снимок
подстановок на этот момент; inline-дерево названия вычисляется после чтения тела
из полного снимка header, перед преобразованием тела. Reader, как Ruby, заранее
читает две обработанные строки даже для ATX,
поэтому директивы непосредственно после ATX ещё не видят неявный `doctitle`.
Объявления атрибутов в теле воспроизводятся после вычисления названия;
снимок `Document.attributes` остаётся неизменным. Значения AST остаются нейтральным текстом:
HTML-экранирование выполняет backend, в отличие от HTML-строк атрибутов Ruby.

`header.title` хранит объявленный текст до подстановок/переопределений;
`title_span` и span Heading сохраняют диапазон декларации. Inline-узлы
переопределённого названия указывают на весь принятый attribute entry, включая
продолжения и provenance через файлы: точные позиции внутри преобразованного
значения не выдумываются. Без декларации span Heading также относится к entry.
Значение из ParseOptions без исходника использует пустой диапазон в начале
reader. Подсветка классифицирует реальные строки исходника: override остаётся
`attribute-entry` и не создаёт дополнительный `heading`-токен.

Вычисление явных author/authors/author_N различает буквальный текст и raw-разметку.
Внешние значения интерпретируются как уже обработанные значения Ruby; строка
`pass:[…]` во внешнем значении сама повторно не разбирается. В документе обычное
`<b>Имя</b>` остаётся текстом, а `pass:[<b>Имя</b>]` сохраняет raw-разметку.
Whole-value pass поддерживает none, a/attributes, c/specialcharacters/specialchars
и r/replacements, q/quotes с roles/id и ссылочные m/macros, включая порядок
и исключение повторов. Остальные стадии
пока не поддержаны.
Компоненты имени исключают raw-теги, а author сохраняет исходное форматированное
значение. Поля исходного `header.authors` и их диапазоны не меняются.

Стадия r/replacements в whole-value pass использует общий механизм замен, но
сохраняет созданные entity как Raw-синтаксис: `pass:r[(C)]` даёт `&#169;`,
а следующая c-стадия в `pass:r,c[(C)]` превращает его в буквальную Text-часть.
Это позволяет последующим стадиям видеть ту же запись, что и Ruby. Замены
пересекают Text/Raw-границы после a-стадии; повторы и aliases выполняются один
раз, в порядке первого появления. Переносы в собранном значении не сворачиваются.
Определение атрибута сохраняет результат выбранных стадий; при использовании
`{name}` отдельно выполняются обычные inline replacements.

`Attributes::get`/`iter` возвращают объединённый текст без семантических маркеров
форматирования. Для значения с raw/форматированными частями `raw_parts(key)`
возвращает `AttributePart::Text`/`Raw`/`Open`/`OpenWithAttributes`/`Close`/`OpenLink`/`CloseLink`;
`set_parts` сохраняет эти границы, а обычный `set` заменяет их буквальным текстом.
При импорте ParseOptions строки без raw_parts считаются внешними raw-значениями.
Snapshots копируют границы вместе со значениями. `Inline::AttributeRef` получил
поле `parts: Vec<AttributePart>`: пустое для обычного текста, иначе содержит все
части. Литералы этого enum-варианта требуют нового поля. Его span по-прежнему
указывает на исходную ссылку `{name}`, независимо от длины значения.
HTML-экранирование выполняет backend; core не сохраняет сериализованный HTML
вместо буквальных частей. Raw-разметка остаётся явно отличимой от них.

`Open(AttributeFormat)` / `Close(AttributeFormat)` представляют strong, emphasis,
monospace, mark, superscript, subscript и span. Маркеры разделены: последовательные
стадии Ruby могут создавать пересекающееся форматирование. `AttributePart::text()`
для маркера возвращает пустую строку, `is_raw()` — false. Исчерпывающие match
должны учитывать все варианты границ. HTML самостоятельно выбирает теги;
core хранит нейтральные маркеры и использует временное лексическое представление
только для следующих стадий и вычисления метаданных.

`pass:c,q[*A & B*]` сохраняет Open(Strong), Text("A & B"), Close(Strong),
а `pass:q,c[*A & B*]` — буквальный Text("<strong>A & B</strong>").
Поддержаны одиночные/двойные маркеры, типографские кавычки, экранирование,
порядок стадий и подстановки через границы частей. Форматирование сохраняется
в replacements, author/authors, snapshots и ссылках на разделы. Span остаётся
на исходном `{name}`; синтетические части не получают вымышленных позиций.
Для q-стадии при присваивании атрибутов compat-mode фиксируется при создании
контекста и завершении header,
как в Ruby; host override действует сразу, присваивание в header — после header.
Обычный inline-текст использует тот же q-проход, но текущий compat-mode блока.

`OpenWithAttributes { format, id, role }` сохраняет свойства форматирования.
Поля id/role — необязательные строки с уже подставленным лексическим написанием,
включая защиту entity; `Some("")` и None различаются. HTML не экранирует их повторно,
как и Raw-фрагменты. Host, передающий структурные части через set_parts, должен
передавать уже подготовленные значения. Плоские get/iter/value не включают
id/role, а JSON/WASM добавляют поля `id` и `role` к объекту `kind:"open"`.
`AttributeFormat::Span` представляет unquoted-текст с метаданными; его name —
`"span"`. Например, `[.red]#x#` даёт OpenWithAttributes(Span, role="red"),
текст и Close(Span); `[ ]#x#` даёт только текст.

Немедленные подстановки в списке quotes используют текущие атрибуты.
Поздние a/r-стадии сохраняют метаданные при изменении значений id/role;
c после q превращает всё временное лексическое представление в Text.
Произвольные raw-теги не распознаются как новые семантические узлы.
Обычный inline a-проход теперь также поддерживает intrinsic-атрибуты и оба
способа экранирования. Теперь тот же resolver используется в определениях
атрибутов и выбранных a-стадиях pass:.

`OpenLink(AttributeLink)` / `CloseLink` задают нейтральные границы ссылки.
AttributeLink содержит target и необязательные id/role/title/window/rel.
Строки сохраняют подставленное лексическое написание и entity-защиту, как
поля OpenWithAttributes; host передаёт уже подготовленные значения.
Содержимое подписи находится между границами и может иметь форматирование.
Плоские get/iter/value содержат только подпись, без адреса и свойств ссылки.
JSON/WASM экспортируют `kind:"open-link"`, target и присутствующие поля,
затем части подписи и `kind:"close-link"`. Span AttributeRef по-прежнему
относится к исходному `{name}`; синтетические границы не создают позиций.
Исчерпывающие match по AttributePart должны учитывать новые варианты.

Стадия m/macros в whole-value pass распознаёт link:, mailto:, URL и email.
Параметры ссылки следуют AttributeList, включая свежие подстановки внутри
одинарных кавычек. Для циклических host-значений вложенные pass/link-проходы
имеют общий предел 32: после лимита внутренний текст сохраняется без очередного
прохода и выдаётся Warning. Это редакторское ограничение, а не семантика Ruby.
Compat-mode для разбора параметров, как для q-стадии, фиксируется в контексте
и при завершении header. a/r после m сохраняют поля ссылки, c защищает всё
временное написание. Автоматические ID используют подпись, удаляя ссылочные
теги из временного текста; заимствованный текст xref удаляет OpenLink/CloseLink
из копии, сохраняя исходный заголовок, форматирование и диапазоны.

После раскрытия атрибутов и replacements ссылочная m-стадия обрабатывает общий
поток соседних Text/Raw/разрешённых AttributeRef. Ссылки могут пересекать границы
узлов и частей значений. Уже обработанный при определении pass:m URL снова
распознаётся в видимой подписи; экранирование снимается один раз за проход.
Определения и snapshots не меняются. После ссылок и email та же m-стадия
распознаёт inline-якоря (см. «Каталог inline-якорей»), а последними — xref
(см. «Разрешение ссылок»). `pass:m` и повторный проход параметров ссылок тоже
распознают xref: результат — части `OpenXref`/`CloseXref` в Substituted или
AttributeRef, подписи и предупреждения (с диапазоном охватывающей конструкции)
вычисляются при преобразовании; токены `xref` для сгенерированного синтаксиса не
создаются. Угловая форма в pass требует `c` (иначе `<<` не защищён), а макросная
форма — `\]`, так как содержимое pass заканчивается первой `]`. В определениях
атрибутов Ruby фиксирует подпись при определении по частичному каталогу; adoctra
вычисляет её при использовании (явный XFAIL). Остальные pass-макросы, включая
image/icon, сохраняются текстом.

Если результат начинается в обычном тексте, он представлен
`Inline::Substituted { value, parts, span }`: плоское значение, нейтральные части
и диапазон поглощённых исходных конструкций. JSON/WASM экспортируют
`name:"substituted"`, `value`, `parts`; WASM добавляет физический span.
HTML выбирает разметку частей так же, как для AttributeRef. Общий обход, ID и
заимствованные подписи xref учитывают новый узел. Исчерпывающие match по Inline
нужно обновить. Исходные AttributeRef сохраняются, в том числе с пустым
значением после поглощения. JSON передаёт их как итоговый текст, WASM — как
attribute-ref с исходным именем и физическим span.

Прямые ссылки теперь также создаются общим macro-проходом и представлены
Substituted, а не Inline::Link. Вариант Link сохранён для программно созданных
деревьев и поддерживается backends. Quotes временно разворачиваются в семантические
границы; непоглощённые пары восстанавливаются в исходные Strong/Emphasis и другие
узлы с прежними диапазонами. Поглощённая подпись хранит форматирование в parts.
Одиночные маркеры учитывают лексические границы; двойные дают unconstrained
форматирование. Общий с pass:q проход применяет стадии в порядке Ruby,
обрабатывает экранирование, roles/id и типографские кавычки до attributes.
Форматирование с метаданными хранится в нейтральных частях Substituted;
типографские кавычки — Unicode Text с диапазонами исходных маркеров.
Поглощённые метаданными ссылки на атрибуты сохраняются как пустые AttributeRef
с исходными spans и токенами. Полученный из атрибутов текст повторно не проходит q.
Xref распознаются той же m-стадией в общем потоке. Ранняя регистрация
якорей, поглощаемых quote-метаданными, ещё не перенесена; их reftext может теряться.
Inline passthrough извлекается до quotes и возвращается после внешних
attributes/replacements/macros. + и ++ защищают специальные символы и сохраняют
буквальные маркеры, +++ сохраняет raw-разметку, $$ работает как буквальная форма.
В compat-mode +/++ остаются quote-маркерами, а backticks дают защищённый monospace.
Поддержаны roles/id, экранирование, legacy x- и inline pass: с отдельными
c/q/a/r/m/p-стадиями, normal/n, verbatim/v, specialchars и none. Resolver общий
для inline и whole-value pass. Группы раскрываются до удаления повторов,
порядок первого появления сохраняется; -name в последующих позициях удаляет
ранее выбранные стадии. Verbatim/v внутри pass означает только защиту специальных
символов, без callouts. Basic не является допустимым именем эталона.
Неизвестные стадии отбрасываются с Warning, остальные применяются. Нераспознанная
лексическая форма pass остаётся обычным текстом без предупреждения о стадиях.

При наличии m/macros вложенные passthrough извлекаются до всех выбранных стадий,
даже если m стоит последним. Вложенность ограничена 32 уровнями: превышение
сохраняет остаток как raw-текст и добавляет Warning. Прямой selector имеет
физический span; вложенный после преобразований ссылается на охватывающий pass,
а whole-value — на определение атрибута. Reader сохраняет source_id и provenance
диагностики через include/selection/indent и удалённые комментарии. Locked
определения не вычисляются и не создают предупреждения.

Добавлен AttributePart::LineBreak: p и завершающая стадия normal создают
нейтральный перенос, JSON/WASM передают kind:"line-break", HTML выбирает br.
Исчерпывающие match по AttributePart должны учитывать новый вариант.
Поздний c защищает временное написание переноса как текст. Поддержаны LF/CRLF,
конечный маркер и hardbreaks-option внутри pass и обычного inline-текста.
Общий post_replacements.rs выполняется после replacements/macros, до возврата
защищённых участков. Поэтому маркер из значения атрибута обрабатывается,
а обычный passthrough не проходит внешнюю p-стадию повторно. Stem остаётся впереди.

В обычном режиме конечный ` +` создаёт LineBreak; с hardbreaks-option
обрабатываются только строки с последующим переводом строки, последняя строка
сохраняет свой маркер. hardbreaks — alias hardbreaks-option для document/host,
включая обе формы unset и locked overrides. Локальные %hardbreaks,
options=hardbreaks и named hardbreaks-option включают опцию для inline-тела
блока, не меняя attribute_context, следующие блоки и содержимое контейнеров.
Локальная опция не задаёт именованный атрибут: {hardbreaks-option} по-прежнему
разрешается только через document/host, в том числе внутри выбранного pass:a.
Principal-текст элементов списка использует документную опцию; verse сохраняет
переводы строк.

Исходные переносы представлены Substituted с диапазоном маркера или физического
перевода строки; переносы из значений остаются в AttributeRef с его исходным span.
Поглощённые ссылки сохраняются пустыми узлами. Карта происхождения переносов
составляется через комментарии/include, включая CRLF и selection/indent.
TokenKind::LineBreak экспортируется как line-break и берётся из полного AST для
самостоятельных source-owned переносов с учётом последней строки блока и
локальных опций. Attribute-owned перенос сохраняет
attribute-ref; protected-фрагмент — pass-text; части внутри результата ссылки
сохраняют её внешний токен. Прочие многострочные конструкции используют общий
проход, описанный в разделе «Единый результат для редактора».

Защищённый результат представлен существующим Substituted: Text/Raw сохраняют
различие буквального текста и разметки, форматирование задаётся нейтральными
границами. Его span охватывает исходную конструкцию с маркерами; при поглощении
ссылкой он входит в диапазон ссылки. Приватные placeholders не сохраняются в
итоговом дереве в исходном виде, в том числе в адресах и метаданных. Исключение
эталона — mailto subject/body: percent-encoding кодирует слот до восстановления,
поэтому адрес сохраняет его закодированное написание; это закреплено регрессией.
Совпадающий текст источника
и host-атрибутов не считается placeholder. Определения атрибутов и snapshots
не меняются; раскрытые значения не запускают извлечение повторно.
Подсветка использует pass-text на всей распознанной конструкции либо monospace
для защищённых legacy/compat-форм. Буквальные внутренние маркеры не подсвечиваются
как quotes/attributes/macros. Прежнее ограничение построчного scanner остаётся
для многострочных inline-конструкций; их AST и составные spans поддержаны.

Обычная a-стадия (`inline_attributes.rs`) применяется к лексическому результату
quotes до replacements/macros. Имена используют Unicode Word и дефисы после
первого символа; определения атрибутов сохраняют combining marks и connector
punctuation той же грамматики. Имена регистронезависимы. `\{name}`, `{name\}`
и `\{name\}` оставляют буквальное `{name}` без AttributeRef-токена; снимается
один начальный слеш. Значения не запускают a-стадию или quotes повторно.

Документные/host-значения имеют приоритет перед intrinsic-атрибутами (`cpp`,
`nbsp`, `empty`, `sp` и остальными именами закреплённого эталона). Intrinsics
используют Raw-части, сохраняя entity-написание до следующих стадий. Определения
и snapshots при inline-подстановке не меняются. Поздняя подстановка в id/role
сохраняет нейтральные границы форматирования.

`attribute-missing` применяется к текущему inline-потоку:

* `skip` и неизвестная политика сохраняют ссылку с `value: None`.
* `warn` сохраняет ссылку и создаёт Warning на каждое вхождение.
* `drop` удаляет ссылку и строки, ставшие пустыми именно из-за отсутствующих
  значений. Определённое пустое значение само по себе строку не удаляет;
  пробелы и сгенерированные границы форматирования делают строку непустой.
* `drop-line` удаляет затронутую строку и создаёт Info. Строки определяются
  после раскрытия значений, включая переводы строк из host-атрибутов.

Удалённые и поглощённые ссылки сохраняются как AttributeRef с `Some("")`,
физическим span и токеном. Сохранённые неизвестные ссылки участвуют в позднем
разборе URL и их подписей, не разрывая поток. После поглощения ссылкой их
собственный вклад становится пустым. Экранированные и защищённые passthrough
ссылки не диагностируются. Диагностики проходят через карты комментариев,
include/selection/indent и сохраняют source_id. Буквальный fallback неудачного
include может дополнительно сообщить Warning о своей неизвестной ссылке.

WASM экспортирует AttributeRef, parts, диапазоны и диагностики; JSON сохраняет
существующую проекцию в resolved text с parts, без исходной формы AttributeRef.
HTML выбирает экранирование по Text/Raw. Stateful set/counter в определениях и
обычном inline-тексте описаны выше. Подсветка использует целые поля общего
разбора и не исполняет выражения повторно.

Ранние quote-метаданные и повторная подстановка single-quoted link params
используют общий a-resolver и текущую политику attribute-missing. Метаданные
q получают mapped lexical slice; intrinsic-значения, Text/Raw и экранирование
не проходят дополнительного неявного экранирования. Обычный warn может дать
два сообщения: на ранней q-стадии и при последующей a-стадии по сгенерированному
полю. Эти сообщения отражают разные подстановки и не дедуплицируются.
У защищённого passthrough позднего повторного a-прохода нет.

Диапазон раннего source-metadata предупреждения указывает на ссылку; позднего —
на породившую поле открывающую конструкцию. Переписанные single-quoted link
параметры используют span исходного макроса; вложенные macro-стадии сохраняют
его. Selected pass и passthrough metadata используют охватывающий pass,
определения — декларацию целиком. Reader переносит эти координаты в физические
source_id/provenance через комментарии и include/selection/indent.

Drop-line действует внутри текущего поля метаданных или параметра, сохраняя
остальное форматирование и ссылку. Title/reftext/opts/options не запускают
повторные substitutions; такое же исключение применяется к разобранному
single-quoted значению с начальным апострофом. Остальные поля повторяют
c/q/a/r/m/p для реализованных семейств макросов: passthrough извлекается до c/q
и восстанавливается после p. Общий набор slots сохраняет защищённые участки
внешнего текста, нейтральные границы и наблюдаемую нумерацию в mailto encoding.
Экранирование закрывающих скобок снимается один раз на уровне macro label;
AttributeList затем снимает только экранирование своей кавычки.

Pass и повторные параметры используют общий предел вложенности 32. Warning
ссылается на охватывающую ссылку, pass или определение, включая физическое
происхождение через include. Переносы сохраняются как AttributePart::LineBreak;
hardbreaks-option по-прежнему отличает последнюю строку от явного ` +`.
Синтетический passthrough внутри параметра не создаёт pass-text tokens на всём
диапазоне ссылки; исходные link/attribute-ref/pass-text tokens сохраняются.
Новых публичных вариантов узлов или токенов этот набор не вводит.

Определения атрибутов и выбранная a-стадия `pass:` используют общий resolver
`inline_attributes::parts`. Он обрабатывает весь лексический поток, включая
Text/Raw-границы и поля нейтральных quote/link-границ. Unicode-грамматика,
оба положения экранирования, intrinsic-значения, приоритет переопределений
и однократность раскрытия совпадают с обычным inline-проходом.

Обычное определение защищает специальные символы до a; whole-value pass
сохраняет выбранный порядок c/q/a/r/m/p. Поэтому `pass:a,c[{cpp}]` хранит
буквальное entity-написание, а `pass:c,a[{cpp}]` — Raw. При использовании
определённого значения внешние replacements могут восстановить entity;
inline pass возвращается уже после внешних replacements. Эти контексты
не следует объединять в повторный normal-проход.

Определения используют политику attribute-missing из текущего контекста до
присваивания, включая само определение attribute-missing. Результат удаления
строки — заданное пустое значение, а не unset. Заблокированные определения
не вычисляются и не создают диагностики. Повторное использование значения
не повторяет диагностик определения. Строковые header helpers сохраняют
отдельное skip-поведение; их плоские API не получают синтетические диапазоны.

Warning/Info у определения указывают на всю декларацию, включая строки
продолжения. У выбранного inline или вложенного pass они указывают на всю
охватывающую конструкцию: тело могло быть распаковано или преобразовано
предыдущей стадией. Карты reader сохраняют физические source_id/provenance
через include/selection/indent. Токены AttributeEntry и pass-text остаются
на исходных конструкциях; новые типы публичных узлов не вводятся.

Replacements и macros сохраняют одну карту фрагментов до записи AST, поэтому
`(C) link:page[Label]` даёт диапазон только самой ссылки. Окружающий Text/Raw
остаётся отдельным; текстовые узлы могут разбиваться на несколько фрагментов.
Подсветка хранит исходные quote/attribute-токены даже при их поглощении и добавляет
Link с диапазоном, сообщённым общим matcher. Синтетические части не получают
выдуманных координат. Macro-проход не повторяет quotes или обычные attributes.

После подстановок общий проход replacements обрабатывает соседние Text и
AttributeRef в порядке Ruby: символы, тире, многоточие, апостроф/right single
quote, стрелки и entity restoration. Он сохраняет Text/Raw-защиту; определения
в Document.attributes и snapshots блоков не меняются. Типографские символы
хранятся как Unicode. Entity сохраняют raw-синтаксис, включая неизвестные имена;
они не декодируются и не запускают предыдущие стадии повторно.

`AttributeRef.value`/`parts` содержат итоговый вклад ссылки в поток. Если замена
начинается в предыдущем узле и поглощает значение, ссылка остаётся в AST с
`Some("")`; её span всегда указывает на исходное `{name}`. Результат замены
принадлежит первому поглощённому узлу. Для замены, начинающейся в исходном тексте,
span охватывает всю конструкцию, включая участвующие ссылки; диапазоны этих
узлов могут пересекаться. Токены ссылок сохраняются даже для пустого результата.

Добавлен `Inline::Raw { value, span }` для entity, восстановленных из обычного
текста (включая `&{name};`). Исчерпывающие match по Inline должны учитывать новый
вариант. HTML выводит value без экранирования, JSON/WASM — `name: "raw"` и value;
WASM также передаёт исходный диапазон. Внутри AttributeRef entity по-прежнему
хранятся в parts. Raw — семантический узел; отдельный токен подсветки не добавлен.

Остаются полный набор header substitutions и остальные macros в pass:,
отложенные reftext substitutions, stateful inline anchors/attribution,
подстановки в block attribute lists и preprocessing,
остальные семейства макросов повторного normal-прохода,
полная последовательность substitutions и структурные/raw-части
в прямых строковых потребителях, включая замену doctitle целиком.
Автоматические ID разделов удаляют raw-теги и entity по грамматике эталона
из временного лексического представления заголовка. Entity не декодируются:
`&#65;` удаляется, а не становится `A`. Защищённый буквальный текст и границы
форматирования/якорей сохраняют своё различие. Исходные inline-узлы, значения
атрибутов, snapshots и диапазоны не меняются; ссылки используют прежние узлы
заголовка. `idprefix`, `idseparator` и `sectids` читаются из атрибутов чтения
заголовка (`Block.attribute_context`); без `sectids` `Block.id` остаётся `None`.
Это основа модели, а не заявление полной совместимости заголовка.

== WASM

В JSON диапазонов добавлено поле `source_id`; `start` и `end` сохраняют смысл.
`parse_json` и `tokens_json` используют id 0. Новые `parse_json_with_source` и
`tokens_json_with_source` принимают id, назначенный приложением для буфера.
Имена и содержимое источников хранятся у приложения; исходный текст не дублируется
в каждом JSON-ответе.

При наличии заголовка JSON backend и WASM добавляют объект `header` с объявлениями
названия (`title`), авторов и ревизии; при отсутствии декларации заголовка поле опущено. WASM дополнительно
передаёт `span`, `title_span` и диапазоны авторов/ревизии. В потоке подсветки
строки авторов и ревизии имеют типы `author` и `revision` и не сканируются как
обычный текст тела документа.

Для ссылки с raw-содержимым JSON backend и WASM добавляют inline-поле `parts`
с элементами `{"kind":"text"|"raw","value":"…"}` или
`{"kind":"open"|"close","format":"strong"|"emphasis"|"monospace"|"mark"|"superscript"|"subscript"}`.
Существующее value содержит текст без семантических маркеров.
WASM также передаёт необязательный `document.attribute_parts`, где ключи атрибутов
сопоставлены массивам частей. Отсутствие parts означает полностью буквальный текст.

== Комментарии и позиции после удаления строк

`ParseResult.comments: Vec<Span>` содержит диапазоны комментариев в порядке
исходника, отдельно от семантического AST. Литералы структуры ParseResult требуют поля `comments`,
`conditional_directives`, `inactive`, `include_directives` и `provenance`. WASM добавляет поле `comments` только при непустом списке,
в формате `[ { "span": { "source_id": 0, "start": 0, "end": 9 } } ]`.
Текст комментариев не копируется в JSON; токены имеют kind `comment`.

Поддержаны строки `//` в колонке 0 (кроме начинающихся с `///`), блоки из четырёх
или более `/` с закрывающим разделителем той же длины и `[comment]` для параграфа
или блока `--`. Комментарии сохраняют pending-метаданные перед следующим блоком;
метаданные `[comment]`-блока потребляются вместе с ним. В listing, literal,
verse и delimited passthrough строки комментариев являются содержимым.

Внутри обычного параграфа или principal text списка строка комментария удаляется
до inline-разбора. Текст соединяется с сохранением одного перевода строки,
а карта фрагментов возвращает диапазоны в исходные координаты. Если markup
охватывает удалённую строку, его Span охватывает и эту строку; узел после неё
получает точный диапазон исходника. Эта карта сочетается с картой включений; полная модель substitutions ещё впереди.
Незакрытый блок комментария пропускается до границы reader и даёт Warning.

Комментарии классифицирует parser; `ParseResult.tokens` отображает эти диапазоны
в физические источники вместе с остальными токенами. `tokens_with_options`
возвращает то же поле результата без повторного структурного прохода.

== Условная обработка

`ifdef::name[]` / `ifndef::name[]` открывают условную ветку, `endif::[]` или
`endif::name[]` закрывают её. Поддержана однострочная форма `ifdef::name[text]`,
а также `ifndef`. Наличие атрибута проверяется независимо от его значения;
имена регистронезависимы. `,` означает «любой», `+` — «все»; `ifndef` отрицает
результат. Смешивание операторов не вводит приоритетов. Обратный slash перед
распознанной директивой экранирует её и удаляется из семантического текста.
Синтаксис описан в link:https://docs.asciidoctor.org/asciidoc/latest/directives/ifdef-ifndef/[документации Asciidoctor];
поведение проверено по закреплённому Ruby 2.0.23.

`ifeval::[left op right]` открывает блок, который закрывается `endif::[]`.
Поддержаны `==`, `!=`, `<`, `<=`, `>` и `>=`; однострочной формы и target нет.
Операнды с `{` получают подстановку как `sub_attributes(attribute_missing: 'drop')`
Ruby (общая a-стадия, Unicode Word-имена, значения в хранимом Ruby написании,
например `a&lt;b`); неизвестные атрибуты удаляются, экранированные ссылки
остаются текстом. Строки, boolean, nil,
целые произвольной длины и float сравниваются по правилам закреплённого Ruby.
Несовместимые типы при упорядочивании дают false. Некорректная активная директива
даёт Error и не открывает блок; в пропущенной ветке она только участвует в балансе.
Сохранены особенности 2.0.23: оператор ищется до подстановки и без учёта кавычек,
а при строковом преобразовании удаляется только открывающая кавычка, поэтому
`"a" == 'a'` ложно. `{set:...}`/`{counter:...}` в операндах исполняются (левый
операнд первым) как эффекты чтения: последующие условия их видят, преобразование
начинается со снимка заголовка (до завершения заголовка эффект попадает в него).
В пропущенной ветке выражения не исполняются; подсветка их не повторяет.

Reader запрашивает строки лениво; условия используют действующие в этот момент
атрибуты, а присваивания выполняет parser. Атрибут внутри параграфа или verbatim
остаётся текстом, внутри скрытой ветки не исполняется. Условия действуют и в
verbatim-блоках. Parsed-контейнер сначала считывает всё тело: изменения атрибутов
в дочерних блоках ещё не действуют при чтении условий этого тела, но сохраняются
после его разбора. Тела комментариев верхнего уровня считываются без preprocessing;
вложенный комментарий не отменяет уже выполненную обработку контейнера.

`ParseResult.conditional_directives` содержит диапазоны директив. У включённой
однострочной формы префикс и закрывающая часть записаны отдельно, оставляя диапазон
содержимого для AST и обычной подсветки. `ParseResult.inactive` содержит диапазоны
пропущенных строк без переводов строк, включая пустые диапазоны для пустых строк.
WASM экспортирует оба поля при непустом значении в том же формате, что `comments`.
Токены имеют kind `conditional-directive` / `inactive`; синтаксис внутри скрытого
текста дополнительно не подсвечивается. Непарные, несовпадающие, незакрытые и
некорректные распознанные директивы дают Error с исходным диапазоном.

Карта фрагментов возвращает диапазоны inline-узлов и диагностик в исходные байты,
включая содержимое однострочных директив и комментарии между выбранными строками.
Диапазон многострочного узла охватывает удалённые промежутки. При переходе между
включёнными файлами составное происхождение сохраняется в `provenance`.


== Базовые включения

`parse_resource(&mut SourceMap, &ParseOptions, &dyn ResourceProvider)` разбирает
зарегистрированный `options.source_id`, раскрывая `include::target[]` по мере
чтения. `tokens_resource` принимает те же аргументы. Неизвестный основной id
возвращает `ResourceError`; ошибки включений дают Error-диагностику на директиве,
оставляют её текст в документе и позволяют продолжить разбор. Обычные строковые
API не загружают ресурсы и оставляют неэкранированный include обычным текстом.

[source,rust]
----
use adoctra::{parse_resource, MemoryResources, ParseOptions, SourceMap};

let mut resources = MemoryResources::new();
resources.insert("docs/main.adoc", "include::part.adoc[]").unwrap();
resources.insert("docs/part.adoc", "Hello *world*").unwrap();
let mut sources = SourceMap::new();
let source_id = sources.load("docs/main.adoc", None, &resources).unwrap();
let result = parse_resource(
    &mut sources,
    &ParseOptions { source_id, ..Default::default() },
    &resources,
).unwrap();
assert!(result.diagnostics.is_empty());
assert_ne!(result.document.blocks[0].span.source_id, source_id);
----

Target и параметры получают однократную подстановку обычных атрибутов текущего parser;
относительные пути разрешает provider от канонического имени включающего файла.
Включения могут поставлять header, продолжать параграф/список/markup и закрывать
контейнер, открытый в другом файле. Атрибуты и разрешение ссылок общие для всего
документа. Отдельного разбора каждого включённого документа нет.

Условия пропускают загрузку неактивных включений; экранирование `\include::…[]`
убирает slash без загрузки. Тела комментариев верхнего уровня обходят preprocessing;
parsed-контейнеры сначала считываются целиком, как и для условий. Verbatim раскрывает
include. Внутри ресурсов с расширениями `.adoc`, `.asciidoc`, `.asc`, `.ad`, `.txt`
обрабатываются вложенные директивы; другие расширения читаются без preprocessing,
по правилу закреплённого Ruby. Исходный BOM и CRLF остаются в SourceMap, reader
пропускает BOM и сохраняет соответствующие смещения. Конец включённого файла без
перевода строки отделяется от следующей строки родителя.

Основной reader и AsciiDoc-включения удаляют хвостовые ASCII-пробелы
(`space`, tab, CR, LF, VT, FF) и NUL с каждой строки, даже внутри verbatim.
Raw-включения удаляют только окончание строки. Unicode-пробелы и внутренние tab
эта стадия сохраняет. Конечные пустые строки убираются только из основного
документа: у include они могут отделять блоки от последующего содержимого.
Суффиксы удаляются через карту фрагментов; переводы строк и следующий текст
сохраняют физические позиции. SourceMap хранит исходные байты, включая пробелы.
Вне include `tabsize` и `indent` verbatim-блоков применяются после чтения, как
`build_block` Ruby (см. ниже раздел об отступах verbatim-блоков).

`lines` выбирает физические строки (нумерация с 1): `lines=2;5..8`,
`lines="2,5..8"`, `lines=5..-1` или `lines=5..`. Пересечения и повторы не
дублируют строки; порядок остаётся исходным. `lines` имеет приоритет над `tag`,
а `tag` — над `tags`, даже при пустом значении. Числовые префиксы, пустые и
обратные диапазоны следуют правилам закреплённого reader. Диапазоны хранятся
компактно, без массива на каждый запрошенный номер строки.

Список параметров использует грамматику закреплённого AttributeList: именованные
и позиционные поля, пустые поля, двойные/одинарные кавычки, экранирование кавычки
обратным slash. Незакрытая кавычка становится частью значения, после неё запятые
снова разделяют поля. После закрытой кавычки допускается следующее поле без запятой.
Разделительные пробелы — только ASCII space/tab. Имена параметров чувствительны
к регистру; позиционные поля и неизвестные имена/options reader игнорирует.
Повторное именованное поле заменяет предыдущее, кроме некавыченного `None`,
которое пропускается; пустое значение заменяет предыдущее. `encoding` передаётся
методу provider `prepare_include`, а `encoding=None` пропускается.

Обычные и intrinsic-ссылки раскрываются однократно во всём списке до разбора:
`:selection: lines="2,4",indent=0` можно использовать как `[{selection}]`.
Значения атрибутов не сканируются повторно. `\{name}` и `{name\}` оставляют
буквальную ссылку. Одинарные кавычки в include не запускают inline-подстановок.
`attribute-missing=skip` (по умолчанию) сохраняет неизвестную ссылку, `drop`
удаляет её, `drop-line` удаляет содержащую её строку списка параметров, а `warn`
сохраняет ссылку и добавляет warning на физическую include-директиву. Пустой
список после drop-line всё ещё раскрывает ресурс.

Target использует ту же однократную подстановку обычных/intrinsic-ссылок и оба
способа экранирования, но обрабатывается раньше списка параметров. `skip` сохраняет
неизвестную ссылку в пути, `drop` удаляет её. `drop-line` при удалении всего пути
из-за отсутствующего атрибута пропускает директиву до разбора параметров и вызова
provider. Для target `warn` применяет drop-line и при пустом результате даёт
warning, если нет optional; ресурс по такому пути не загружается. Пустой результат
подстановки определённого атрибута также не загружается: optional пропускает
директиву, иначе создаётся warning о пустом пути. Эти ранние решения предшествуют
проверке encoding и лимита глубины. Диапазоны предупреждений и include-токенов
остаются физическими, включая выбранные строки после indent и Unicode/BOM/CRLF.
При warning и при ошибке загрузки (кроме `InvalidEncoding`) директива
заменяется сгенерированной строкой Ruby `Unresolved directive in <путь> -
include::<цель>[<параметры>]` с происхождением в директиве (для пустой цели —
исходная цель): путь — имя файла основного документа по `document_path`
(`<stdin>` без него) или путь include относительно каталога документа, иначе
имя источника. Сгенерированный текст получает обычные подстановки и не даёт
токенов подсветки.

Цель с `{` и список параметров используют ту же подстановку, что и `ifeval`, с
исполнением `{set:}`/`{counter:}` (эффекты чтения), ровно там, где их вызывает
`preprocess_include_directive` Ruby: цель — один раз (политика зафиксирована,
warn → drop-line); при пустой цели — повторно `цель + ' '` для drop-line,
список для проверки optional и ещё раз `цель + ' '` для предупреждения warn;
иначе список — только после ссылки secure mode, проверки provider и глубины.
Информационные сообщения drop-line подстановок директивы не выводятся,
предупреждения — выводятся.

`tag=name` / `tags=a;b` выбирают регионы между `tag::name[]` и `end::name[]`.
Поддержаны вложенные/повторные регионы, `!name`, `*`, `**` и их сочетания;
порядок фильтров значим (`a;!*` отличается от `!*;a`). Маркер может быть внутри
комментария языка ресурса; при фильтрации тегов вся строка маркера удаляется.
Выбор предшествует условиям и вложенным include, включая raw-ресурсы. Несмежные
выбранные строки одного источника сохраняются отдельными provenance-фрагментами.
Исключённые строки и маркеры тегов не получают токенов в проекции этого документа;
полный физический буфер доступен через SourceMap. Предупреждения о неверных и
незакрытых тегах указывают на физические строки маркеров, а о ненайденных
положительных тегах — на включающую директиву. Результат остаётся частичным.

`opts=optional` / `options=optional` (также `optional-option=`) пропускает
отсутствующий ресурс без диагностики и без текста директивы. Пустой раскрытый
target пропускается без вызова provider. `AccessDenied`, `InvalidEncoding`,
`InvalidTarget`, `Io`, циклы и превышения лимитов продолжают давать диагностику.
Диапазон пропущенной директивы остаётся в `include_directives` и в подсветке.
Несколько opts/options объединяют флаги. В значении с запятыми удаляются все
ASCII space, но не tab; без запятой пробелы внутри кавычек сохраняются.
Поэтому `opts="other, op tional"` включает optional, а `opts=" optional "` — нет.

`leveloffset=+1` / `leveloffset=-1` меняет текущий уровень относительно предыдущего;
значение без знака задаёт абсолютное смещение. То же правило действует для
`:leveloffset:`, `:leveloffset!:` удаляет смещение. Внешние locked-атрибуты сохраняют
приоритет. Include временно обрамляет выбранный непустой поток объявлением
смещения, пустыми строками и восстановлением значения при раскрытии, как Ruby.
Это часть потока parser: внутри verbatim служебные строки остаются буквальным
текстом, а при capture контейнеров действуют правила read-ahead. Пустой выбранный
поток не меняет контекст. Уровень doctitle определяется до следующих header-атрибутов.

Служебные строки не изменяют SourceMap и не создают токенов. Диапазоны AST используют
физические фрагменты; узел, состоящий только из служебного текста, привязывается к
include-директиве. Отрицательные уровни ограничиваются нулём; положительные выше 255
ограничиваются с warning из-за текущего типа `Heading.level: u8`. Числовые префиксы
и относительные значения обрабатываются с насыщением i128, без panic на огромных
числах; точная арифметика за пределами i128 не обещается. HTML ограничивает тег до h6.

`indent=0` удаляет минимальный общий отступ непустых выбранных строк;
положительное значение затем добавляет заданное число пробелов. Отрицательное
значение сохраняет отступ. При положительном `tabsize` табуляция раскрывается
до этой операции, в том числе при отрицательном indent; позиции табуляции считаются
по Unicode-символам. Без положительного tabsize табуляция остаётся одним символом.
AsciiDoc-ресурсы при этой операции предварительно теряют хвостовые пробелы;
raw-ресурсы сохраняют их. Выбор lines/tag(s) предшествует indent, а условия,
вложенные include и служебные объявления leveloffset обрабатываются после него.
Источник остаётся неизменным. Удалённый отступ и добавленные пробелы не получают
токенов; раскрытый tab отображается на исходный символ целиком, обычный текст —
побайтово. Разрывы физических диапазонов сохраняются в provenance.

`depth=N` разрешает N дополнительных уровней include внутри выбранного файла.
Сам файл загружается и при `depth=0`, но его вложенные директивы дают диагностику
без вызова provider. Нулевые, отрицательные и нечисловые значения запрещают
дальнейшее раскрытие. Без depth наследуется предел родителя; явное значение
дочернего include может изменить его, но не превысить абсолютный предел.
Абсолютный предел — атрибут API `max-include-depth` (как `to_i` Ruby, по умолчанию
64), ограниченный `IncludeLimits.max_depth`; неположительное значение отключает
include, директивы остаются текстом. Атрибут читается при создании reader, запись
в header его не меняет. Диагностика: `maximum include depth of N exceeded`, где N —
относительный предел текущего файла.
При возврате из файла действует прежний предел родителя. Числа с суффиксами
используют тот же числовой префикс, что и остальные параметры reader.

`ParseOptions.includes: IncludeLimits` ограничивает глубину (по умолчанию 64) и
суммарный объём загруженного содержимого включений (16 MiB, каждое повторное
включение учитывается заново, до выбора строк/тегов). Дополнительно учитывается
рост каждой строки при раскрытии табуляции и добавлении отступа, включая
промежуточное расширение перед удалением общего отступа. Размеры проверяются
до выделения памяти; превышение оставляет исходную директиву с диагностикой.
Основной файл в объём не входит. Проверяются циклы
по каноническим именам активных источников. Эти ограничения относятся к раскрытию;
ограничения размера ответа и стоимости I/O принадлежат provider.

`ParseResult.include_directives` и WASM `include_directives` сохраняют исходные
диапазоны распознанных активных директив. Токен имеет kind `include-directive`.
WASM добавляет `provenance` в диапазон только для составного происхождения и
экспортирует таблицу `provenance` как массив массивов обычных диапазонов. Токены
разделяются на физические фрагменты, сортируются по source_id/start/end; точные
повторы удаляются. Таблица provenance для токенов не нужна. Существующее ограничение
построчного inline-highlighting, включая многострочное форматирование, сохраняется.

CLI раскрывает включения файлового ввода через существующий rooted adapter;
stdin использует строковый API без provider. `encoding` выбирает декодирование
ресурса; неизвестные имена параметров игнорируются. Safe mode, URI-включения
(с `allow-uri-read`) и строка `Unresolved directive` для ошибок загрузки и пустого
target реализованы (см. выше и «Атрибуты»). Это базовый профиль включений,
а не полная совместимость.

== Каталог inline-якорей

Как в закреплённом Ruby, в реестр ссылок попадают только якоря, каталогизированные
при чтении: в обычных абзацах (включая абзац с меткой `NOTE:` и абзацы внутри
контейнеров) и в начале пункта списка. Абзацы со стилями `[NOTE]`, `[quote]`,
`[example]`, `[sidebar]`, `[verse]`, `[pass]` и т. п., хвостовые якоря пунктов
списка, названия и другие поля по-прежнему выводят `<a id>`, но `<<id>>` на них
не разрешается. Поиск повторяет `InlineAnchorScanRx`: экранированные `\[[`/`\anchor:`,
`[[[` и якорь сразу после предыдущего не учитываются; экранированные якоря
выводятся текстом без обратной косой.

Reftext каталога проходит раннюю a-стадию с состоянием чтения (эффекты не
воспроизводятся); каждая ссылка форматирует его c/q/r заново. Пустой результат
ранней стадии у `[[id,…]]` исключает якорь, у `anchor:` оставляет его без текста.
`\]` в `anchor:` снимается. Узлы reftext сохраняют физические диапазоны и origin
через include. Предупреждения о пропущенных атрибутах выдаются и каталогом, и
преобразованием абзаца, как в Ruby.

Отображение якоря от каталога не зависит: как `InlineAnchorRx` в `sub_macros`,
якорь распознаётся m-стадией после ссылок и email, по лексическому результату
quotes, attributes и replacements. Раскрытое значение может создать якорь
(`[[{id}]]`) или разрушить его (`[[a,]]` после drop остаётся текстом), а ленивый
reftext может захватить текст из значения. Поглощённые quote-границы не
восстанавливаются. Якорь, начатый в исходном тексте, остаётся узлом
`Inline::Anchor { id, span }` с физическим диапазоном всей конструкции; поглощённые
AttributeRef остаются пустыми узлами после него. Поле reftext у узла удалено:
подпись ссылки берётся только из каталога. Якорь, целиком созданный значением
атрибута, хранится как `AttributePart::Anchor(id)` в частях ссылки или
Substituted: HTML выводит `<a id>`, JSON/WASM — часть `kind:"anchor"` с `id`.
Заимствованные подписи xref удаляют такие части вместе с тегами ссылок
(`DropAnchorRx`). Та же стадия работает в `pass:m` и в повторном проходе параметров
ссылок. Экранированный якорь теряет обратную косую; оставшийся текст сохраняет
собственные байты. Подсветка даёт токен `anchor` по сообщённому диапазону и
сохраняет токены исходной разметки reftext.

== Разрешение ссылок

Xref распознаются последними в m-стадии обычного inline-текста, после ссылок, email
и inline-якорей, как `InlineXrefMacroRx` в `sub_macros`: по лексическому результату
quotes, attributes и replacements. Поэтому `<<{id}>>` берёт раскрытый ID, а значение
атрибута может открыть, закрыть или целиком создать ссылку. Refid начинается со
словесного символа или одного из `#/.:{` и лениво продолжается (в том числе через
строки) до первого `>>` или до `[` макроса; подпись макроса заканчивается первой
неэкранированной `]`, а `\]` в ней снимается. Угловая форма делит refid по первой
запятой и удаляет пробелы слева от подписи; пустая подпись делает ссылку
textless. Подпись макроса с `=` (вне compat-mode) разбирается как AttributeList
(`extract_attributes_from_text`): первый позиционный атрибут — подпись (одинарные
кавычки повторяют подстановки), `role` — класс; только именованные атрибуты
оставляют ссылку textless. Вне compat-mode ведущий `#` отделяется (`<<#id>>`).
Экранированная ссылка теряет обратную косую.

Цель ссылки вычисляется в той же стадии, как в Ruby, и хранится в `Xref`
(`target` — href, `refid`, `path`, `fragment`, `role`, `window`, `rel`). Вне
compat-mode первый `#`, перед которым нет `&`, делит refid на путь и фрагмент.
Угловая форма отбрасывает AsciiDoc-расширение (`.adoc`, `.asciidoc`, `.asc`, `.ad`,
`.txt`) и считает любой путь исходным документом; макрос — только `.adoc` или путь
без расширения, а `xref:file.pdf[]` без `#` остаётся путём к файлу. Исходный документ,
совпадающий с `docname` или включённый целиком, даёт `#fragment` (или `#` без
фрагмента, `refid: None`); иначе `path` = `relfileprefix` + путь + `relfilesuffix`
(по умолчанию `outfilesuffix`, закреплённый по завершении header; встроенное
значение задаёт backend: `.html` для `html5`), а `refid` — `путь#фрагмент`. Каталог include (`Reader`) хранит
AsciiDoc-файлы относительно каталога документа без расширения; выбор строк или тегов
(кроме `tags=**`) делает включение частичным, невидимым для ссылок, пустой выбор
не регистрируется. Пути нужны от `ResourceProvider::document_path`; без него
каталог пуст. Заголовки, преобразуемые при чтении, видят только прочитанные include.
`window`/`opts=nofollow`/`noopener` дают `window`/`rel` только междокументной ссылке.

Голый ID вне compat-mode, неизвестный реестру и похожий на текст (пробел или
заглавная буква), ищется как естественная ссылка (`Document#resolve_id`): первый
в порядке регистрации узел, чья подпись (непустой reftext, иначе название; в
лексическом написании с тегами форматирования) совпадает с лексическим refid.
При преобразовании таблица строится один раз (с побочными эффектами подписей);
заголовки при чтении ищут без кэша среди уже зарегистрированных ID. `#id`,
compat-mode и найденные ID не ищутся. Textless-подпись междокументной ссылки —
`path`; ссылки на текущий документ — его reftext, название документа или первого
раздела верхнего уровня, иначе `[^top]`. Предупреждение о неизвестной ссылке
выдаётся только для внутренних ID. Атрибут `title` как название документа и
декодирование символьных ссылок (`&#38;`) в полях узла не реализованы.

`xrefstyle` берётся из списка атрибутов макроса (`Xref.xrefstyle`), иначе из
атрибута документа в месте ссылки, и применяется к названию после reftext, как
`AbstractBlock#xreftext`/`Section#xreftext` (`resolve::styled`). Пример с
названием и непустой подписью: `full` — `<example-caption> N, “название”`,
`short` — `<example-caption> N`; без номера (собственный `caption`) или без
префикса — подпись без завершающей `. `; другие значения — название. Номер
сохраняется при назначении подписи. Раздел — как `Section#xreftext`: у
нумерованного `full` даёт `<sectname>-refsig N.M, “название”` (у глав и
приложений название выделено `Inline::Emphasis`), `short` — `<sectname>-refsig
N.M`; без refsig остаётся номер; иначе ненумерованные главы выделяются при любом
стиле. Сгенерированный текст несёт диапазон ссылки, заимствованное название —
свои диапазоны. Естественный поиск и подпись текущего документа стиль не используют.

Нумерация разделов (`sectnums`, алиас `numbered`, `section_numbers.rs`) следует
Ruby: решение принимается при чтении заголовка с атрибутами в этот момент
(`initialize_section`: `sectname` part/chapter/section или стиль специального
раздела; специальные разделы — только при `sectnums=all`, в книге уровня 1 как
главы; части — при `partnums`), номера назначаются иерархией разделов
(`assign_numeral`: порядковый номер среди нумерованных соседей, римский у частей).
Глава при закрытии во время чтения (перед названием следующего раздела) берёт
следующее значение счётчика-атрибута `chapter-number`; это видят последующее
чтение, но не преобразование, начинающееся с атрибутов header. Префикс
заголовка — `Block.caption` заголовка (`1.2. `, `<chapter-signifier> 3. `,
`<part-signifier> II: `), вычисляемый при преобразовании с `sectnumlevels` и
signifier в месте раздела. Встроенные `*-refsig` и `appendix-caption` заданы как
у Ruby.

Все слова подписей — атрибуты документа, поэтому их можно локализовать:
`:appendix-caption: Приложение` даёт `Приложение A: `, `:appendix-refsig:`,
`:chapter-refsig:`, `:section-refsig:`, `:part-refsig:` задают слова в подписях
ссылок, `:chapter-signifier:`/`:part-signifier:` — в заголовках книги.
Удалённый атрибут убирает слово (у приложения остаётся `A. `).

Специальные разделы — любой стиль раздела, кроме `sectN` (в книге `[abstract]`
вместо этого — глава уровня 1): уровень 0 становится 1 (уровень заголовка тоже),
а вложенность, предупреждения о порядке и ошибка уровня 0 вне книги определяются
уровнем строки заголовка. Признак специального раздела наследуется вложенными
разделами (их нумерация — только при нумерованном родителе); специальные разделы
уровня 1, кроме appendix/preface/abstract, не допускают вложенных разделов
(ошибка `<sectname> sections do not support nested sections`). Приложение
нумеруется всегда: при закрытии во время чтения оно берёт счётчик
`appendix-number` (с `A`) и подпись из `appendix-caption` в этот момент, которая
выводится независимо от `sectnumlevels`; вложенные разделы продолжают `A.1.`.
Подписи, вычисляемые при чтении (заголовки, ссылки из определений атрибутов),
видят номера только уже закрытых разделов. В документе `manpage` (кроме
вложенных) раздел без стиля с исходным названием `SYNOPSIS` (без учёта регистра
ASCII) — специальный раздел `synopsis` без смены уровня, как в Ruby.

Partintro книги повторяет `next_section` Ruby: первый блок содержимого части
(раздела уровня 0 книги) оборачивается в `BlockKind::Open` со стилем `partintro`
и диапазоном обёрнутого содержимого, следующие блоки до первой главы попадают в
него. Open-блок без стиля или `[open]` сам получает стиль `partintro`; абзац
`[open]` при втором блоке становится обычным абзацем внутри контейнера (id, роли,
название и атрибуты переходят на абзац). `[partintro]`-блок и `--` остаются
partintro, следующий блок идёт в часть с error `illegal block content outside of
partintro block`. Часть без раздела в конце даёт error `invalid part, must have at
least one section (e.g., chapter, appendix, etc.)` на её заголовке. Стили
`[abstract]`/`[partintro]` на абзаце дают open-блок с этим стилем. После
построения иерархии ядро сообщает о блоках, которые HTML-конвертер Ruby
исключает: partintro не как дочерний блок части книги (error) и abstract прямо
в документе книги (warning); HTML их не выводит. Книга без header открывает
preamble, если её первый блок не abstract, и сохраняет его без разделов.
`preface-title` из header становится `Block.title` preamble книги — текстом
исходного значения без подстановок с пустым диапазоном в начале preamble (HTML,
как Ruby, его не выводит; JSON/WASM экспортируют `title` у `preamble`).

TOC. Встроенные атрибуты включают `toc-placement=auto` и `toc-title=Table of
Contents`. При завершении header, как `save_attributes` Ruby, значение `toc` (или
`toc2`, который удаляется и означает `left`) задаёт размещение: `toc` становится
пустым, `toc-placement` — `auto`, а `toc-position` — `left`/`right`/`top`/`bottom`
(также `<`, `>`, `^`, `v`, с `toc-class=toc2`, если класс не задан) или `content` с
`toc-placement=preamble`/`macro`; неизвестное значение удаляет `toc-position`.
Явный `toc-position` (при `toc-placement=auto`) или иной `toc-placement` важнее
значения `toc`; удалённый `toc-placement` означает `macro`. Производные значения
обходят блокировки host-атрибутов; записи в теле не нормализуются.
`BlockKind::Toc` — блочный макрос `toc::[…]` в начале блока (`^toc::\[(.+)?\]$`,
любой стиль, внутри абзаца — текст). Список в скобках разбирается грамматикой
AttributeList без подстановок: `id`, `role` и `title` заменяют метаданные блока
(название затем преобразуется как обычное), остальные именованные поля
(например, `levels`) добавляются в `Block.attrs.named`, позиционные игнорируются.
JSON/WASM используют `name:"toc"`, подсветка — `block-macro`. Сам TOC строит
backend по разделам документа: HTML выводит `<nav id="toc">` после названия
(размещение не `macro`/`preamble`), в конце preamble (`preamble`, класс из
`toc-class`) или на месте макроса (`macro`, атрибуты в его месте; иначе
`<!-- toc disabled -->`), только если в документе есть разделы и задан `toc`
(атрибуты header). Пункты — подпись номера заголовка и его inline-узлы без тегов
`<a>`, вложенность — пока уровень раздела меньше `toclevels` (или `levels`
макроса), как `String#to_i` Ruby.

Изображения. `BlockKind::Image { target, src, alt }` — блочный макрос
`image::target[…]` в начале блока (`^image::(\S|\S.*?\S)\[(.+)?\]$`; внутри
абзаца — текст; стиль literal/listing/source/verse оставляет строку verbatim-абзацем,
как и для `toc::[]`). Список в скобках получает раннюю a-стадию строки атрибутов
(с побочными эффектами и политиками отсутствующих атрибутов) без подстановок
значений в одинарных кавычках и без shorthand; позиционные поля также называются
`alt`, `width`, `height` (в порядке полей). `id`, `role`, `title`, `reftext` и
`options` разделяют ключи с метаданными блока, остальные поля попадают в
`Block.attrs.named`. Затем атрибуты подставляются в цель; если `drop-line`
опустошил её, блок и его метаданные отбрасываются. Стиль блока удаляется: без
явного `alt` он становится текстом alt, иначе alt — имя файла без расширения с
пробелами вместо `_`/`-`. Не по умолчанию alt получает replacements (созданные
entity — `AttributePart::Raw`). `scaledwidth` без единиц получает `%`. `src` —
web-путь цели относительно `imagesdir` в месте блока при преобразовании (URI
сохраняются, пробелы — `%20`, `.`/`..` разрешаются), как `image_uri` Ruby в режиме
secure. Изображение с названием нумеруется `figure-caption` (по умолчанию `Figure`,
счётчик `figure-number`), подпись в `Block.caption`; xrefstyle использует тот же
префикс. JSON/WASM экспортируют `name:"image"`, `target`, `src` и плоский `alt`,
подсветка — `block-macro`.

Inline-изображения. `Inline::Image { image, span }` — макрос `image:target[…]`
или `icon:name[…]` (`InlineImageMacroRx`), распознанный стадией макросов перед
ссылками над лексическим результатом quotes, атрибутов и replacements (также в
`pass:m` и повторных проходах параметров ссылок); `\image:` теряет обратную
косую черту. Изображение, целиком созданное значением атрибута, остаётся
`AttributePart::Image` его ссылки. `InlineImage` хранит лексические `target`,
`src`, `attributes` (как Ruby, вставляющий их как есть), `options` и части
`alt` (границы форматирования и Raw сохраняются; по умолчанию — имя файла без
расширения). Список получает `normalize_text` (strip, перевод строки — пробел,
`\]`) и AttributeList без подстановок значений; позиционные — alt/width/height
(у иконки size). `src` — web-путь цели относительно `imagesdir` в месте
макроса; иконка хранит режим `icons`: без него — текст `[alt]`, `font` — глиф,
иначе `src` по `iconsdir` (по умолчанию `./images/icons`) и `icontype`
(нормализуется при завершении header). JSON/WASM — `name:"image"` и
`kind:"image"` в parts, подсветка — `inline-macro`.

Видео и аудио. `BlockKind::Video { target, src, poster, embedded }` и
`BlockKind::Audio { target, src }` — блочные макросы `video::`/`audio::` той же
грамматики (`BlockMediaMacroRx`) и с тем же чтением списка, цели, drop-line и
метаданных. Позиционные поля видео называются `poster`, `width`, `height`, у аудио
имён нет; стиль блока удаляется. Названия не нумеруются. Источники вычисляются в
ядре при преобразовании, как `convert_video`/`convert_audio` Ruby: `poster`
`youtube`/`vimeo` даёт `embedded` URL плеера (`asset-uri-scheme`, по умолчанию
`https`; список/playlist или hash из цели и атрибутов, `start`/`end`/`theme`/`lang`
и опции; разделители — буквальный `&`), иначе `src` — web-путь цели относительно
`imagesdir` с якорем `#t=start,end`, а непустой `poster` разрешается так же.
JSON/WASM экспортируют `name:"video"` (`target`, `src`, `poster`, `embedded`) и
`name:"audio"` (`target`, `src`), подсветка — `block-macro`. HTML выводит
`<figure class="videoblock|audioblock">` с ведущим `<figcaption class="title">` и
`<iframe>`/`<video>`/`<audio>` с текстом Ruby для браузеров без поддержки.

Таблицы. `BlockKind::Table(Box<Table>)` — блок `|===`, `,===`, `:===` или `!===`
(более длинная серия `=` закрывается той же строкой; любой стиль оставляет
таблицу). Строки до закрывающей строки читаются без строковых комментариев `//`
и разбираются как `parse_table` Ruby: формат из `format` или символа ограничителя
(`,` — csv, `:` — dsv; `tsv` — csv с табуляцией), `separator`, спецификации ячеек
psv (`2.3+`, `3*`, выравнивания `<^>` и `.<.^.>`, стили `d s e m h l a`),
неявный заголовок, `%header`, `%noheader`, `%footer`. `Table.columns` —
`TableColumn { halign, valign, style, width, autowidth }`, где `width` —
`colpcwidth` в записи числа Ruby (`33.3333`, `50.0001`, `50.0`); `head`, `body`,
`foot` — строки `TableCell { content, style, halign, valign, colspan, rowspan,
background, span }`. Диапазон ячейки — от её спецификации или разделителя до
конца обрезанного текста. `CellContent::Paragraphs` содержит inline-узлы с
обычными подстановками (ячейки тела делятся на абзацы по пустым строкам, ячейка
заголовка — один фрагмент); `CellContent::Literal` — текст `l`-ячейки. Ячейка `a` —
`CellContent::Blocks`: блоки вложенного документа, прочитанного при создании
ячейки (порядок Ruby) с собственным header и телом; диапазоны указывают в
исходный текст. Он начинает с атрибутов чтения родителя (без `doctitle`,
`notitle`, `showtitle`, `toc`, `toc-position`), унаследованные атрибуты
заблокированы (кроме `compat-mode`, `doctype`, `toc-placement`), каталоги ссылок
общие, счётчики изменяют корневой документ. Записи атрибутов ячейки действуют
только внутри неё. Во вложенном документе psv-таблицы используют разделитель
`!`. Первая строка ячейки, содержащая `::`, предобрабатывается повторно, как в Ruby
(`a|include::…[]`, однострочные условия) с собственным стеком условий и атрибутами
чтения родителя; диапазоны включённого текста указывают в его файл. `Table.width` — `tablepcwidth`;
`frame`, `grid`, `stripes` и `background` ячеек вычисляются при преобразовании
(атрибуты `table-frame`/`table-grid`/`table-stripes` и `cellbgcolor` документа).
Название нумеруется `table-caption` (счётчик `table-number`). Диагностики
повторяют сообщения Ruby. JSON/WASM экспортируют `name:"table"` с `width`,
`frame`, `grid`, `stripes`, `columns`, `head`, `body`, `foot` (ячейки с
`paragraphs`, `blocks` или `literal`; WASM — с диапазонами), подсветка — `table-delimiter`
для ограничителей и `cell-separator` для разделителей со спецификациями.

Списки. `BlockKind::List { ordered, items }` и `BlockKind::DescriptionList {
items }` разбираются как `parse_list`/`parse_description_list` Ruby: строки пункта
собираются до соседнего пункта (`read_lines_for_list_item`: пустые строки,
продолжения `+`, отложенные продолжения, вложенные списки с другим маркером,
литеральные абзацы, жадный термин без описания) и разбираются как блоки пункта;
абзац сразу после строки маркера сворачивается в текст пункта. Маркеру может
предшествовать отступ. `ListItem { inlines, blocks, span, checkbox, marker }`:
`marker` — маркер (`*`, `-`) или первый маркер нумерованной серии (`.`, `1.`, `a.`,
`i)`); `checkbox` — состояние пункта чек-листа (список получает опцию
`checklist`). Нумерованный список получает неявный стиль Ruby в
`BlockAttrs::style` (`arabic`, `loweralpha`, …); несоответствие номеров даёт
предупреждение `list item index: expected …, got …`. Элемент списка определений —
`DescriptionListItem { terms: Vec<ListTerm>, description: Option<ListItem>, span
}`: термины без описания объединяются со следующим, ведущий якорь термина
получает остаток термина как reftext. Строка списка не прерывает абзац; простой
абзац завершается ограничителем блока или строкой атрибутов. Абзац с отступом без
стиля — литеральный блок с удалённым общим отступом. JSON/WASM экспортируют
`name:"dlist"` с `terms` и `description` (WASM — с диапазонами) и `checkbox` у
пунктов; подсветка — `list-marker` для маркеров и разделителей терминов.

Callouts. `BlockKind::Listing` и `BlockKind::Literal` содержат `callouts:
Vec<Callout>` — метки в конце строк, как `sub_callouts` Ruby: `start`/`end` —
байтовый диапазон в `text` от префикса-комментария (`guard`: `// `, `# `, `-- `,
`;; ` или `line-comment`) до метки, `number` (для `<.>` — номер по порядку в
блоке), `xml` для `<!--N-->`, `id` Ruby (`CO1-2`) и `span` метки в источнике.
Экранированная метка теряет обратную косую черту и остаётся текстом.
`BlockKind::CalloutList { items }` — список `<1> текст` (`CalloutListItem { item,
coids }`, где `coids` — метки текущего списка каталога с этим номером);
предупреждения `callout list item index: expected …, got …` и `no callout found
for <N>`. JSON/WASM экспортируют `callouts` (если есть) и `name:"colist"` с
`coids`. Каждая запись `callouts` содержит `text_range: {start, end}` —
полуоткрытый UTF-8 диапазон в нормализованном `text`, включая guard и метку.
Он учитывает снятие экранирования и нормализацию CRLF; физический `span`
WASM остаётся диапазоном исходника. Подсветка — `callout` для меток и `list-marker` для номеров списка.

Макросы интерфейса. При заданном атрибуте `experimental` (в точке подстановки)
первая стадия макросов, как в Ruby, распознаёт `kbd:[…]`/`btn:[…]`
(`InlineKbdBtnMacroRx`), затем `menu:имя[…]` (`InlineMenuMacroRx`), затем
сокращение `"File > Save"` (`InlineMenuRx`) по лексическому результату
предыдущих стадий. Макрос из исходного текста — `Inline::Ui { ui, span }` с
диапазоном макроса, созданный значением атрибута — `AttributePart::Ui`.
`UiMacro::Keyboard { keys }` — клавиши, разделённые первым `,` или `+` после
первого символа (завершающий разделитель — сам последняя клавиша);
`UiMacro::Button { label }` — текст с нормализованными пробелами;
`UiMacro::Menu { menu, submenus, item, font }` — меню, подменю и пункт (`None`
у `menu:Имя[]`), `font` — `icons=font` в точке макроса (выбирает каретку).
Каждая надпись — лексические части с семантическими границами (форматирование,
raw-сущности). Последующие стадии макросов видят разметку Ruby вокруг надписей и
вкладывают найденное (ссылки, xref, изображения, сноски) в надпись: узел
собирается заново при выходе из лексического текста. В отличие от Ruby,
содержимое с вложенным макросом длится до скобки, закрывающей этот макрос
(`btn:[link:x[y]]`; литеральная скобка `kbd:[[]` по-прежнему заканчивается
первой `]`), а разделители `,`/`+`/`>` внутри вложенного макроса или `<<…>>` не
делят клавиши и пункты меню, поэтому HTML остаётся корректно вложенным там, где у
Ruby теги перепутаны. Граница, пересекающая разметку макроса, делится:
форматирование, открытое внутри надписи, закрывается в её конце и открывается
снова в следующей надписи или после макроса, открытое до макроса — закрывается
перед ним и открывается в начале надписей. Ссылка, открытая до макроса и
закрытая внутри надписи, оставляет разметку Ruby как есть. JSON/WASM экспортируют
`name:"kbd"` (`keys`), `"button"` (`parts`) и `"menu"` (`menu`, `submenus`,
`item`, `font`); части — `kind` с тем же значением; подсветка — `inline-macro`.
HTML выводит `<kbd>`, `<span class="keyseq">`, `<b class="button">` и
`<span class="menuseq">`/`<b class="menuref">` Ruby.

Сноски. Макрос сноски распознаётся последней стадией макросов (после xref), как
`InlineFootnoteMacroRx` Ruby. Сноска из исходного текста — `Inline::Footnote {
footnote, span }` с диапазоном макроса, созданная значением атрибута —
`AttributePart::Footnote`. `Footnote { kind, index, id, content }`: `kind` —
`Definition` (`footnote:[текст]`, `footnote:id[текст]`), `Reference`
(`footnote:id[]` или повторный id) или `Unresolved` (неизвестный id без текста,
предупреждение `invalid footnote reference`); `index` — значение счётчика
`footnote-number` при преобразовании (у ссылки — индекс определения); `content` —
текст определения после предыдущих подстановок как лексические части с
семантическими границами. `Document.footnotes` — зарегистрированные определения
(`FootnoteDefinition { index, id, content, span }`) в порядке регистрации,
включая определения из неиспользованных или удалённых атрибутов. Для них span
указывает на объявление атрибута; passthrough и xref завершены без повторных
эффектов счётчиков. Видимые узлы определяют принадлежность сноски документу,
в том числе при ленивом вычислении внешнего заголовка из ячейки.

AsciiDoc-ячейка хранит свой список в `CellContent::Blocks { footnotes }`, нумерация
общая с корневым документом. JSON/WASM экспортируют `name:"footnote"` (части —
`kind:"footnote"`) с `type`, `index`, `id`, `parts` и список `footnotes` документа и
ячейки (WASM — с диапазонами); подсветка — `inline-macro`. HTML выводит маркеры и
список `<div id="footnotes">` Ruby, если не задан `nofootnotes`.

Ссылка, начатая в исходном тексте, — узел `Inline::CrossReference { xref,
children, span }` с физическим диапазоном всей конструкции (поля `xref`
декодированы); поглощённые AttributeRef
остаются пустыми узлами после него. Поглощённая подпись хранит текст (Text/Raw) или,
при семантических границах, один `Inline::Substituted` с диапазоном подписи;
форматирование подписи хранится в его parts. Quote, пересекающий закрывающие
скобки, как в Ruby, оставляет непарную границу. Ссылка, целиком созданная значением
атрибута, хранится парой `AttributePart::OpenXref(Xref)` / `CloseXref`
в частях ссылки или Substituted (лексические значения с защитой, как у полей
ссылок); HTML выводит `<a href>` с `class`/`target`/`rel`, JSON/WASM — части
`kind:"open-xref"` (с `target` и необязательными `refid`, `path`, `fragment`,
`role`, `window`, `rel`) и `kind:"close-xref"`. Узел JSON `name:"xref"` содержит
`target` (href), `refid`, `path` и `role`; WASM добавляет `fragment`, `window`
и `rel`. Подпись такой textless-пары
вставляется частями при преобразовании (или при чтении для заголовков), плоское
`value` обновляется. Подсветка даёт токен `xref` по сообщённому диапазону и сохраняет
токены поглощённой исходной разметки.

После чтения `resolve::register` строит реестр: автоматические ID заголовков,
ID блоков и каталог inline-якорей в порядке источника; дубликат предупреждает,
побеждает первый. Подписи textless-ссылок вычисляются при преобразовании
(`body_subs.rs`) в порядке документа, после подстановок поля, как `xreftext`
Ruby: непустой reftext, отформатированный c/q/r с текущими
атрибутами и счётчиками (эффекты сохраняются, предупреждения выдаются при каждом
обращении); иначе название блока или раздела; иначе `[id]`. Неизвестный ID
предупреждает на физическом диапазоне ссылки и тоже выводит `[id]`.

Отложенное название блока конвертируется один раз: первой ссылкой (с состоянием
в месте ссылки, без replay) или самим блоком; результат используется обоими.
Ссылки внутри вычисляемой подписи выводят `[id]`; ссылка из названия на сам блок
вычисляет его повторно, как memo Ruby. Заимствованная подпись удаляет якоря и
теги ссылок (Link/CrossReference разворачиваются в текст), сохраняя форматирование
и spans источника. Заголовок с автоматическим ID и название с явным ID и `{`
разрешают ссылки при чтении: незарегистрированный ID (вперёд или на себя) даёт
`[id]`, ранний — reftext (атрибуты чтения, без исполнения) или название;
отложенное название тогда конвертируется при чтении. Автоматический ID строится
из этого результата. Регистрация контейнеров после их содержимого не перенесена.

== Inline-формулы

`Inline::Stem { stem, span }` хранит формулу из исходника; в значении атрибута
или вложенном результате это `AttributePart::Stem(Box<Stem>)`.
`Stem { style, parts }` содержит нотацию `StemStyle::AsciiMath` /
`StemStyle::LatexMath` и семантические части после выбранных подстановок.
JSON/WASM: `name:"stem"` (часть — `kind:"stem"`),
`style:"asciimath"` / `"latexmath"`, `parts`; WASM добавляет исходный `span`.

Макросы извлекаются после обычных passthrough до quotes/attributes и
восстанавливаются после внешних substitutions. Generic `stem:` выбирает
нотацию по действующему `stem` при извлечении, до выполнения внутреннего
`a`-прохода. По умолчанию работает specialcharacters; список после двоеточия
выбирает тот же pipeline, что `pass:`. Непустое содержимое, `\]`, снятие
`$…$` LaTeX, `pass:m` и повторные проходы совпадают с Ruby. Незакрытый макрос
остаётся текстом. В ошибочном `latexmath:[$]`, на котором Ruby выбрасывает
исключение, сохраняется пустая формула без panic.

Подсветка использует `inline-macro` по диапазону всей конструкции, включая
Unicode/CRLF и многострочные формулы; защищённые quotes/attributes внутри
не создают токенов. Внешний pass сохраняет свой токен. HTML выводит разделители
`\$…\$` / `\(…\)` и содержимое с выбранными substitutions. Подключение
MathJax и блочные формулы описаны ниже.

== Заголовки и метки admonition

`Document.has_title` показывает, что `blocks[0]` — название документа (исходное
`= Title` или атрибут `doctitle` без него). Остальные заголовки, включая discrete
(`[discrete]`/`[float]`) и заголовки уровня 0 в теле, получают автоматические id.
HTML выводит discrete-заголовок с классом из стиля и ролей, а заголовок уровня 0
вне названия — с классом `sect0`. Хвостовой ` [[id]]`/` [[id, reftext]]` у названия
раздела, discrete-заголовка или документа удаляется из названия и задаёт id, если
id не пришёл из метаданных; его reftext без a-стадии получает c/q/r и заменяет
отложенный reftext (у названия документа reftext игнорируется). Заимствованное
название в ссылке теряет inline-якоря.

`BlockKind::Admonition.label` — части `textlabel` Ruby: `caption=` блока как Raw
(HTML выводит без экранирования), иначе части атрибута документа `<kind>-caption`
на момент чтения. Встроенные значения `note-caption`…`caution-caption` есть в
`Document.attributes`; снятый атрибут даёт пустую метку. JSON/WASM экспортируют
`label` как текст.

`icons` и `src` — значок, как `convert_admonition` Ruby: режим `icons`
документа в месте преобразования блока (`None` — текстовая метка, `font` —
глиф шрифта, если у блока нет атрибута `icon`, иначе изображение) и
`icon_uri` изображения: `icon` блока (с `icontype`, если нет расширения) или
имя admonition с `icontype` под `iconsdir` документа (`iconsdir` блока не
действует). HTML выводит в `p.admonition-title` `<i class="fa icon-<имя>">`
или `<img>` с меткой в `title`/`alt`, содержимое — в `div.admonition-content`;
JSON/WASM экспортируют `icons` и `src`.


== Блочные формулы и состояние после conversion

`BlockKind::Stem { style: StemStyle, inlines: Vec<Inline> }` представляет
формулы в `++++` со стилем `stem`, `asciimath` или `latexmath`. Generic `stem`
выбирает нотацию по второму позиционному параметру или действующему атрибуту
`stem` при чтении. Отсутствующее значение использует атрибут документа,
явное `""` выбирает AsciiMath. На абзаце, listing или open эти стили не
создают формулу.

`inlines` сохраняет результат выбранных подстановок как нейтральные части
`Inline::Substituted`; его диапазон охватывает исходное содержимое блока,
а `Block.span` включает ограждения. JSON/WASM экспортируют `name:"stem"`,
`style:"asciimath"` / `"latexmath"`, `inlines` и метаданные; WASM также spans.
CRLF в значении становится LF, физические координаты сохраняются.
Пустой блок имеет пустой `inlines`. По умолчанию применяется specialcharacters;
`subs` использует правила выбора стадий для блоков, включая модификаторы
и callouts (см. «Атрибут subs блоков»).

Подсветка получает `stem-delimiter` и `stem-text` из структурного parser,
с учётом include, списков, ячеек и незавершённого ввода. Внутренний текст
формулы не сканируется повторно как обычный inline-текст.

`Document.final_attributes` — снимок после body conversion, отдельно от
`Document.attributes` (заголовок). Он включает побочные эффекты и replay
атрибутов обработанных блоков. Хвостовые объявления без следующего блока
не проигрываются, как в Ruby. HTML использует его для включения MathJax и
`eqnums`; `asset-uri-scheme` берётся из заголовка. Это поле доступно в Rust API;
JSON/WASM сохраняют прежний контракт экспорта атрибутов документа.


== Атрибут subs блоков

Именованный атрибут `subs` выбирает подстановки содержимого блока по правилам
`resolve_block_subs` Ruby: группы `normal`, `verbatim`, `specialchars`, `none`,
модификаторы `+name`, `name+`, `-name` относительно умолчаний модели содержимого,
пробелы игнорируются, пустое значение отключает все стадии. Неизвестные имена
дают предупреждение `invalid substitution type(s) for <context>` на диапазоне
блока. Выбор, равный умолчаниям, не меняет AST.

* `Paragraph`, `Verse`, `Stem` и единственный абзац абзацной формы стилей
  (`Admonition`, `Example`, `Quote`, `Sidebar`, `Open`) получают
  `[Inline::Substituted]` вместо обычного разбора; ограждённые контейнеры
  `subs` не применяют.
* `Listing`, `Literal` и `Passthrough` получают `inlines:
  Option<Vec<Inline>>` — `Some` с одним `Inline::Substituted` при выбранных
  подстановках, иначе `None`. `text` остаётся исходным текстом; backends
  выводят `inlines`, если они есть (pass — по-прежнему без обёртки).
  Диапазон узла — физическое тело блока (для литерального абзаца с отступом
  — без отступа первой строки), в том числе через include.

Стадия callouts регистрирует исходные метки в каталоге при чтении (без них
стадия удаляется) и при conversion превращает метки после specialcharacters в
`AttributePart::Callout(InlineCallout)`: `number`, `guard` (лексический),
`xml`, `id` каталога по порядку (или `None`), `icons` и `src` иконки на момент
подстановки. Список `callouts` блока для таких listing/literal пуст.
Встроенные атрибуты включают `stylesdir` (`.`, fallback Ruby) и
`iconfont-remote` (пусто: standalone-значение Ruby). Публичная
`normalize_web_path(target, start, preserve_uri_target)` повторяет
`AbstractNode#normalize_web_path`.
`ast::Callout` и `CalloutListItem` тоже содержат `icons` и `src`, заполняемые
при conversion блока (а не из заголовка), как в Ruby; JSON/WASM экспортируют их.
JSON/WASM экспортируют части как `{"kind":"callout",…}` и поле `inlines`
блоков. Подсветка в тексте с выбранными `subs` оставляет только inline-токены
исполненных стадий и добавляет `callout` для преобразуемых исходных меток.


== Простое содержимое абзацных форм

`Block.simple` — модель `:simple` Ruby: контейнер (`Admonition`, `Example`,
`Sidebar`, `Open`, `Quote`), построенный из стилизованного абзаца, хранит этот
абзац единственным дочерним блоком (со своими spans и `subs`), а backends
выводят его inlines без элемента абзаца. Разделённые блоки, `[partintro]`-абзац
части книги и перестроенный `[open]`-вводный абзац — составные (`false`).
JSON/WASM добавляют `"simple":true` только к таким контейнерам.

== Markdown-цитаты и абзацы в кавычках

Абзац без стиля (или со стилем, который Ruby не считает стилем абзаца), первая
строка которого начинается с `> `, — составной `Quote` со стилем `quote`:
маркеры `> `/`>` снимаются, строки комментариев пропускаются, а остальные строки
разбираются как блоки с физическими spans (разделы внутри не распознаются).
Абзац, начинающийся с `"`, с последней строкой `-- …` и предпоследней,
оканчивающейся на `"`, — простой `Quote` с текстом между кавычками. Строка
`-- автор, произведение` получает обычные подстановки при чтении, а после
разрешения меток ссылок делится, как `split ', ', 2` Ruby по преобразованной
разметке: по первой `, ` выводимого текста, в том числе внутри форматирования,
ссылок и passthrough. Если разделитель внутри элемента, `Attribution.author`
получает начало (элементы закрыты), `citetitle` — остаток самого внутреннего
элемента в копиях его элементов, а `Attribution.trailing` — продолжение строки
после `cite` в копиях внешних элементов: так браузер восстанавливает разметку
Ruby. JSON/WASM экспортируют `trailing` только непустым. Позиционные поля
метаданных в атрибуцию не переносятся. Маркеры `>` дают токены
`quote-delimiter`.

== Сворачиваемые примеры и nowrap

Пример с опцией `collapsible` (`%collapsible`, `options=`, `collapsible-option`)
получает `Block.caption = Some("")`, как ветка `:example` Ruby, задающая
`caption` = '': номер `example-number` не расходуется, `caption=` не действует,
xrefstyle использует название. Опции остаются в `Block.attrs`; HTML выводит
`<details>`/`<summary>` (`open` при опции `open`). `prewrap` — встроенный
атрибут документа; атрибуты преобразования блока показывают его значение в
месте блока, по которому HTML добавляет `nowrap` (как и по опции `nowrap`).

== Source-умолчания и отступы verbatim-блоков

При завершении блока ветка `:listing`/`:source` Ruby дополняет `Listing`:

* Listing без стиля (ограждение `----`, а также `[#id]`/`[.role]`) становится
  `source`, если второй позиционный атрибут или атрибут чтения
  `source-language` задаёт язык (пустое значение тоже язык); третий
  позиционный тогда — `linenums`. Listing с другим стилем (`[listing]`,
  `[foo]`) не меняется.
* `source` без собственного `language` получает `source-language`; fenced code
  без языка в строке ограждения заменяет им даже `language` метаданных.
* `linenums` (если не задан) — пустое значение при опции `%linenums`,
  атрибуте `linenums-option` или `source-linenums-option` документа;
  `[source,lang,x]` даёт `linenums` = `x`, кавычки `""` у языка дают пустой язык.
* `indent` (если не задан) берётся из `source-indent`.

Абзацы `[listing]`/`[source]` — verbatim `Listing` (как `[literal]`): они
заканчиваются только пустой строкой или `+` и сохраняют строки, похожие на
ограждения, комментарии, списки и макросы; `[listing]` на `--` тоже даёт listing.

Атрибуты `indent` и `tabsize` (блока, иначе документа) применяются к
`Listing`/`Literal` во всех формах и к телу `Verse`, как `adjust_indentation!`
в `build_block`: табуляция раскрывается до позиций табуляции, считаемых по
Unicode-символам; затем при `indent` ≥ 0 удаляется общий отступ непустых строк
(любая строка без отступа отменяет удаление; tab без `tabsize` — один символ
отступа) и добавляется `indent` пробелов. Отрицательный `indent` только
раскрывает tab. Значения разбираются как `String#to_i` Ruby и ограничиваются
4096. Литеральный абзац с отступом по-прежнему только удаляет общий отступ.
`text` содержит результат; `inlines` при `subs` и тело verse строятся из того же
преобразованного текста с картой фрагментов: скопированный текст сохраняет
физические байты, добавленный отступ имеет нулевую ширину перед сохранённым
текстом строки, раскрытый tab отображается на исходный символ. Диапазоны
callouts сохраняют физические метки. Подсветка остаётся физической.

== Страницы руководства (manpage)

Doctype `manpage` повторяет `parse_manpage_header` Ruby в конце заголовка (не во
вложенных документах). Атрибут `doctitle` (лексическое написание) по
`ManpageTitleVolnumRx` даёт `manvolnum` и `mantitle` (после a-стадии, в нижнем
регистре); иначе ошибка `non-conforming manpage title` на первой строке и
запасные `doctitle`/`docname`/`command` и `1`. Если заданы и `manname`, и
`manpurpose`, раздел NAME не поглощается (`manname-title` по умолчанию `Name`).
Иначе после пустых строк читаются метаданные (они достаются первому блоку тела)
и раздел уровня 1: его название преобразуется как при чтении, строки до пустой
(без строчных комментариев, с `lstrip`, через пробел) делятся по
`ManpageNamePurposeRx`; имя и назначение получают только a-стадию (политика
`attribute-missing`, stateful-выражения, физические диапазоны). Имена делятся по
`,` как `String#split` Ruby. Значения — атрибуты заголовка: `manname`,
`mannames` (как `Array#inspect` Ruby), `manpurpose` (сырые части),
`manname-title` (если не задан — плоские части названия раздела), `manname-id`.
Ошибки `name section expected`, `name section must be at level 1` и
`non-conforming name section body` указывают на строку после пустых строк; тело
читает метаданные и раздел заново (роли сокращённой записи, как в Ruby,
удваиваются), `manname` — `docname` или `command`. Несоответствующее тело
оставляет зарегистрированным id раздела (Ruby регистрирует его до проверки),
поэтому раздел в теле получает `_name_2`.

`Document.manpage` (`Manpage`) хранит `names` и `name_section: Option<NameSection>`
— заголовок уровня 1 с id (регистрируется в реестре после названия документа,
ссылки в нём получают метки как при чтении, сноски входят в общий список) и
`body: Option<Span>` (строки имени и назначения; `None` для несоответствующего
тела), а `section_title` отмечает, что `manname-title` взят из раздела. После
регистрации `manname-id`/`manname-title` уточняются по разрешённому заголовку.
HTML выводит `<h1>… Manual Page</h1>` (без названия — название первого раздела,
как `doctitle` Ruby) и, если есть `manpurpose`, раздел `<section class="sect1">`
с `<h2 id=manname-id>` и `<p>имена - назначение</p>` перед автоматическим TOC;
при названии первого раздела в верхнем регистре метка переводится в верхний
регистр (в отличие от Ruby, теги и ссылки на символы не меняются). JSON —
`manpage` с `names` и `name_section` (`heading`, `conforming`), WASM — с `body`.
Подсветка: заголовок — `heading`, в строках имени — только `attribute-ref`.


== Опциональный экспорт снимков в JSON backend

`adoctra_json::JsonBackend::convert_with_attributes(&document)` возвращает
обычное JSON-дерево с добавленным `attribute_snapshots`. Поля `header` и `final`
содержат `values` (строковый словарь) и опциональный `attribute_parts`
(семантические части значений). Экспорт читает `Document.attributes` и
`Document.final_attributes`, не изменяя их. Вызов обычного `Backend::convert`
сохраняет прежний формат. В CLI используется `--to json --json-attributes`;
с другими backend этот флаг возвращает ошибку.

Экспорт используется link:semantic-profile.adoc[семантическим сравнительным
профилем] для явной выборки имён. Это не новый официальный формат ASG.
