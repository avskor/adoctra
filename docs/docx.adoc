= DOCX-бэкенд и контракт шаблона

Бэкенд `adoctra-docx` записывает документ в шаблон Word. Оформление задаёт
шаблон, а не конвертер: каждый элемент получает именованный стиль, который
шаблон определяет. Решение пользователя от 2026-11-04 снимает отсрочку DOCX
(DocBook и manpage остаются отложенными). План этапов —
link:implementation-plan.adoc[план совместимости], раздел «DOCX-бэкенд».

У Asciidoctor нет DOCX-эталона, поэтому совместимость DOCX с Ruby не
измеряется и не заявляется. Содержимое (текст, номера, подписи, ссылки)
берётся из того же core, что и HTML; его согласованность с HTML-бэкендом
проверяется отдельно (текстовый дифференциал, этап 8).

== Состояние

Этап 1 (2026-11-04): пакетный слой, модель шаблона, встроенные шаблоны,
поля обложки, проверка шаблона.

Этап 2 (2026-11-04): абзацы, разделы, inline-разметка, ссылки, закладки,
перекрёстные ссылки, обложка с подстановками и подзаголовком,
`docProps`, маркеры в колонтитулах, колонтитулы встроенного `book`.

Ещё не выводятся (одно предупреждение на вид): списки, таблицы,
изображения, видео и аудио, оглавление. Сноски пока выводятся меткой
`[n]`, inline-изображения — текстом `[alt]`. Блоки-контейнеры (пример,
врезка, предупреждение, цитата) пока без рамок: выводится их содержимое,
метка предупреждения — отдельным абзацем; листинги — абзацами `Code` по
одному на строку.

Запланировано (link:implementation-plan.adoc[план], «DOCX-бэкенд»): смена
ориентации страниц через `page-layout` и `%rotate` (отдельный этап, решение
от 2026-11-04).

== Преобразование

Блоки обходятся на явном стеке; inline-вложенность, ограниченная
синтаксисом, — рекурсивно, как в HTML-бэкенде.

Разделы:: стиль по уровню: `Part Title` (уровень 0 книги),
`Heading 1`–`6`, `Appendix Heading N` (стиль `appendix`),
`Floating Title N` (`discrete`/`float`). Номер (`1.2. `, `Appendix A: `,
сигнатуры глав) — текст из core, как в Ruby; нумерация стиля шаблона
(`numPr`, в том числе унаследованная) подавляется прямым `numId=0`. Id
раздела — закладка.
Абзацы:: `Normal`; первый абзац преамбулы без ролей и стиля — `Lead` (как
в таблице стилей Ruby), роль `lead` — `Lead`, внутри `[abstract]` —
`Abstract`, внутри цитаты — `Quote`; роли `text-left|center|right|justify`
задают выравнивание. `.Title` блока — абзац `Block Title` с подписью
(`Example 1. `), у врезки — `Sidebar Title`.
Inline:: у run один символьный стиль — самый конкретный из активных
(`Keyboard`/`Button`/`Menu`, `Callout`, `Monospace`, `Mark`,
`Xref`/`Hyperlink`, `Strong`, `Emphasis`); остальные форматы — прямыми
свойствами (`w:b`, `w:i`, выделение, подчёркивание, верхний и нижний
индекс), поэтому вложенное форматирование не теряется. Отсутствующий в
шаблоне символьный стиль заменяется прямыми свойствами. Роли фраз
`underline` и `line-through` дают подчёркивание и зачёркивание. Разрыв
строки (`+`, `hardbreaks`) — `w:br`; перевод строки исходника — пробел.
Значения `Raw` (ссылки на символы, сырая разметка passthrough) становятся
текстом: ссылки декодируются, теги отбрасываются.
Ссылки:: внешняя ссылка — `w:hyperlink` со связью (одна связь на URL);
перекрёстная ссылка внутри документа — `w:hyperlink w:anchor` на закладку
с текстом, который определил core; ссылка на другой документ — внешняя
связь на его путь. Вложенных ссылок в Word нет: действует внешняя. Имена
закладок: буквы, цифры и `_`, до 40 символов, начало с буквы или `_`
(скрытая закладка, как сгенерированные id Asciidoctor); имена уникальны и
одинаковы для якоря и ссылки на него.
Прочее:: тематический разрыв — абзац `Horizontal Rule`; разрыв страницы —
`w:br w:type="page"`; блоки passthrough отбрасываются с предупреждением
(сырому выводу нет формы в DOCX); стихи — `Verse` с разрывами строк и
атрибуцией `Verse Attribution`; цитата — абзацы `Quote` и атрибуция
`Quote Attribution` после вложенных блоков (`— автор`, разрыв, источник).

== Обложка, свойства и колонтитулы

Заголовок делится на основной и подзаголовок по последнему
`title-separator` (по умолчанию `:`) с пробелом, как `doctitle partition`
Ruby; `notitle` убирает заголовок. Поля обложки сохраняют inline-разметку.
Если в шаблоне нет маркера `adoctra:title`, заголовок и подзаголовок
открывают тело (стили `Title` и `Subtitle`).

`docProps/core.xml` заменяется: название (полный заголовок текстом),
авторы через `; ` (`dc:creator` и `cp:lastModifiedBy`), `description`,
`keywords`, даты создания и изменения из `docdatetime` (или `docdate`) в
W3CDTF; с `reproducible` дат нет. Content controls свойств документа Word
в колонтитулах показывают эти значения.

Маркеры `adoctra:*` заполняются и в колонтитулах (частях header/footer,
на которые ссылается главная часть); маркер тела там удаляется.

Встроенный `book`: обложка — раздел без колонтитулов; в теле шапка
«название (маркер `adoctra:title`) — заголовок текущей главы (поле
`STYLEREF "heading 1"`)», номер страницы внизу. Если в последнем
`w:sectPr` тела шаблона книги есть `w:titlePg`, каждая часть и глава
начинает раздел (копия этого `w:sectPr`), и её первая страница получает
колонтитулы первой страницы (во встроенном шаблоне — пустую шапку).
Перезапуск номеров страниц остаётся только у первого раздела тела.

== Шаблоны

Без пользовательского шаблона берётся встроенный по `doctype`: `book` для
книги, `article` для остальных (включая `manpage` и `inline`).

* `article`: заголовок, подзаголовок, авторы и строка ревизии в начале
  тела, затем документ.
* `book`: обложка отдельным разделом без колонтитула; документ — в разделе с
  номерами страниц с 1. Стили `Part Title` и `heading 1` начинают страницу.

Исходники — текстовые XML в `crates/adoctra-docx/templates/` (`common/` и
`document.xml` каждого шаблона); бинарных `.docx` в репозитории нет. Готовые
файлы для доработки в Word:

[source,sh]
----
cargo run -p adoctra-docx --example export_templates -- <каталог>
----

Пользовательский шаблон (`.docx` или `.dotx`) передаётся через API
`DocxBackend::with_template`; атрибут `docx-template` для CLI — этап 7.
`check_template` перечисляет пользовательские стили контракта, которых в
шаблоне нет.

== Контракт шаблона

=== Пакет

Шаблон остаётся непрозрачным пакетом: тема, шрифты, колонтитулы, custom XML
и все прочие части копируются побайтно. Меняются только тело
`document.xml`, маркеры, `styles.xml` (добавленные встроенные стили) и
связи главной части. Главная часть `.dotx` объявляется документом.
Вывод детерминирован: части в порядке имён (первой `[Content_Types].xml`),
фиксированные дата и права zip-записей.

=== Маркеры

Маркеры — content controls (SDT, «Элементы управления содержимым» Word) с
тегом `adoctra:<имя>`:

`adoctra:body`:: место тела документа; SDT целиком заменяется телом, всё до
и после остаётся. Без этого маркера тело шаблона (абзацы-образцы)
очищается, документ вставляется перед финальным `w:sectPr`, остальные
маркеры тела при этом удаляются.
`adoctra:title`, `adoctra:subtitle`, `adoctra:author`, `adoctra:email`,
`adoctra:revnumber`, `adoctra:revdate`, `adoctra:revremark`, `adoctra:revision`::
поля обложки. Блочный SDT заменяется своим первым абзацем (сохраняются
атрибуты и `w:pPr`, текст — значение поля); строчный SDT внутри абзаца —
текстом. Поле без значения удаляет SDT. `revision` — строка ревизии, как в
HTML-шапке Ruby: `version 1.2, 2026-01-02: Draft` (метка из атрибута
`version-label` в нижнем регистре).

Абзацы-образцы конфигурацию не несут: их можно держать внутри
`adoctra:body` как витрину стилей для дизайнера.

=== Стили

Стили ищутся по имени (`w:name`), затем по алиасу (`w:aliases`), затем по
`w:styleId`, без учёта регистра ASCII и только среди стилей нужного типа.
Идентификаторы, которые Word генерирует в локализованном интерфейсе (`1`,
`a7`), значения не имеют.

Word сохраняет встроенный стиль (`heading 4`, `toc 3`, `caption`…) в
`styles.xml` только после использования или изменения. Отсутствующий
встроенный стиль Word конвертер дописывает со значениями Word по умолчанию
(тема Office 2016+) без предупреждения. Отсутствующий пользовательский стиль
даёт предупреждение `docx template is missing <тип> style: <имя>` (один раз
на стиль), элемент остаётся с базовым оформлением.

Список имён — `crates/adoctra-docx/src/contract.rs`:

Абзацные:: `Normal`, `Title`, `Subtitle`, `Document Details`, `Part Title`,
`Heading 1`–`6`, `Appendix Heading 1`–`6`, `Floating Title 1`–`6` (вне
оглавления), `Lead`, `Abstract`, `List Paragraph`, `Term`, `Description`,
`Question`, `Answer`, `Code`, `Literal`, `Horizontal Rule`, `Block Title`,
`Caption`, `Quote`, `Quote Attribution`, `Verse`, `Verse Attribution`,
`Sidebar Title`, `Admonition Label`, `Footnote Text`, `TOC Heading`,
`TOC 1`–`6`.
Символьные:: `Strong`, `Emphasis`, `Monospace`, `Mark`, `Hyperlink`, `Xref`,
`Keyboard`, `Button`, `Menu`, `Callout`, `Line Number`, `Footnote Reference`.
Табличные:: `Table` (таблицы данных), `Code Table`, `Literal Table`,
`Admonition Table`, `Admonition Note|Tip|Important|Warning|Caution Table`,
`Example Table`, `Sidebar Table`, `Quote Table`, `Verse Table`.

Встроенные шаблоны определяют все стили контракта; оформление следует
`adoctra.css` (Noto Serif, Open Sans, цвета Asciidoctor; моноширинный —
Consolas, потому что Droid Sans Mono из таблицы стилей Ruby обычно не
установлен). Шрифты
подставляются Word, если не установлены (в `fontTable.xml` указаны
`altName` и семейство).

== Проверка

* Модульные тесты: XML-сканер, пакет (детерминизм, content types, связи),
  реестр стилей (имя, алиас, id, встроенные стили с базами и
  непересекающимися id), маркеры, встроенные шаблоны (корректный XML,
  стили контракта, существующие базы).
* Интеграционные `crates/adoctra-docx/tests/render.rs` и CLI-тест
  `cli_writes_docx_next_to_the_input_and_prints_its_warnings`.
* `scripts/docx_check.py` (только стандартная библиотека): XML частей,
  content types, связи, `w:sectPr`, определённость используемых стилей;
  `--render` конвертирует в PDF headless LibreOffice (`soffice` или
  `$SOFFICE`). Встроенные шаблоны и примеры проверены 2026-11-04
  (LibreOffice для Windows).
