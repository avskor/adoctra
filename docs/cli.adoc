= CLI и матрица сравнения

Команда `adoctra` повторяет наблюдаемое поведение команды Ruby `asciidoctor`
(`Asciidoctor::Cli::Options` и `Invoker` закреплённой версии) там, где речь
идёт о конвертации документов. Ruby API, шаблоны и библиотеки Ruby в цель
проекта не входят (решение пользователя от 2026-10-31).

== Опции

Разбор повторяет `OptionParser`:

* длинные опции по уникальному префиксу (`--em`), формы `--name=value` и
  `--name value`;
* склеенные короткие флаги (`-sn`) и присоединённые значения (`-Ssafe`,
  `-o-`);
* значения перечислений (`-d`, `-S`, `--failure-level`, `--eruby`) по
  уникальному префиксу с учётом регистра (`-d b` — book, `-S SAFE` — ошибка);
* `--` завершает опции, опции можно указывать после входных файлов.

Ошибки опций печатают сообщение Ruby (`invalid option: --x`, `invalid
argument: -d foo`, `ambiguous argument: -S s`, `option missing argument: -o`)
в stderr и справку в stdout, код выхода 1. Без входа справка идёт в stderr
(код 1), `-h` — в stdout (код 0) в момент разбора; `-V` или одиночный `-v`
печатают версию.

[cols="1,3",options="header"]
|===
|Опция |Поведение
|`-b BACKEND`
|`html5`/`html`/`xhtml5`/`xhtml` — HTML-конвертер и атрибут `backend`
(XML-синтаксис у xhtml); `json`/`docx` — форматы adoctra; `docbook5`/
`manpage` отложены; иначе ошибка Ruby `missing converter for backend`.
|`-d`, `-e`/`-s`, `-n`, `-a`, `-B`, `-S`/`--safe`
|Как в Ruby; `-a` пропускает пустое значение и `=`. Умолчание safe-режима —
`safe` (Ruby: `unsafe`), это намеренное отличие.
|`-o`, `-D`, `-R`
|Файловый вывод `Asciidoctor.convert` (см. upstream-tests.adoc); `-R`
сохраняет подкаталог входа ниже корня в `-D`.
|Входы
|Несколько файлов по порядку; имя, не являющееся файлом, раскрывается как
`Dir.glob` (`*`, `?`, `[…]`, `{a,b}`, `**/`); `-` один — stdin; `-` среди
других — предупреждение Ruby; отсутствующий файл или каталог — ошибка до
конвертации.
|`--failure-level`, `-q`, `-v`
|Каждое сообщение лога повышает максимальную серьёзность; код 1, если она не
ниже уровня (по умолчанию FATAL). `-q` ничего не печатает, но учитывает;
`-v` печатает и INFO. INFO, которые Ruby пишет только при уровне INFO
(`possible invalid reference`), учитываются только с `-v`
(`DiagnosticReport.verbose_only`).
|`-t`
|Отчёт `Timings#print_report` в stderr.
|`-w`, `--trace`, `--eruby`
|Принимаются без эффекта (интерпретатор Ruby, backtrace, шаблоны).
|`-T`, `-E`, `-I`, `-r`
|Ошибка: шаблоны и библиотеки Ruby вне цели проекта.
|===

`-B` — это `ParseOptions.base_dir` (Ruby `:base_dir`): include и изображения
основного документа разрешаются от него с jail в safe-режиме, а provider
по-прежнему читает путь относительно ссылающегося файла.

Собственные опции adoctra: `--to html|json|docx`, `--stdout`,
`--json-attributes`, `--diagnostics compat|editor`. Строки сообщений имеют
формат adoctra (`adoctra: file:N: warning: …`); имя файла — полный путь.
Как Ruby (`Asciidoctor.convert` с `to_file: '/dev/null'`), `-o /dev/null`
только загружает документ: выводятся диагностики чтения и действует
`--failure-level`, а конвертации, записи файла и проверки jail нет; `-t`
сообщает нулевое время конвертации. Ядро помечает диагностики конвертации
(`DiagnosticReport::conversion`).

== Матрица `cli-v1`

`scripts/cli_matrix.py` выполняет сценарии `compatibility/cli/cases.json`
обеими командами в одном временном каталоге с одинаковыми аргументами и
stdin. Эталон — `scripts/ruby-cli.rb` (`Invoker` закреплённого gem, тот же
Rouge и заглушки подсветчиков, что в остальных эталонах). Сравниваются:

* код выхода;
* stdout: HTML в проекции body-dom-v1, справка и версия — по виду;
* stderr: записи (уровень, имя файла, строка, текст) без имени программы и
  подсказки `Use --trace`, справка — по виду, отчёт `-t` без чисел;
* созданные и изменённые файлы, как в upstream-аудите.

Падение Ruby (необработанное исключение) — RUBY_ERROR. Результат: 71 PASS,
1 RUBY_ERROR (неоднозначный длинный префикс `--s`: Ruby не перехватывает
`OptionParser::AmbiguousOption`). CI запускает
`python3 scripts/cli_matrix.py --baseline compatibility/cli/report.json`;
`--case ID --show` печатает обе проекции.

Двоичные файлы сценария задаются `binary_files` (hex), двоичный stdin —
`stdin_hex`. Восемь сценариев проверяют кодировку входа, как
`Helpers.prepare_source_string` Ruby: BOM UTF-16LE/BE декодирует весь файл
или stdin; невалидный UTF-8 и UTF-16 нечётной длины прерывают загрузку
сообщением `FAILED: <абсолютный путь>|<stdin>: Failed to load AsciiDoc
document - source is either binary or contains invalid Unicode data` с кодом 1
до записи вывода; docinfo с BOM UTF-16 декодируется, строки docinfo
обрезаются справа по `rstrip` Ruby (U+00A0 остаётся, NUL/TAB/CR удаляются).
Docinfo проверяется в `docinfo-footer`: проекция stdout не включает `<head>`.

Не входят в матрицу: тексты справки и версии (различаются по замыслу),
`-h syntax`/`-h manpage` (документация Ruby), бэкенды DocBook/manpage,
опции Ruby API.
