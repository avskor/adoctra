= Корпус upstream-тестов

`compatibility/upstream/cases.json` — отдельная выборка из Asciidoctor 2.0.23,
commit `2c03d22eb9fe83d04ee452939581d1b842f6d8b4`.
43 адаптированных сценария из 30 именованных Ruby-тестов дают 43 PASS:
20 по приоритету/сбросу атрибутов, 13 по substitutions и 10 по include.
Это не запуск полного Ruby test suite и не процент совместимости языка.

== Происхождение и адаптация

В `sources/test/` сохранены полные неизменённые `attributes_test.rb`,
`substitutions_test.rb`, `reader_test.rb` и четыре include-fixture.
`sources/LICENSE` содержит лицензию MIT Asciidoctor.
Все восемь upstream-файлов сверены с Git blob-хешами закреплённого commit;
манифест фиксирует SHA-256, исходные пути и лицензию.
Для каждой адаптации указаны файл, номер строки объявления, точное имя теста
и описание изменений. Стенд проверяет контрольные суммы и соответствие
имени теста строке; неверное происхождение останавливает запуск.

`fixtures/` содержит входы выбранных сценариев. Варианты одного Ruby-теста
развёрнуты в отдельные случаи. В тестах атрибутов, исходно проверяющих
`doc.attributes['cash']`, добавлены ifdef/ifndef-параграфы для наблюдения
значения/отсутствия через HTML. В `apply normal substitutions` значение
`inception_year=2012` передаётся как host-атрибут вместо изменения Ruby-объекта
перед вызовом `apply_subs`. Ruby-специфичные варианты `nil`, `false`, `true`
не импортированы: текущий контракт host API и стенда принимает строки.

Выборка включает жёсткие значения и unsets, мягкие значения по имени и значению,
четыре строковые формы мягкого unset и восстановление встроенного `sectids`.
Substitutions проверяют normal/none, incremental pass, вложенные passthrough,
восстановление после macro substitution, роли, экранирование и неверные
списки substitutions. Include проверяет вложенные относительные пути,
диапазоны строк (включая пустой, неверный и открытый диапазон), кавычки/пробелы,
один/несколько тегов и вложенные маркеры. Исходные include-ресурсы не изменены.

== Проверяемый контракт

Используется существующий `body-dom-diagnostics-v1`: проекция HTML body и
упорядоченные warning/error severity/text. Эталон вычисляется тем же закреплённым
Ruby launcher. Исходные assertions на приватные методы Ruby не переносятся
буквально; сравнивается наблюдаемый результат полной обработки входа.
Позиции диагностик, все атрибуты/inline-узлы и официальный ASG/TCK в этот
профиль не входят. XFAIL потребовал бы отдельного объяснения и полного baseline;
сейчас в данной выборке XFAIL нет. Дрейф эталона и XPASS считаются ошибками.

Дополнительные Rust-тесты используют те же upstream-fixture и проверяют
порядок шести параграфов вложенных include, исходные source_id, byte spans
и номера строк 1/3/5. Для `tags=snippetA;snippetB` проверяются физические строки
12 и 18 через составной provenance объединённого текстового узла.
Атрибутные Rust-тесты проверяют снимки header/body, сохранение исходных host-значений,
семантических частей и диапазонов ссылок при Unicode/CRLF. Эти проверки
составляют отдельные утверждения о модели adoctra, а не новый сравнительный профиль.

== Запуск

[source,shell]
----
cargo build -p adoctra-cli
python3 scripts/acceptance.py --manifest compatibility/upstream/cases.json
python3 scripts/acceptance.py --manifest compatibility/upstream/cases.json --verify-reference
python3 scripts/acceptance.py --manifest compatibility/upstream/cases.json --case attr-soft-value
python3 scripts/acceptance.py --manifest compatibility/upstream/cases.json --json-report target/upstream-report.json
----

Для пересоздания эталонов после проверки изменений используется
`--update-reference`. Обычно нужен `--verify-reference`, который не меняет
файлы. Offline-проверка и повторное вычисление эталонов включены в CI;
установка Asciidoctor использует общую версию `compatibility/asciidoctor-version`.
Минимальный корпус и приёмка реальных документов продолжают запускаться отдельно.


== Дополнительная семантическая проверка

`compatibility/upstream/semantics.json` переиспользует 20 атрибутных и 4
include-сценария этой выборки и добавляет 14 собственных проб: 38 PASS в
link:semantic-profile.adoc[`inline-semantics-v1`]. Это отдельный профиль с
собственными эталонами и явной выборкой атрибутов; исходная HTML-выборка
остаётся 43 PASS. Семантические пробы не считаются импортированными upstream-тестами.

== Полный дифференциальный аудит

`scripts/upstream_audit.py` проверяет не выборку, а все документы, которые
строит тестовый набор закреплённого Asciidoctor. В `sources/test/` теперь
закреплены все 24 файла `*_test.rb` и `test_helper.rb` commit
`2c03d22eb9fe83d04ee452939581d1b842f6d8b4` без изменений.

=== Инвентарь

`scripts/upstream_record.rb` оборачивает `Asciidoctor::Document#initialize`.
Через него проходят хелперы тестов (`convert_string*`, `document_from_string`)
и прямые `Asciidoctor.load`/`convert`. Каждый документ без родителя
записывается с исходным текстом, фактическими опциями, файлом, строкой вызова
и объявлением `test '…' do`. Прогон всего набора дал 2816 документов из
21 файла (`converter_test.rb` требует `tilt` для пользовательских шаблонов
и вне контракта). После устранения дублей по (текст, опции) в
`compatibility/upstream/audit/inventory.json` 2621 запись. Абсолютный путь
копии upstream заменён меткой `<UPSTREAM>`. Аудит проверяет SHA-256 каждого
закреплённого тестового файла, устойчивые id и то, что строка объявления
действительно содержит `test '<имя>' do` (три вызова из вспомогательного
кода вне блоков `test` записаны без объявления).

Запись выполняет код тестового набора upstream и требует его зависимостей
(`minitest`, `nokogiri`, `rouge`). Поэтому это отдельная ручная операция
по копии закреплённого commit:

[source,shell]
----
ASCIIDOCTOR_TEST_DIR=<copy>/test RECORD_OUT=rec.jsonl \
  ruby -r ./scripts/upstream_record.rb <copy>/test/<file>_test.rb   # каждый файл
python3 scripts/upstream_audit.py --record <copy> --recording rec.jsonl
----

=== Сравнение

Для каждой поддерживаемой записи эталонная сторона
(`scripts/upstream-audit-reference.rb`, один процесс Ruby) строит документ
с записанными опциями теста, а CLI получает `-S` (без опции —
`secure`, как у `Document.new`), `-s` для embedded, `-a` для атрибутов и
`doctype`. Обе стороны получают одинаковые `SOURCE_DATE_EPOCH` и `TZ`.
Сравниваются проекция `body-dom-v1` (оболочки standalone header/main/footer
сопоставлены, как в asset-аудите) и упорядоченные warning/error.
Некорректный HTML (сырые несбалансированные теги passthrough) проекция не
принимает; тогда сравнивается тело страницы целиком (`raw-body`). Эталонное
окружение не имеет необязательных серверных подсветчиков (`rouge`, `coderay`,
`pygments`) независимо от установленных на машине gem, как эталоны golden и CI.

UNSUPPORTED — записи, которые контракт CLI не выражает, с причиной:
бэкенды docbook/manpage/xhtml (в том числе через атрибут `backend`),
опции `base_dir`, `to_dir`/`to_file`, реестры расширений, `sourcemap`,
`parse_header_only`, `logger`, путь копии upstream и входы, обращающиеся
к временному HTTP-серверу тестов. Это не PASS и не исключение из
контракта; часть из них можно перевести в поддерживаемые отдельными
адаптерами.

Разбор 145 расхождений по причинам (по именам тестов и `--show ID`):

* *`doctype=inline`* (около 40): не реализован. Ruby выводит содержимое
  первого абзаца без обёрток, adoctra — обычный документ. Самый крупный пробел.
* *Серверная подсветка* (33): эталон без gem `rouge` предупреждает
  «optional gem 'rouge' is not available» и выводит `<pre class="rouge
  highlight">`. adoctra так поступает для CodeRay/Pygments, но не для Rouge.
  Способ работы с Rouge — отдельное решение (см. реестр расхождений).
* *Пробелы passthrough-блока и счётчиков* (12): например, `++++` с
  `subs=attributes` у adoctra оставляет завершающий пробел.
* *Предупреждения* (9): незакрытые комментарии, несогласованный `endif`,
  ошибочные `ifeval`/`ifdef` без цели.
* *Пограничные случаи include* (9): цели с пробелами, `skip-front-matter`,
  ссылки вместо удалённого include в secure mode.
* *Якоря* (7): якоря внутри заголовков разделов, пустой reftext.
* *Callouts с иконками и комментарии строк* (6).
* *Заголовки ATX/Markdown* (6): `# Title` и симметричная форма `== Title ==`
  не распознаются.
* *Прочее* (около 25, по одному-два): лимит размера значения атрибута в
  secure mode, `user-home`, роли списков, `max-width`, пустая дата ревизии,
  `fragment` для порядка разделов, SVG `%inline` без файла и др.

Полный список со статусами — `compatibility/upstream/audit/report.json`;
`python3 scripts/upstream_audit.py --show <id>` показывает вход, опции,
диагностику и разницу проекций обеих сторон.
