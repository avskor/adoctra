= Корпус upstream-тестов

`compatibility/upstream/cases.json` — отдельная выборка из Asciidoctor 2.0.23,
commit `2c03d22eb9fe83d04ee452939581d1b842f6d8b4`.
43 адаптированных сценария из 30 именованных Ruby-тестов дают 43 PASS:
20 по приоритету/сбросу атрибутов, 13 по substitutions и 10 по include.
Это не запуск полного Ruby test suite и не процент совместимости языка.

== Происхождение и адаптация

В `sources/test/` сохранены полные неизменённые `attributes_test.rb`,
`substitutions_test.rb`, `reader_test.rb` и весь каталог `test/fixtures`
(73 файла без изменений; аудит сверяет их SHA-256 в инвентаре).
`sources/LICENSE` содержит лицензию MIT Asciidoctor.
Все восемь upstream-файлов сверены с Git blob-хешами закреплённого commit;
манифест фиксирует SHA-256, исходные пути и лицензию.
Для каждой адаптации указаны файл, номер строки объявления, точное имя теста
и описание изменений. Стенд проверяет контрольные суммы и соответствие
имени теста строке; неверное происхождение останавливает запуск.

`fixtures/` содержит входы выбранных сценариев. Варианты одного Ruby-теста
развёрнуты в отдельные случаи. В тестах атрибутов, исходно проверяющих
`doc.attributes['cash']`, добавлены ifdef/ifndef-параграфы для наблюдения
значения/отсутствия через HTML. В `apply normal substitutions` значение
`inception_year=2012` передаётся как host-атрибут вместо изменения Ruby-объекта
перед вызовом `apply_subs`. Ruby-специфичные варианты `nil`, `false`, `true`
не импортированы: текущий контракт host API и стенда принимает строки.

Выборка включает жёсткие значения и unsets, мягкие значения по имени и значению,
четыре строковые формы мягкого unset и восстановление встроенного `sectids`.
Substitutions проверяют normal/none, incremental pass, вложенные passthrough,
восстановление после macro substitution, роли, экранирование и неверные
списки substitutions. Include проверяет вложенные относительные пути,
диапазоны строк (включая пустой, неверный и открытый диапазон), кавычки/пробелы,
один/несколько тегов и вложенные маркеры. Исходные include-ресурсы не изменены.

== Проверяемый контракт

Используется существующий `body-dom-diagnostics-v1`: проекция HTML body и
упорядоченные warning/error severity/text. Эталон вычисляется тем же закреплённым
Ruby launcher. Исходные assertions на приватные методы Ruby не переносятся
буквально; сравнивается наблюдаемый результат полной обработки входа.
Позиции диагностик, все атрибуты/inline-узлы и официальный ASG/TCK в этот
профиль не входят. XFAIL потребовал бы отдельного объяснения и полного baseline;
сейчас в данной выборке XFAIL нет. Дрейф эталона и XPASS считаются ошибками.

Дополнительные Rust-тесты используют те же upstream-fixture и проверяют
порядок шести параграфов вложенных include, исходные source_id, byte spans
и номера строк 1/3/5. Для `tags=snippetA;snippetB` проверяются физические строки
12 и 18 через составной provenance объединённого текстового узла.
Атрибутные Rust-тесты проверяют снимки header/body, сохранение исходных host-значений,
семантических частей и диапазонов ссылок при Unicode/CRLF. Эти проверки
составляют отдельные утверждения о модели adoctra, а не новый сравнительный профиль.

== Запуск

[source,shell]
----
cargo build -p adoctra-cli
python3 scripts/acceptance.py --manifest compatibility/upstream/cases.json
python3 scripts/acceptance.py --manifest compatibility/upstream/cases.json --verify-reference
python3 scripts/acceptance.py --manifest compatibility/upstream/cases.json --case attr-soft-value
python3 scripts/acceptance.py --manifest compatibility/upstream/cases.json --json-report target/upstream-report.json
----

Для пересоздания эталонов после проверки изменений используется
`--update-reference`. Обычно нужен `--verify-reference`, который не меняет
файлы. Offline-проверка и повторное вычисление эталонов включены в CI;
установка Asciidoctor использует общую версию `compatibility/asciidoctor-version`.
Минимальный корпус и приёмка реальных документов продолжают запускаться отдельно.

== Полный дифференциальный аудит

`scripts/upstream_audit.py` проверяет не выборку, а все документы, которые
строит тестовый набор закреплённого Asciidoctor. В `sources/test/` теперь
закреплены все 24 файла `*_test.rb` и `test_helper.rb` commit
`2c03d22eb9fe83d04ee452939581d1b842f6d8b4` без изменений.

=== Инвентарь

`scripts/upstream_record.rb` оборачивает `Asciidoctor::Document#initialize`.
Через него проходят хелперы тестов (`convert_string*`, `document_from_string`)
и прямые `Asciidoctor.load`/`convert`. Каждый документ без родителя
записывается с исходным текстом, фактическими опциями, файлом, строкой вызова
и объявлением `test '…' do`. Прогон всего набора дал 2816 документов из
21 файла (`converter_test.rb` требует `tilt` для пользовательских шаблонов
и вне контракта). После устранения дублей по (текст, опции) в
`compatibility/upstream/audit/inventory.json` 2621 запись. Абсолютный путь
копии upstream заменён меткой `<UPSTREAM>`. Аудит проверяет SHA-256 каждого
закреплённого тестового файла, устойчивые id и то, что строка объявления
действительно содержит `test '<имя>' do` (три вызова из вспомогательного
кода вне блоков `test` записаны без объявления).

Запись выполняет код тестового набора upstream и требует его зависимостей
(`minitest`, `nokogiri`, `rouge`). Поэтому это отдельная ручная операция
по копии закреплённого commit:

[source,shell]
----
ASCIIDOCTOR_TEST_DIR=<copy>/test RECORD_OUT=rec.jsonl \
  ruby -r ./scripts/upstream_record.rb <copy>/test/<file>_test.rb   # каждый файл
python3 scripts/upstream_audit.py --record <copy> --recording rec.jsonl
----

=== Сравнение

Для каждой поддерживаемой записи эталонная сторона
(`scripts/upstream-audit-reference.rb`, один процесс Ruby) строит документ
с записанными опциями теста, а CLI получает `-S` (без опции —
`secure`, как у `Document.new`), `-s` для embedded, `-a` для атрибутов и
`doctype`, `-B` для `base_dir`. Пути копии upstream (`<UPSTREAM>` в
исходнике, атрибутах и опциях) обе стороны получают как один временный
каталог, в котором развёрнуты завендоренные фикстуры (`test/fixtures`).
Обе стороны получают одинаковые `SOURCE_DATE_EPOCH` и `TZ`; документ без
`base_dir` и `docdir` разрешает пути от текущего каталога процесса (корень
репозитория), как Ruby. Сообщение с переводом строки (Ruby сохраняет его)
читается из stderr CLI целиком. На время прогона стенд поднимает веб-сервер
тестов upstream по их фиксированному адресу `127.0.0.1:9876` (его называют
записанные исходники): копия `using_test_webserver` из `test_helper.rb`
(ответ HTTP/1.1 без Content-Length, `image/<ext>`, `.adoc` и файлы без
расширения как text/plain, `/name/asciidoctor` как JSON, иначе 404), но не
отдающая файлы вне каталога `test`. Эталон Ruby даёт каждой записи свой
пустой каталог кэша open-uri-cached, как отдельный процесс.
Сравниваются (профиль отчёта `upstream-audit-body-shell-positions-model-v3`):

* проекция `body-dom-v1` (оболочки standalone header/main/footer сопоставлены,
  как в asset-аудите);
* для standalone-вывода — оболочка документа: атрибуты `<html>` и `<body>`
  (класс doctype, `toc2`, роли) и дети `<head>` (тег, атрибуты, текст) по
  порядку. Намеренные отличия исключены явно: `meta` generator и
  http-equiv, содержимое таблицы стилей по умолчанию (узнаётся по
  начальному комментарию; сравнивается её место, встроенная или ссылкой) и
  ссылка Google Fonts из пустого умолчания `webfonts` Ruby (тема adoctra
  использует системные шрифты; явное значение `webfonts` сравнивается);
* упорядоченные warning/error: уровень, текст и курсор logger Ruby
  (`source_location`: файл и строка или его отсутствие) против `файл:строка`
  CLI; stdin — `<stdin>`, файлы копии — относительно её корня;
* модель документа, которую утверждения читают через API: структура блоков
  (схема link:acceptance.adoc[`block-structure-v1`]: контекст, id, роли,
  уровень, модель содержимого, пункты списков, форма таблиц и вложенные
  документы ячеек) и снимки атрибутов — при сохранении заголовка
  (`Document#save_attributes`) и после конвертации — против JSON adoctra
  (`--to json --json-attributes`, те же аргументы). Значения сравниваются как
  текст: Ruby хранит их после подстановок заголовка (разметка, ссылки на
  символы), adoctra — в исходном написании с размеченными частями рядом;
  пути копии заменяются на `<UPSTREAM>`, значение `nil` равно отсутствию.
  Записи с файловым выводом (`to_file`/`to_dir`) модель не сравнивают:
  обе стороны там — запуски CLI.
Некорректный HTML (сырые несбалансированные теги passthrough) проекция не
принимает; тогда сравнивается тело страницы целиком (`raw-body`). Эталонное
окружение не имеет необязательных серверных подсветчиков (`rouge`, `coderay`,
`pygments`) независимо от установленных на машине gem, как эталоны golden и CI.

UNSUPPORTED — записи, которые контракт CLI не выражает, с причиной
(277): бэкенды docbook/docbook5/manpage (243, в том числе через атрибут
`backend` документа) и неизвестный backend (2), реестры расширений и
фабрики подсветчиков Ruby API (18), `parse_header_only` (6), `logger` (4),
вывод в абсолютный путь вне копии upstream (`/tmp`, 2), атрибут-объект
`Pathname` (1) и целочисленный safe-уровень выше secure (1). Это не PASS и
не исключение из контракта; часть из них можно перевести в поддерживаемые
отдельными адаптерами.

Записи с `to_dir`/`to_file` (файловый вывод `Asciidoctor.convert`)
выполняются как один запуск CLI на каждой стороне с одинаковыми аргументами
(`-D`, `-o`, `-S`, `-a`, `-B`): эталон — `Asciidoctor::Cli::Invoker`
(режим `--invoke` эталонного скрипта, те же заглушки подсветчиков), рабочий
каталог — развёрнутая копия upstream. Входом служит фикстура `docfile`,
если она совпадает с исходником (тогда `docfile`/`docdir`/`docname`/
`docfilesuffix` выводит сам CLI), иначе stdin. Записанные
файлы фиксируются по снимку дерева до и после запуска, дерево
восстанавливается перед следующим запуском. Сравниваются код выхода,
текст ошибки, предупреждения, stdout и каждый записанный файл (HTML — в
проекции и по наличию завершающего LF, прочие — побайтно; стандартная
таблица стилей `asciidoctor.css`/`adoctra.css` — только по наличию).
Записанный эталон адаптирован: опции зафиксированы на входе `Document.new`
(`:to_dir` уже разрешён `convert`), поэтому повторный запуск может писать в
другой путь, чем исходный тест, но обе стороны получают одинаковый вызов.

Опции Ruby API, которые меняют только состояние API, а не вывод
(`sourcemap`, `catalog_assets`, `timings`, `eruby`: html5-конвертер не
использует шаблоны), эталон передаёт Ruby, а CLI их не требует
(`PASSIVE_OPTIONS`). Опция `backend` (`html5`, `html`, `xhtml`, `xhtml5`)
передаётся CLI как заблокированный атрибут `backend`, как
`attr_overrides` Ruby; мягкое `backend=html5@` разрешено. Неизвестное имя
safe-уровня — secure, как `value_for_name … rescue SECURE` Ruby.
Синтаксис XML (`htmlsyntax=xml`) HTML-бэкенд выводит как html5-конвертер
Ruby: `/` у void-элементов, булевы атрибуты `name="name"`, `xmlns` у `html`;
его выбирает синтаксис конвертера на момент последнего `backend`
(`Document.htmlsyntax`), а не позднее присвоенный атрибут.

=== Сопоставление утверждений с проверками

Аудит сравнивает результат обработки входов тестов, а не их утверждения.
Чтобы видеть, что утверждения проверяют и наблюдает ли это какой-либо
профиль, 2026-11-03 утверждения 2568 тестов (блоки `test '…' do` всех 24
файлов) были разобраны эвристически — по строкам `assert_*`/`refute_*` — и
связаны с записями инвентаря по строке объявления. Числа приблизительны
(один тест может попасть в несколько строк); это разовая оценка, а не
стенд.

Две строки таблицы до 2026-11-03 ничем не сравнивались: оболочка standalone
(902 записи) и курсоры диагностик. После их включения оболочка совпала у всех
902 записей (с исключением трёх намеренных отличий выше), а курсоры выявили
расхождения, исправленные в core: Ruby пишет без курсора исключённые
`abstract`/`partintro` (и только при конвертации — с `-o /dev/null` их нет),
`invalid footnote reference`, `found deprecated footnoteref macro` и
`invalid substitution type…`; часть без раздела Ruby сообщает в
`reader.cursor` после её чтения (заголовок закрывающей части или конец
ввода), предупреждения стиля (`[#]`, `[#a#b]`) — в `cursor_at_prev_line`,
строка 0 для первой строки. Каждое закреплено пробой профиля позиций и
Rust-тестом (`upstream_single_cases.rs`). Статусы аудита не изменились.

Затем аудит стал сравнивать модель документа (структуру блоков и снимки
атрибутов) у 2305 записей. Совпали все, кроме двух находок: `[separator=::]`
над заголовком документа Ruby записывает в атрибут `title-separator`
(исправлено в core, `upstream_single_cases.rs`), а опции API `:doctype` и
`:backend` перекрывают одноимённые атрибуты (стенд передавал их CLI раньше
атрибутов; исправлен порядок `-a`). Не сравниваются: тексты, заголовки и
метаданные отдельных блоков через API (видны через HTML), номера строк
узлов, каталог ссылок и сносок вне HTML, а также модель записей с файловым
выводом.

=== Состояние

Аудит выполняется за секунды и входит в CI (`--baseline` замораживает статус
каждой записи; регрессия, улучшение и новая ошибка останавливают проверку,
улучшение записывается отдельно).

Эталонная сторона воспроизводит отдельный запуск CLI Ruby для каждого
документа: вывод — `output.chomp` и LF (ничего для `nil`), а кэш статуса
библиотек подсветки (`@@library_status`) сбрасывается перед каждой записью.
Без этого предупреждение об отсутствующем gem выдавалось только для первого
документа пакета. Закреплённый Rouge (`compatibility/rouge-version`, его
переносит `adoctra-highlight`) в эталоне доступен; заглушка остальных
необязательных gem (coderay, pygments) задаёт `LoadError#path`, как при
настоящем отсутствии gem (текст без «reason»).

inline) и семантическая проба `semantic-svg-incomplete`. Правило аудита не
меняется, и запись остаётся DIFF; и
RUBY_ERROR reader_test.rb:845 — Ruby падает на выбранной строке с ошибочным
UTF-8 (adoctra остаётся устойчивым, граница описана в «Кодировках include»).

Фикстуры upstream (161 запись, ранее UNSUPPORTED «path:upstream-checkout»)
потребовали порта `PathResolver#system_path` Ruby: include и изображения
разрешаются от базового каталога (`docdir`) с jail и его «восстановлением»
с safe mode (предупреждения «… has illegal reference to ancestor of jail /
is outside of jail; recovering automatically»), сообщения называют
разрешённый путь («include file not found: …», «image to embed not found or
not readable: …», «<docfile>: SVG does not exist or cannot be read: …»);
однострочный `ifdef` повторно обрабатывает `include::`; каталог включений
для stdin строится от базового каталога. CLI получил `-B/--base-dir`, а stdin
читает ресурсы от `-B`, иначе `docdir`, иначе текущего каталога, как Ruby.

Единичные расхождения исправлены (каждое — регрессионным тестом в
`crates/adoctra-core/tests/upstream_single_cases.rs`):

* строка ревизии `v1.0.0,:remark` с пустой датой (`RevisionInfoLineRx`);
* атрибуция цитаты из `[, author, source]` и из именованных
  `attribution`/`citetitle` (`AttributeList.rekey`: позиционное значение
  важнее именованного);
* `max-include-depth` по умолчанию 64 как атрибут (`||= 64`), так что
  `{counter:max-include-depth:128}` даёт 65, а значение остаётся 64;
* заголовок блока над заголовком документа отменяет заголовок
  (`invalid-header`): строка становится разделом уровня 0 с ошибкой;
* `fragment` снимает проверку уровня только для верхнего раздела;
* `sectnums`/`numbered` из API документ может переключать
  (`FLEXIBLE_ATTRIBUTES`), а снятие из API остаётся;
* текстовая иконка (`icon:gear[]` без `icons`) входит в id раздела как
  `[gear&#93;`;
* экранированный обратный апостроф после `[x-]` не начинает passthrough;
* сложенный абзац описания теряет общий отступ (`adjust_indentation!`),
  физические span сохраняются;
* `+` после пустой строки во вложенном списке описаний прикрепляет блок к
  вложенному термину (идентичность placeholder между вложенными reader);
* незакрытый контейнер предупреждает раньше своих дочерних блоков;
* AsciiDoc-ячейка с `:doctype: inline` выводит содержимое без обёрток;
* сведения об авторе в шапке выводятся только при наличии заголовка документа.

Стенд аудита: `backend` из самого документа (не HTML) — UNSUPPORTED
(`backend:document:…`); значение `False` атрибута API передаётся как мягкое
снятие (`name!@`); неизвестные «теги» в тексте (например, `<html5>`)
нейтрализуются для проекции на обеих сторонах. Проекция `body-dom-v1`
игнорирует класс `arabic` рядом с ролями нумерованного списка.

`doctype=inline` реализован (HTML-бэкенд, как `Document#convert` Ruby):
выводится только содержимое первого блока — абзаца, verbatim/raw/STEM-блока,
verse или простого содержимого стилизованного абзаца — без обёрток и перевода
строки; блок с составным или пустым содержимым (раздел, preamble, список,
таблица, изображение, разрыв, только заголовок документа) даёт
предупреждение Ruby «no inline candidate…» и пустой вывод; документ без
блоков пуст. CLI, как Ruby CLI, дописывает LF к непустому выводу и теперь
печатает предупреждения бэкенда и в embedded-режиме (раньше они терялись).
Из 41 записи с `doctype=inline` расходится одна (переименование `language`
в compat-mode — другая функция).

Предупреждения условных директив и незакрытого блока комментария теперь
выдаются в отчёте конвертации (вывод CLI по умолчанию) дословно как у Ruby:
«malformed preprocessor directive - text not permitted / missing target /
target not permitted / missing expression / invalid expression: <директива>»,
«mismatched preprocessor directive: endif::<цель>[], expected endif::<цель>[]»
(цель в нижнем регистре, текст в скобках как есть) и «unterminated comment
block». Короткие сообщения для редактора (`Diagnostic.message`) не изменились.

Директивы include следуют грамматике Ruby (IncludeDirectiveRx): пустая
цель или цель с пробелом в начале или конце не директива, а обычный текст
(например, `include:: []` — список описаний). Без провайдера (строковые API,
stdin) ничего не читается, но URI-цель без `allow-uri-read` при включённых
include (положительный host `max-include-depth`) становится ссылкой
`link:…[role=include]`, как в Ruby, которому для этого не нужен ввод-вывод;
файловые цели по-прежнему остаются текстом. `skip-front-matter` пропускает
front matter (`---` … `---` в начале) основного документа до заголовка и
каждого включённого файла и задаёт атрибут `front-matter` (во включении —
эффект чтения), физические span остаются прежними.

Заголовки разделов следуют `ExtAtxSectionTitleRx` (Markdown-синтаксис Ruby
включён по умолчанию): маркер из одного–шести `=` или `#`, пробелы или
табуляции и необязательный закрывающий маркер той же длины (`== Title ==`,
`## Title ##`), который в заголовок не входит. Поэтому и якорь
`[[id, reftext]]` перед закрывающим маркером снова становится id раздела.
Блочный якорь следует `BlockAnchorRx`: id `[\p{Alpha}_:][\p{Word}\-:.]*`
(без цифры в начале; иначе строка — текст), а пустой `[[]]` — якорь без id,
который поглощается и сбрасывает ожидающий id.

Список callouts с иконками (`icons=font`/`image`) у Ruby — таблица, у
adoctra — семантический `ol` со `span.colist-icon` и `div` (визуально
одинаковы). Это намеренное отличие разметки, а не обработки: проекция
`body-dom-v1` теперь сопоставляет обе формы (см. реестр в compatibility.adoc),
и пять таких записей совпадают.
