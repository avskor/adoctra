= Совместимость с Asciidoctor

Эталон — Asciidoctor *2.0.23*. Машиночитаемая версия находится в
link:../compatibility/asciidoctor-version[compatibility/asciidoctor-version].
Обновление версии — отдельное изменение с проверкой различий корпуса.

== Контракт

* Язык: одинаковая интерпретация содержимого, атрибутов, блоков и ссылок при
  одинаковых настройках. Сейчас реализовано ограниченное подмножество.
* HTML: существующий backend использует собственную разметку. Точное соответствие
  HTML эталону будет отдельным режимом; текущие нормализованные сравнения его не доказывают.
* Редактор: AST, диагностики и позиции должны согласовываться с подсветкой;
  незавершённый документ должен давать частичный результат.
* Ruby API и исполнение Ruby-расширений находятся за пределами этого контракта.

== Проверки

Начальный сравнительный профиль `body-dom-v1` сравнивает всё тело документа.
Он удаляет только известные структурные обёртки HTML, переносит их id/roles на
содержимое, согласует представление списков и verbatim-блоков, декодирует HTML
entities и нормализует пробелы обычного текста. В listing/literal/pre пробелы,
табуляция и переводы строк сохраняются. Неизвестные теги и атрибуты сохраняются.
Этот профиль проверяет наблюдаемое содержимое HTML, а не полный ASG, диагностики,
атрибуты документа или точное совпадение HTML. Для них нужны отдельные профили.
При генерации этого профиля задан `showtitle`, чтобы заголовок документа входил
в сравнение; adoctra запускается с `--embedded -a showtitle` (как `-s` Ruby). Quote и verse проецируются в общие узлы: Ruby `div.attribution`
и `pre.content` согласуются с `figcaption` и `pre.verse`, а единственный параграф
внутри `blockquote` сравнивается с текстом простой цитаты. `figure.imageblock`,
`figure.videoblock`, `figure.audioblock` и их `figcaption.title` adoctra
проецируются в `div` и `div.title` Ruby; `frameborder="0"` у `iframe` Ruby —
оформление (adoctra задаёт рамку стилями). Обёртки `div.dlist`/`div.qlist`
снимаются, как у других списков (повторяющиеся классы обёртки и списка
объединяются); таблица `div.hdlist` Ruby проецируется в `dl` (термины ячейки
`hdlist1` разделяются по `<br>`, ширины `colgroup` и стиль сетки adoctra —
оформление). Обёртка `div.colist` снимается, а класс `colist` списка adoctra —
оформление.
`aside.sidebarblock` adoctra проецируется в `div.sidebarblock` Ruby, обёртка
`div.content` снимается. Таблица `div.admonitionblock` Ruby и
`aside.admonition` adoctra проецируются в общий узел: тип, id, роли, текстовая
метка или разметка значка (`<i>`/`<img>` ячейки `icon` и
`p.admonition-title`) и тело ячейки `content` (обёртка
`div.admonition-content` adoctra снимается); `aria-label` — оформление.
Значки `icons` стенд не видит (secure mode блокирует `icons`), их сравнивает
golden-тест `golden/admonition_icons/` с эталоном в safe mode. Текст `blockquote` сравнивается как есть: простое содержимое цитаты
(абзацная форма) отличается от абзаца `<p>`.
Спроецированные узлы `quote`/`verse` в пункте списка — блоки, как и остальные.
Корпус содержит 3300 сценариев: все PASS.

Отдельный link:acceptance.adoc[приёмочный корпус] содержит 21 прогон полных
документов и семь диагностических примеров. Профиль `body-dom-diagnostics-v1`
сравнивает эту же HTML-проекцию и сообщения warning/error; результат — 25 PASS
и 3 XFAIL диагностик. Эти числа учитываются отдельно от минимальных сценариев.
Отдельный профиль `block-structure-v1` сравнивает проекцию деревьев parser
через JSON, без HTML: порядок и вложенность блоков, ID/роли, уровни разделов,
списки и таблицы. 21 прогон документов и пять структурных примеров —
26 PASS. Это не полный ASG: текст, inline-семантика, атрибуты и позиции не
сравниваются; точный состав и ограничения описаны в приёмочном корпусе.
Корпус включает по шесть страниц руководств Asciidoctor и Spring Framework
с закреплёнными коммитами, лицензиями и include-примерами. Сборка Antora и
её разрешение межстраничных ссылок в этот профиль не входят.

[source,sh]
----
cargo build -p adoctra-cli
python3 scripts/compatibility.py
python3 scripts/compatibility.py --verify-reference
python3 -m unittest discover -s scripts -p 'test_*.py'
----

Обычный запуск использует сохранённые эталоны и не требует Ruby.
`--verify-reference` заново запускает закреплённый gem и проверяет эталоны.
Установка: `gem install asciidoctor --version 2.0.23 --no-document`.
Ruby-процесс явно активирует эту версию; другая установленная версия не заменяет её.
Обычный профиль работает в secure mode без файловых включений (CLI с
`-S secure`). Сценарии `include-body-dom-v1` задают словарь `resources`: стенд
создаёт временное дерево с `main.adoc`, запускает Ruby в safe mode с этим
base_dir, а CLI — с тем же основным файлом, корнем ресурсов и `-S safe`. Нормализация HTML совпадает с `body-dom-v1`.
Необязательный словарь `attributes` передаёт атрибуты API обоим процессорам
(`--attribute` эталону, `-a` CLI).
Пути fixtures проверяются до записи; выход за дерево и подмена main.adoc запрещены.

`--update-reference` пересоздаёт эталоны, но не меняет ожидаемые результаты adoctra.
Проверки различают PASS, XFAIL (известное расхождение), FAIL (регрессия) и XPASS
(расхождение исправлено, baseline требует обновления). FAIL и XPASS завершаются
ненулевым кодом. Повреждённый fixture, ошибка процесса или отсутствующий эталон
считаются ошибкой стенда, а не ожидаемой несовместимостью.
Для XFAIL дополнительно проверяется сохранённый текущий результат adoctra:
изменившийся сбой считается FAIL. `--record-known-differences` явно перезаписывает
эти baseline-файлы; такие изменения требуют проверки diff и причины расхождения.
Исправленный случай переводится в `pass`, его baseline удаляется.

Fixtures начального корпуса — минимальные воспроизведения из аудита проекта,
не полный набор upstream-тестов. Первые реальные документы добавлены в отдельный
приёмочный корпус; его разнообразие ещё нужно расширять. Количество PASS/XFAIL
не является процентом совместимости языка.

Условный корпус также фиксирует два ранее существовавших расхождения: текущий
профиль не согласует HTML-разметку verse, а ссылка без текста на параграф с
подписью использует id вместо подписи. Оба случая имеют явные XFAIL и baseline.
Условия проверяют атрибуты текущего контекста, включая встроенный профиль
backend/doctype (см. «Встроенные атрибуты»), режим embedded/standalone и даты
от host и атрибуты safe mode (см. «Safe mode»); атрибуты окружения не моделируются.

`ifeval` проверен по закреплённому reader, включая числовые префиксы Ruby,
целые числа произвольной длины и несовместимые типы. Унаследованные особенности
2.0.23 (сохранение закрывающей кавычки и поиск первого оператора без учёта кавычек)
зафиксированы сценариями. Обычные и intrinsic-атрибуты подставляются однократно;
`{set:...}` и `{counter:...}` внутри условий исполняются (см. «Эффекты
выражений препроцессора» ниже).
Побочные эффекты предшествующих определений атрибутов доступны reader (см. ниже).

Ресурсный API раскрывает базовые `include::target[]` через явно переданный provider.
19 сценариев `include-body-dom-v1` проверяют вложенность, атрибуты, заголовок, списки,
параграфы и markup через границы файлов, контейнеры, условия, комментарии, verbatim,
raw-ресурсы, повторы, пустые файлы, экранирование, Unicode/BOM/CRLF и ссылки вперёд.
Rust-тесты отдельно проверяют диапазоны и provenance, диагностики, отказ доступа,
циклы, глубину/объём, незавершённый ввод, JSON/WASM и неизменность старых снимков.

Ещё 39 сценариев проверяют `lines` / `tag` / `tags`: диапазоны и объединения,
открытый конец, числовые префиксы/некорректные номера, приоритет параметров,
вложенные/повторные теги, исключения, `*` / `**`, порядок фильтров, границы маркеров,
header, списки, контейнеры, markup, подстановку атрибутов и выбор до preprocessing.
Предупреждения о тегах проверяются отдельно в Rust, включая физические позиции.
Диапазоны не разворачиваются в массивы номеров; огромный конечный предел безопасен.
Полные снимки ресурсов сохраняются, несмежные выбранные строки используют provenance.

Ещё 28 сценариев проверяют `opts=optional` / `options=optional`, существующие и
отсутствующие файлы, пустой target, абсолютный/относительный `leveloffset`, вложенность,
восстановление, doctitle, атрибуты, выбор строк/тегов, условия, контейнеры и verbatim.
Ошибки provider кроме `NotFound`, циклы и лимиты не подавляются `optional`.
Служебные строки `leveloffset` учитываются в грамматике, но не создают подсветку
несуществующего текста. Огромные смещения обрабатываются без переполнения: модель
ограничивает уровень до 255 с warning, HTML использует h6 для уровней 5 и выше.
Иерархия разделов и диагностика порядка уровней описаны ниже.

Ещё 38 сценариев проверяют `indent` / `depth`: общий отступ, положительные и
отрицательные значения, табуляцию с `tabsize`, Unicode/CRLF, выбор строк/тегов,
header, условия, комментарии, списки, вложенность и восстановление лимита.
Добавленные пробелы не создают токенов; раскрытая табуляция указывает на исходный
символ, остальной текст сохраняет точные byte offsets. Расширение текста учитывается
в лимите байтов до выделения памяти. `depth=0` разрешает сам файл, но запрещает его
вложенные include; дочерний depth может изменить унаследованный предел только в
границах жёсткого лимита host. Проверены диагностики и неизменность снимков.

9 сценариев проверяют `max-include-depth`, как `PreprocessorReader` Ruby:
значение читается из атрибутов API при создании reader (запись в header не
действует), числовой префикс как `to_i`, по умолчанию 64. Неположительное или
нечисловое значение отключает include: директива остаётся строкой без
диагностики. Относительный `depth`, выводящий за абсолютный предел, заменяется
им; ошибка называет относительный предел (`maximum include depth of N
exceeded`). Значение ограничено жёстким лимитом host `IncludeLimits.max_depth`
(64 по умолчанию, в том числе у CLI), поэтому предел выше 64 не расширяет
вложенность, в отличие от Ruby.

`encoding` пока отклоняется с диагностикой: provider возвращает готовый UTF-8
snapshot. Позиционные поля, неизвестные параметры и неизвестные options
игнорируются, как у встроенного Ruby reader. Имена параметров чувствительны к регистру.
Safe mode, URI-включения и строка `Unresolved directive` при ошибках добавлены
позднее (см. «Safe mode»); восстановления пути внутри jail нет. CLI сохраняет
ограничение корнем основного файла (кроме unsafe); stdin не получает provider. Строковый parser не выполняет
I/O. API составных позиций и лимиты описаны в link:parser-api.adoc[Parser API].

== Документ standalone

По умолчанию HTML backend, как `convert_document` Ruby, пишет полный документ:
`<html lang>` (`nolang`), `<head>` с `charset` (`encoding`), viewport,
generator adoctra, `application-name`, `description`, `keywords`, `author`
(`authors` с replacements, без тегов), `copyright`, `favicon` (тип по
расширению) и `<title>` (атрибут `title`, название документа, первый раздел
или `untitled-label`, без тегов и со сжатыми пробелами). `<body>` получает id
документа и классы doctype, `toc-class`/`toc-<позиция>` для автоматического TOC
и роль документа. Шапка (кроме `noheader`) содержит название (кроме `notitle`),
сведения об авторах (`Document::authors`, как `Document#authors`: имена с
replacements, email с macros), версии, дате и примечании ревизии, затем
автоматический TOC; у manpage — заголовок `… Manual Page`, TOC и раздел NAME.
Затем идут содержимое, сноски и подвал (кроме `nofooter`) с версией и датой
обновления по атрибутам после преобразования. `max-width` задаёт стиль
шапки, содержимого, сносок и подвала. `HtmlBackend::embedded()` и флаг CLI
`-s`/`--embedded` дают прежний embedded-вывод.

Стили — как ветка stylesheet Ruby: `stylesheet` пустой или `DEFAULT` — встроенная
тема adoctra (`adoctra.css`), со `linkcss` — ссылка под `stylesdir`; явный
`webfonts` даёт ссылку Google Fonts перед ней (пустое умолчание Ruby ничего не
подключает: тема adoctra использует системные шрифты); пользовательский stylesheet
со `linkcss` — ссылка (URI сохраняется), иначе читается через provider
(`HtmlBackend::with_resources`) из `stylesdir` и встраивается, а нечитаемый даёт
предупреждение Ruby и пустой `<style>`; без `stylesheet` стилей нет. Docinfo
(`docinfo`, `docinfo1`, `docinfo2`, `docinfodir`, `docinfosubs`) читается через
provider и выводится в конце `<head>`, в начале `<body>` и в конце `<body>` (после
MathJax, по атрибутам после преобразования). CLI, как Ruby CLI, передаёт даты,
читает stylesheet и docinfo рядом с входным файлом, создаёт каталог вывода и при
`linkcss` с `copycss` копирует тему или пользовательский stylesheet в `stylesdir`
рядом с выводом; `-a name[=value]` задаёт внешний атрибут.

Golden fixtures `golden/document/` сравнивают оболочку документа с
`asciidoctor-reference.rb --standalone` (с `reproducible`). Намеренные отличия:
семантические `<header>`/`<main>`/`<footer>`/`<nav>` вместо div Ruby, нет
устаревшего `X-UA-Compatible`, generator — adoctra, кавычки в `content`
экранируются (у Ruby атрибут получается некорректным). Даты, docinfo, stylesheet,
`linkcss`/`copycss` и `webfonts` сверены с Ruby в safe mode вручную и закреплены
Rust-тестами (эталон стенда работает в secure mode, где docinfo и чтение файлов
отключены). `allow-uri-read` (чтение stylesheet по URI) не поддерживается.

Режим embedded (`ParseOptions.embedded`, CLI `-s`) задаёт атрибут `embedded` и
скрывает название без `showtitle`, как Ruby; стенд запускает adoctra с
`-s -a showtitle`, как эталон с `--showtitle`. 3 PASS проверяют атрибуты режима и
связь `showtitle`/`notitle`. Вид шапки, подвала и боковой TOC (`toc: left/right`)
сверен со скриншотами Ruby в Chrome.

== Safe mode

`ParseOptions.safe` (`SafeMode::Unsafe`/`Safe`/`Server`/`Secure`, CLI
`-S`/`--safe-mode`, `--safe`) воспроизводит `Document#initialize` Ruby: атрибуты
`safe-mode-name`, `safe-mode-<имя>`, `safe-mode-level` (заблокированы),
`allow-uri-read` задаёт только host. Начиная с server: `copycss`,
`source-highlighter` сняты и заблокированы, `backend` заблокирован как `html5`,
`docdir` пуст, `docfile` относителен, `user-home` равен `.` (ниже server CLI
передаёт домашний каталог). Secure: `max-attribute-value-size` 4096 (значения
записей усекаются по границе символа, как `limit_bytesize`), принудительный
`linkcss`, снятый `icons`; `include::` становится `link:цель[role=include]`
(цель с пробелами — в `pass:c[…]`, также в verbatim-блоках и без provider),
docinfo не читается, CLI не копирует stylesheet. Значения host имеют приоритет,
где Ruby использует `||=`. Include по URI (или относительная цель внутри
URI-включения) без `allow-uri-read` становится той же ссылкой; с ним цель
передаётся provider. Пользовательский stylesheet по URI читается так же
(предупреждения Ruby при отсутствии `allow-uri-read` и при ошибке чтения). CLI
загружает URI через `ureq` (http/https), а в unsafe mode снимает ограничение
путей каталогом входного файла.

Умолчания отличаются от Ruby намеренно: `ParseOptions` по умолчанию `Safe`
(Ruby API — `Secure`), так как provider уже задаёт политику доступа; CLI по
умолчанию `safe` (Ruby CLI — `unsafe`), сохраняя ограничение путей. В safe mode
выход за каталог запрещается provider, тогда как Ruby восстанавливает путь
внутри jail с предупреждением; adoctra в этом случае, как для ненайденного
файла, выводит строку `Unresolved directive` Ruby. Data URI изображений читаются через
`load_binary` provider, как и встраиваемые SVG; `cache-uri` не реализован.
7 PASS проверяют атрибуты и блокировки secure mode, ссылки include, усечение
значений, а также бывший XFAIL `icons-secure-mode-lock`; уровни unsafe/safe/
server, include и stylesheet по URI сверены с Ruby вручную и закреплены
Rust-тестами (включая локальный HTTP-сервер в тестах CLI).

== Подсветка исходного кода

`source-highlighter` выбирается, как `save_attributes` Ruby: по атрибутам
заголовка (присваивание в теле не действует), только для basebackend `html` и
без `<имя>-unavailable`; вложенные документы (ячейки AsciiDoc) используют
подсветчик документа. Перенесены клиентские адаптеры Ruby: `highlight.js`/
`highlightjs` (`<pre class="highlightjs highlight">`, `code` с
`language-<язык|none> hljs`, тема `highlightjs-theme` в head, скрипты 9.18.3,
`highlightjs-languages` и инициализация в конце body), `prettify` (`prettyprint`,
`linenums[:start]`, `prettify-theme` — имя или URL, `run_prettify`) и
`html-pipeline` (`<pre lang>`; класс `listing` у adoctra заменяет обёртку
`listingblock`, как у обычного листинга). Каталоги `highlightjsdir`/`prettifydir`, тема и
языки читаются из итоговых атрибутов, схема CDN — из `asset-uri-scheme`
заголовка, как в `convert_document`. Подсветку выполняет браузер; adoctra не
разбирает исходный код. coderay и pygments ведут себя как Ruby в закреплённом
окружении эталона, где их gem нет: предупреждение Ruby (`optional gem … is not
available…`, один раз при первом листинге source) и `<pre class="CodeRay
highlight">`/`<pre class="pygments highlight">` без подсветки и docinfo.
rouge (в эталоне 4.7.0) намеренно не переносится: он раскрашивает код при
конвертации, что требует порта движка и 228 лексеров Rouge; adoctra выдаёт
обычный листинг `highlight` (известное расхождение, без XFAIL в корпусе).
Подсветка без отличий от Ruby доступна через `highlight.js` или `prettify`. Secure mode блокирует атрибут, поэтому 7 PASS стенда
работают в safe mode (профиль include без ресурсов), ещё один проверяет
блокировку secure. Golden-тест `golden/highlight/` сравнивает шапку, подвал и
разметку листингов standalone-документа с `asciidoctor-reference.rb
--standalone --safe`; вид highlight.js и prettify (с номерами строк) сверен со
скриншотами Ruby в Chrome.

== Встроенные атрибуты

Как `Document#initialize` Ruby, документ начинается с `attribute-undefined`
(`drop-line`), `attribute-missing` (`skip`) и `DEFAULT_ATTRIBUTES`, включая
метки `last-update-label`, `untitled-label`, `version-label`. Затем, после
атрибутов host, `update_backend_attributes` задаёт backend по умолчанию
`html5`: `backend`, `basebackend`, `filetype`, `htmlsyntax`, `outfilesuffix`
(если host его не задал), `pagewidth` для DocBook и флаги `backend-<b>`,
`basebackend-<bb>`, `filetype-<ft>`, `doctype-<d>` и их сочетания с doctype
(`doctype` по умолчанию `article`; backend `manpage` фиксирует doctype
`manpage`). В header `:doctype:` и `:backend:` обновляют эти флаги
(`update_doctype_attributes`/`update_backend_attributes`: алиасы `html`/
`docbook`, `xhtml…` с `htmlsyntax=xml`, повторная инициализация после
изменения `htmlsyntax`); в теле это обычные атрибуты. Как `@doctype` Ruby,
текущий doctype хранится отдельно: `:doctype!:` удаляет только атрибут, книга
остаётся книгой, а следующее присваивание убирает флаги прежнего значения.
Вложенный документ AsciiDoc-ячейки сбрасывает doctype на `article` (флаги
родителя удаляются, но остаются заблокированными). Для неизвестного backend
используются выведенные признаки `derive_backend_traits` (Ruby прерывает
обработку без конвертера).

18 PASS сравнивают флаги backend/doctype, присваивания в header и теле, пустое
значение, удаление и повторное присваивание doctype, manpage, блокировки,
`ifdef`, ячейки AsciiDoc, метки, `attribute-missing`, `htmlsyntax` и
`outfilesuffix`. Эталон работает в secure mode, где `backend` заблокирован,
поэтому смена backend в header проверена только Rust-тестами.

Как `Document#initialize` Ruby, `asciidoctor` (пустое значение) и
`asciidoctor-version` (закреплённая версия эталона,
`adoctra_core::COMPATIBILITY_VERSION`) — заблокированные overrides: значения
host и присваивания/удаления в документе их не меняют, условия и ячейки
AsciiDoc их видят (5 PASS `processor-attributes*`). Не реализованы
включение `toc`/`sectnums` для DocBook и XHTML-разметка HTML backend.

== Ленивые заголовки разделов

Как `initialize_section` и ветка discrete heading Ruby, заголовок раздела
преобразуется при чтении только для генерации id (`sectids`) или при явном id
с `{` в тексте. Остальные заголовки преобразуются при первом использовании во
время конвертации, с её состоянием атрибутов и счётчиков: в TOC (автоматический
— до тела с атрибутами header; TOC преамбулы — до её содержимого; `toc::[]` —
в своей позиции, с вложенностью до `toclevels`/`levels`), в `<title>`
standalone-документа без названия (первый раздел), в метке ссылки, иначе на
самом заголовке. Поэтому эффекты `{counter:}`/`{set:}` доходят до тела, а
сноски нумеруются в порядке конвертации.

16 сценариев сравнивают счётчики и `{set:}`, сноски с явным id, якорь в
заголовке, discrete, атрибут тела, TOC в header/преамбуле/макросе и
`toclevels`/`levels`, части книги, ячейку AsciiDoc и включение `sectids` по
ходу документа. Golden `toc/lazy_titles.adoc` сравнивает TOC и сноски.

Метки xref при преобразовании строятся внутри стадии макросов, как текст узла
`:xref` Ruby: textless-ссылка преобразует отложенный заголовок цели раньше
последующих сносок того же поля, а лексический текст метки виден этим сноскам
(экранированная сноска заголовка становится сноской абзаца). Прежние XFAIL
`lazy-title-xref-footnote` и `lazy-title-xref-block-title-footnote` переведены в
PASS; ещё 3 PASS (`lazy-title-xref-escaped-footnote`,
`lazy-title-xref-footnote-cell`, `lazy-title-xref-twice-footnote`) и golden
`footnotes/xref_titles.adoc`. Ссылка внутри сноски даёт несбалансированную
разметку Ruby (ленивое содержимое заканчивается на `]` маркера метки); стенд
такие эталоны не принимает, совпадение закреплено Rust-тестом. Ссылки,
зафиксированные определением атрибута, сохраняют метку, вычисленную при
определении, как в Ruby.

== Порядок регистрации id

Как в Ruby, раздел регистрирует id при чтении заголовка, а остальные блоки — в
конце `next_block`, после содержимого и его inline-якорей. 4 PASS
`register-*` сравнивают natural-ссылки на дочерние блоки примера и цитаты,
якорный заголовок контейнера со ссылкой на дочерний якорь и дубликат id;
место предупреждения о дубликате (на контейнере) закреплено Rust-тестом.

== Замена doctitle и вложенные документы

Замена doctitle целиком преобразует хранимое Ruby написание значения как
исходный текст названия: 9 PASS `doctitle-replacement-*` (с атрибутом API
`showtitle`) сравнивают разметку `pass:q`/`pass:m` всего значения,
раскрытые ссылки, счётчики, ссылки на сущности и частичный `pass:q`.
Вложенный документ ячейки AsciiDoc сохраняет название и preamble, как
`convert_embedded`: 8 PASS `nested-title-*` проверяют скрытие по умолчанию,
`:showtitle:`/`:notitle!:` в шапке ячейки, хостовый `showtitle`, preamble,
сноски и счётчики. 8 PASS `nested-toc-*` сравнивают TOC вложенного документа:
автоматический после названия, в preamble, макрос, уровни и TOC только родителя.
10 PASS `anchor-catalog-*` закрепляют каталог якорей в quote-метаданных,
pass-макросах и замене doctitle.

== Эффекты выражений препроцессора

`{set:…}`, `{counter:…}` и `{counter2:…}` в операндах `ifeval`, цели и списке
параметров include исполняются, как `Document#sub_attributes` Ruby из
`resolve_expr_val`/`preprocess_include_directive`: эффекты меняют атрибуты
чтения (последующие условия и include их видят), преобразование начинается со
снимка заголовка, а до его завершения эффект попадает в снимок. Значения
атрибутов подставляются в хранимом Ruby написании (`a&lt;b`), имена — по
Unicode Word-грамматике. Подстановки выполняются ровно в ветках Ruby, поэтому
счётчик в отсутствующей цели с `drop-line` или `warn` увеличивается дважды, а
список параметров не вычисляется в secure mode и при превышении глубины. В
пропущенной ветке и при повторном сканировании подсветки выражения не
исполняются.

11 PASS (`ifeval-counter-*`, `ifeval-set-effects-order`,
`ifeval-stored-spelling`, `ifeval-header-effects`, `include-target-counter*`,
`include-parameter-counter`, `include-blank-target-set`,
`include-missing-target-effects`, `include-secure-parameters`) сравнивают
результат с Ruby; порядок вычисления, блокировки и подсветка закреплены
Rust-тестами. Расхождение: информационные сообщения drop-line подстановок
директивы (скрытые уровнем журнала Ruby по умолчанию) не выводятся.


== Адаптированные upstream-тесты и мягкие host-атрибуты

Отдельный link:upstream-tests.adoc[корпус upstream-тестов] содержит 43 сценария
из 30 тестов Asciidoctor 2.0.23: атрибуты (20), substitutions (13), include (10).
Все дают PASS в `body-dom-diagnostics-v1`; SHA-256, лицензия, исходные Ruby-файлы,
точные имена/строки тестов и описания адаптаций сохранены. Это отдельная выборка,
не полный upstream suite. Оба режима — offline и проверка эталонов Ruby — есть в CI.

Перенос обнаружил отсутствие мягких host/CLI overrides. Теперь `name=value@`
и `name@=value` допускают изменение/удаление документом; `!name`/`name!`
запрещают установку, а формы `!name@`, `name!@`, `!name=@`, `name!=@` снимают
умолчание без блокировки. Изменение применяется в общем ParseContext, поэтому
снимки, inline-разрешение и все consumers получают одинаковые значения.
CLI учитывает порядок повторных `-a` с разными формами одного имени.
Ruby nil/boolean остаются вне строкового API; конфликтующие формы одного имени
в BTreeMap API не моделируют insertion order Ruby Hash.

Rust отдельно проверяет сохранение semantic parts, header/body snapshots,
физических диапазонов ссылок, блокировок процессора/safe mode и нормализацию
имени лимита include. Исходные upstream include-fixture проверяют source_id,
номера строк и составной provenance; это не сравнение source positions с Ruby
в HTML-профиле. Приёмочное окружение документации Asciidoctor/Spring пока
сохраняет ранее закреплённые явные host-значения.


== Независимая inline-семантика и атрибуты

link:semantic-profile.adoc[`inline-semantics-v1`] сравнивает ограниченное
inline-дерево и явно выбранные снимки атрибутов header/final. Ruby использует
собственный converter с семантическими границами, adoctra — JSON AST с
опциональным экспортом атрибутов. HTML не генерируется и не разбирается.
129 сценариев (24 из upstream-выборки, 105 собственных проб) и двенадцать полных
страниц Asciidoctor / Spring Framework дают PASS;
эталоны, происхождение, offline/verify, схема и проверки XFAIL/XPASS сохранены.

Проверяются форматирование, текст, основные ссылки/anchor и явные/неявные
подписи xref, переносы, UI-макросы, метаданные ссылок и inline/блочные изображения.
Indexterm сохраняет видимость, иерархию и see/see-also; inline- и блочные формулы —
нотацию asciimath/latexmath и точные пробелы. Типографские кавычки также включены.
Дерево блоков включает списки с checkboxes/description/присоединённым содержимым,
простые и составные контейнеры, listing/literal с точными пробелами и языком.
Таблицы сравниваются со столбцами, head/body/foot, объединениями/выравниванием,
стилем и фоном ячеек, параграфами, literal-текстом и вложенными документами.
Semantic parts атрибутов
сохраняются; отсутствие и пустое значение различаются. Флаг CLI
`--to json --json-attributes` включает `attribute_snapshots`; без флага эти снимки
не экспортируются. Полный список ограничений дан в описании профиля:
raw HTML, дополнительные метаданные xref и позиции диагностик
пока не входят в проверку. Исходники реальных страниц и прежние 105 эталонов
сохранены без изменений; все 141 сценарий проходят, XFAIL нет.
Неподдерживаемые узлы и warning/error вызывают ошибку, а не исчезают из сравнения.

Табличная выборка выявила потерю перевода строки в CSV literal-ячейке.
Ядро теперь сохраняет значимые переводы строк CSV/DSV literal вместе с обычными
substitutions; это проверено в AST с физическими Unicode/LF/CRLF-диапазонами,
HTML golden, JSON/WASM и отдельном минимальном сценарии.

Пробы xref в значениях атрибутов выявили потерю вычисленной подписи в снимках
header/final при правильном отображении использования в тексте. Снимки теперь
получают уже вычисленные при определении target/label: ссылка вперёд сохраняет
fallback, ссылка после цели — форматированный заголовок. Подстановки и счётчики
повторно не исполняются; физические диапазоны использования не меняются.

Сноски сравниваются как маркеры и отдельные каталоги определений, включая
вложенные документы, неиспользованные/удалённые атрибуты, повторные ссылки и
сброс счётчика. Callouts сохраняют положение в тексте, номер/id, guard/XML,
режим иконок/src и привязки coids к спискам. JSON/WASM экспортируют `text_range`
в UTF-8 байтах нормализованного текста блока, отдельно от физического span.
33 новые пробы и три полные страницы проходят независимый Ruby converter.

Сравнение выявило потерю сносок без видимого использования атрибута. Каталог
ядра теперь сохраняет определения при регистрации, завершает passthrough и
ссылки внутри содержимого. Сноска ленивого внешнего заголовка не дублируется
в каталоге ячейки, из которой пришёл xref. Добавлены четыре минимальных
регрессионных сценария, HTML golden, AST/Unicode/CRLF и JSON/WASM проверки.

== Позиции диагностик

Отдельный link:diagnostic-positions.adoc[`diagnostic-positions-v1`] сравнивает
упорядоченные severity/message и первичную позицию `{file, line}` либо `null`.
Ruby отдаёт настоящий `source_location` MemoryLogger, adoctra — координаты CLI;
колонки и байтовые диапазоны не домысливаются. Нормализуются только stdin и
временный корень include-fixture. HTML конвертируется для получения отложенных
предупреждений, но не участвует в сравнении этого профиля.

18 собственных проб дают 18 PASS, без XFAIL: обычные документы, Unicode/CRLF,
порядок сообщений, вложенные include, отбор строк/тегов и снятие отступа.
Восемь прежних расхождений исправлены без изменения эталонов Ruby.
CLI по умолчанию выводит совместимые диагностики, используя `Diagnostic.report`:
уровень/текст listing и endif, отсутствие cursor для пропущенного атрибута,
позицию директивы для незакрытого тега, cursor после lookahead через EOF include
и нумерацию выбранных строк. Редакторские xref/условия не попадают в обычный журнал.
Физические spans и исходные severity/message сохраняются в API/WASM;
`--diagnostics editor` выводит их с колонками и byte spans. Приёмка HTML/диагностик
также теперь даёт 28 PASS, без XFAIL. Стенд не маскирует отличия по типу сообщения.

Дрейф и XPASS запрещены; offline/verify и проверки exporter включены в CI.
Native-тесты отдельно проверяют физические byte spans и Unicode-колонки после
преобразования include. Полный набор диагностик, вторичный include_location,
стек включений и сравнительная проверка составного provenance пока вне профиля.


== Производительность

link:performance.adoc[Стенд производительности] измеряет native parse/tokens/JSON
и parse+JSON на 12 закреплённых страницах и 12 синтетических входах, а также
размер release WASM до упаковки wasm-bindgen. Сохранены исходные выборки,
контрольные суммы, происхождение и параметры машины/сборки. Это базовая линия
этапов 7–8, без порогов времени в CI и без новых утверждений о совместимости.
Отдельное исследование временных буферов substitutions добавляет повторные
native-прогоны, режим профилирования одной операции и счётчики аллокаций glibc
для стресс-входов со ссылками/сносками и AsciiDoc-ячейками. Из вычисления source
spans убраны временные текстовые буферы; неизменённые semantic boundaries
сохраняют свой вектор фрагментов. Схемы AST/JSON/WASM и правила подстановок
не меняются; все сравнительные корпуса проходят с прежними эталонами.
Предупреждение таймера gprofng явно ограничивает интерпретацию CPU-профиля;
снижение объёма аллокаций не объявляется снижением RSS или пикового heap.
Browser runtime, глубокая вложенность, RSS и инкрементальный API пока
не измеряются. Методика и результаты приведены в документации производительности.
