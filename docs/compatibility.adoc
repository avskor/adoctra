= Совместимость с Asciidoctor

Эталон — Asciidoctor *2.0.23*. Машиночитаемая версия находится в
link:../compatibility/asciidoctor-version[compatibility/asciidoctor-version].
Обновление версии — отдельное изменение с проверкой различий корпуса.

== Контракт

* Язык: одинаковая интерпретация содержимого, атрибутов, блоков и ссылок при
  одинаковых настройках. Сейчас реализовано ограниченное подмножество.
* HTML: существующий backend использует собственную разметку. Точное соответствие
  HTML эталону будет отдельным режимом; текущие нормализованные сравнения его не доказывают.
* Редактор: AST, диагностики и позиции должны согласовываться с подсветкой;
  незавершённый документ должен давать частичный результат.
* Ruby API и исполнение Ruby-расширений находятся за пределами этого контракта.

== Проверки

Начальный сравнительный профиль `body-dom-v1` сравнивает всё тело документа.
Он удаляет только известные структурные обёртки HTML, переносит их id/roles на
содержимое, согласует представление списков и verbatim-блоков, декодирует HTML
entities и нормализует пробелы обычного текста. В listing/literal/pre пробелы,
табуляция и переводы строк сохраняются. Неизвестные теги и атрибуты сохраняются.
Этот профиль проверяет наблюдаемое содержимое HTML, а не полный ASG, диагностики,
атрибуты документа или точное совпадение HTML. Для них нужны отдельные профили.
При генерации этого профиля задан `showtitle`, чтобы заголовок документа входил
в сравнение. Корпус содержит 975 сценариев: 965 PASS и 10 XFAIL.

[source,sh]
----
cargo build -p adoctra-cli
python3 scripts/compatibility.py
python3 scripts/compatibility.py --verify-reference
python3 -m unittest discover -s scripts -p 'test_*.py'
----

Обычный запуск использует сохранённые эталоны и не требует Ruby.
`--verify-reference` заново запускает закреплённый gem и проверяет эталоны.
Установка: `gem install asciidoctor --version 2.0.23 --no-document`.
Ruby-процесс явно активирует эту версию; другая установленная версия не заменяет её.
Обычный профиль работает в secure mode без файловых включений. Сценарии
`include-body-dom-v1` задают словарь `resources`: стенд создаёт временное дерево
с `main.adoc`, запускает Ruby в safe mode с этим base_dir, а CLI — с тем же
основным файлом и корнем ресурсов. Нормализация HTML совпадает с `body-dom-v1`.
Пути fixtures проверяются до записи; выход за дерево и подмена main.adoc запрещены.

`--update-reference` пересоздаёт эталоны, но не меняет ожидаемые результаты adoctra.
Проверки различают PASS, XFAIL (известное расхождение), FAIL (регрессия) и XPASS
(расхождение исправлено, baseline требует обновления). FAIL и XPASS завершаются
ненулевым кодом. Повреждённый fixture, ошибка процесса или отсутствующий эталон
считаются ошибкой стенда, а не ожидаемой несовместимостью.
Для XFAIL дополнительно проверяется сохранённый текущий результат adoctra:
изменившийся сбой считается FAIL. `--record-known-differences` явно перезаписывает
эти baseline-файлы; такие изменения требуют проверки diff и причины расхождения.
Исправленный случай переводится в `pass`, его baseline удаляется.

Fixtures начального корпуса — минимальные воспроизведения из аудита проекта,
не полный набор upstream-тестов. Реальные документы для приёмки ещё предстоит
добавить. Количество PASS/XFAIL не является процентом совместимости языка.

Условный корпус также фиксирует два ранее существовавших расхождения: текущий
профиль не согласует HTML-разметку verse, а ссылка без текста на параграф с
подписью использует id вместо подписи. Оба случая имеют явные XFAIL и baseline.
Условия проверяют только атрибуты, предоставленные текущим контекстом; полный
набор встроенных атрибутов Asciidoctor, включая backend/env, ещё не реализован.

`ifeval` проверен по закреплённому reader, включая числовые префиксы Ruby,
целые числа произвольной длины и несовместимые типы. Унаследованные особенности
2.0.23 (сохранение закрывающей кавычки и поиск первого оператора без учёта кавычек)
зафиксированы сценариями. Обычные и intrinsic-атрибуты подставляются однократно;
`{set:...}` и `{counter:...}` с побочными эффектами пока не поддержаны.

Ресурсный API раскрывает базовые `include::target[]` через явно переданный provider.
19 сценариев `include-body-dom-v1` проверяют вложенность, атрибуты, заголовок, списки,
параграфы и markup через границы файлов, контейнеры, условия, комментарии, verbatim,
raw-ресурсы, повторы, пустые файлы, экранирование, Unicode/BOM/CRLF и ссылки вперёд.
Rust-тесты отдельно проверяют диапазоны и provenance, диагностики, отказ доступа,
циклы, глубину/объём, незавершённый ввод, JSON/WASM и неизменность старых снимков.

Ещё 39 сценариев проверяют `lines` / `tag` / `tags`: диапазоны и объединения,
открытый конец, числовые префиксы/некорректные номера, приоритет параметров,
вложенные/повторные теги, исключения, `*` / `**`, порядок фильтров, границы маркеров,
header, списки, контейнеры, markup, подстановку атрибутов и выбор до preprocessing.
Предупреждения о тегах проверяются отдельно в Rust, включая физические позиции.
Диапазоны не разворачиваются в массивы номеров; огромный конечный предел безопасен.
Полные снимки ресурсов сохраняются, несмежные выбранные строки используют provenance.

Ещё 28 сценариев проверяют `opts=optional` / `options=optional`, существующие и
отсутствующие файлы, пустой target, абсолютный/относительный `leveloffset`, вложенность,
восстановление, doctitle, атрибуты, выбор строк/тегов, условия, контейнеры и verbatim.
Ошибки provider кроме `NotFound`, циклы и лимиты не подавляются `optional`.
Служебные строки `leveloffset` учитываются в грамматике, но не создают подсветку
несуществующего текста. Огромные смещения обрабатываются без переполнения: модель
ограничивает уровень до 255 с warning, HTML использует h6 для уровней 5 и выше.
Иерархия разделов и полная совместимость диагностики уровней ещё впереди.

Ещё 38 сценариев проверяют `indent` / `depth`: общий отступ, положительные и
отрицательные значения, табуляцию с `tabsize`, Unicode/CRLF, выбор строк/тегов,
header, условия, комментарии, списки, вложенность и восстановление лимита.
Добавленные пробелы не создают токенов; раскрытая табуляция указывает на исходный
символ, остальной текст сохраняет точные byte offsets. Расширение текста учитывается
в лимите байтов до выделения памяти. `depth=0` разрешает сам файл, но запрещает его
вложенные include; дочерний depth может изменить унаследованный предел только в
границах жёсткого лимита host. Проверены диагностики и неизменность снимков.

`encoding` пока отклоняется с диагностикой: provider возвращает готовый UTF-8
snapshot. Позиционные поля, неизвестные параметры и неизвестные options
игнорируются, как у встроенного Ruby reader. Имена параметров чувствительны к регистру.
Не реализованы полный набор safe mode, URI-включения, маскирование путей
и Ruby fallback при ошибках. CLI сохраняет ограничение
корнем основного файла; stdin не получает provider. Строковый parser не выполняет
I/O. API составных позиций и лимиты описаны в link:parser-api.adoc[Parser API].

Ещё 25 PASS проверяют нормализацию reader без indent: конечные ASCII-пробелы
и NUL удаляются из основного документа и AsciiDoc-включений, в том числе в
verbatim. Raw-включения сохраняют пробелы; Unicode-пробелы и внутренние tab
остаются на стадии reader. Конечные пустые строки удаляются только у основного
документа. Проверены header, атрибуты, комментарии, условия, контейнеры,
lines/tag(s), вложенность, leveloffset, BOM/CRLF и незакрытые блоки.
Отдельный XFAIL фиксирует прежнее отсутствие verbatim-подстановки tabsize вне
include[indent=…]; это работа стадии substitutions, а не нормализации reader.

Ещё 34 PASS проверяют многострочные атрибуты: ` \` и legacy ` +`, смешанные
маркеры, отступы и Unicode-пробелы, пустые строки/EOF, header/body, unset,
подстановки прежних значений, условия, контейнеры, списки и verbatim.
Включения проверяют сбор значения через границы файлов, lines selection,
raw-суффиксы и использование собранного значения в следующем include target.
Rust-тесты отдельно проверяют locked overrides, исходные позиции после indent,
Unicode/BOM/CRLF, неизменность snapshots и устойчивость длинных цепочек.

Два новых XFAIL документируют прежние ограничения, проявившиеся в этих сценариях:
` +` с переводом строки внутри подставленного значения не превращается в HTML
hard break, а присваивание в пустом контейнере влияет на следующие параграфы
иначе, чем Ruby attribute replay. Первое относится к порядку substitutions,
второе воспроизводится и с однострочным атрибутом. Оба имеют точные baseline.

Ещё 18 PASS проверяют `docfile`, `docdir`, `docname` и `docfilesuffix` основного
файла: header/body, блокировку присваиваний и unset, условия, многострочные значения,
вложенные include с абсолютными целями, tag-параметры, indent, leveloffset,
списки, контейнеры, verbatim и Unicode/CRLF. Полные пути проверяются условиями
и загрузкой ресурсов, поэтому эталоны не зависят от временного каталога стенда.
Rust-тесты покрывают суффиксы и dotfiles, непрозрачные идентификаторы provider,
виртуальные пути, неизменность снимков, AST/позиции/токены и HTML/JSON/WASM.
Атрибуты файлового ввода соответствуют safe-профилю; строковый API не берёт cwd,
а полная семантика safe mode и маскирование путей остаются отдельной работой.

Ещё 47 PASS проверяют грамматику и подстановки списка параметров include:
позиционные/пустые поля, пробелы и tab, кавычки и их экранирование, незакрытые
кавычки, соседние поля без запятой после кавычки, повторные параметры, `None`,
объединение options и особые правила пробелов. Ссылки на обычные и intrinsic
атрибуты раскрываются однократно перед разбором всего списка; результат может
добавлять поля и разделители. Поддержаны оба способа экранирования ссылок и
политики `attribute-missing`: skip, drop, drop-line, warn. Одинарные кавычки
не запускают дополнительных inline-подстановок: include вызывает parse_attributes
без sub_result, в отличие от блочных списков атрибутов.
Проверены header, списки, контейнеры, verbatim, вложенность, leveloffset,
Unicode/BOM/CRLF, selection/indent, физические позиции предупреждений и токенов,
provenance, HTML/JSON/WASM и неизменность снимков. Известные XFAIL не изменились.

Ещё 36 PASS проверяют однократные подстановки в include target: регистр имён,
обычные/intrinsic-атрибуты и их переопределение, оба способа экранирования,
неверные имена, отсутствие повторного сканирования значений и изменения контекста.
Проверены политики skip/drop/drop-line/warn, optional, пустой путь, порядок
обработки target перед параметрами, header, списки, контейнеры, verbatim,
вложенность, leveloffset, selection/indent и Unicode/BOM/CRLF. Rust-тесты отдельно
проверяют отсутствие вызовов provider при удалённом/пустом пути, warning и его
физические позиции, исходные snapshots, HTML/JSON/WASM и неполный ввод.
В target `warn` использует drop-line и предупреждает вместо загрузки, optional
подавляет это предупреждение. `drop-line` пропускает директиву с отсутствующим
атрибутом до разбора параметров. Пустое определённое значение без optional даёт
warning. Текст частичного результата при warning сохраняет исходную директиву;
Ruby fallback с `Unresolved directive in ...` остаётся за пределами текущего
профиля, как и fallback при ошибках загрузки. Побочные эффекты set/counter
по-прежнему отложены до общей стадии substitutions. Прежние XFAIL не изменились.

Ещё 38 PASS проверяют setext-названия документа: однородное подчёркивание,
Unicode-длины с допуском одного символа, буквенно-цифровой текст (десятичные
цифры допускаются, отдельные дроби/надстрочные числа — нет), приоритет ATX,
пустые строки/комментарии, авторов/ревизию, атрибуты и compat-mode. Поддержаны
`=`, а также `-`, `~`, `^`, `+`, если эффективный leveloffset даёт уровень 0.
Проверены условия, include между строками, selection/indent, BOM/CRLF, EOF,
verbatim и сохранение физических диапазонов/снимков. Rust-проверки покрывают
locked overrides, HTML/JSON/WASM, подсветку обеих строк и частичный ввод.
Setext-разделы в теле и влияние compat-mode на общие substitutions ещё впереди;
само наличие атрибута не означает полной реализации legacy-синтаксиса.

Ещё 46 PASS проверяют `doctitle`: явное/неявное название, overrides до и после
декларации, пустые значения/unset с восстановлением, ранние снимки атрибутов,
изменения в теле, ATX/setext/leveloffset, авторов/ревизию, markup, условия,
многострочные значения, включения/selection/indent и Unicode/BOM/CRLF.
Сохранён порядок двухстрочного lookahead эталона: директива сразу после ATX
обрабатывается до установки неявного doctitle. Rust отдельно проверяет hard
и пустые host overrides, исходные декларации и диапазоны замен, provenance,
неизменность snapshots, диагностики/подсветку, JSON/WASM и незавершённый ввод.
`header.title` хранит объявленный текст, первый Heading — действующее название.
Полный набор header substitutions и семантика отдельного атрибута `title`
(выбор названия для метаданных документа) остаются вне этого изменения.

Ещё 36 PASS проверяют индексированные `author_N`: непрерывную нумерацию,
приоритет author/authors, пустые значения/unset, сравнение с исходными именами,
составные компоненты через underscore, старые поля и email, ранние подстановки,
условия, setext, Unicode/CRLF, include/selection/indent и границу header/body.
Обработка индексов требует заголовка документа и останавливается на первом
отсутствующем ключе. Если переопределение запускает пересчёт, производные поля
объединяются с текущими значениями, включая замену locked host-полей; отсутствующие
в результате поля не удаляются. Rust отдельно проверяет блокировку последующих
присваиваний, исходные объявления/позиции, snapshots, частичный ввод и HTML/JSON/WASM.
На этом этапе markup в явных именах и общий набор header substitutions оставались ограничениями.

Следующие 40 PASS закрывают raw-разметку в явных именах: whole-value `pass:[…]`,
стадии `a`/`attributes`, `c`/`specialcharacters`/`specialchars`, `none`, порядок
и удаление повторных стадий, подстановки значений с разной защитой, литеральные
теги и entity, несколько авторов, author_N, составные имена, Unicode-пробелы,
header/body, include/selection/indent. Raw-теги исключаются при вычислении частей
имени; сам author сохраняет разметку и пробелы. Обычные `<…>` в исходном значении
остаются текстом. Rust проверяет также host values, source spans, snapshots,
частичный ввод и экспорт границ фрагментов в JSON/WASM.
Для имени, состоящего только из пустых raw-тегов, Ruby может завершиться ошибкой;
adoctra возвращает пустые компоненты имени, сохраняя author и частичный AST.

Добавленный на этом этапе XFAIL `header-markup-literal-entity` фиксировал отсутствие entity restoration
после подстановки атрибута: поля имени вычислены, но HTML для буквального `&amp;`
